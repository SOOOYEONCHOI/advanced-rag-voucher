## 2. 알려진 제약

### 2-1. 기능 제약 (의도된 것)

| 제약 | 내용 | 근거 |
|---|---|---|
| **추론은 매핑·배포된 모델만** | 추론은 Wezard 로 연결됐다(2026-10-12). 매핑이 없으면 사유 없이 `RECEIVED`, 매핑한 모델이 Wezard 에 배포돼 있지 않으면 `RECEIVED`(사유 `WEZARD_MODEL_NOT_DEPLOYED`), Wezard 설정이 없으면 Stub(`GPU_INFERENCE_NOT_CONFIGURED`)이다. **이미지는 어느 경우든 저장된다** | DECISIONS O-12, DEC-030 |
| **health `components.gpu` 없음** | health 에 `components.gpu` 가 없다. 넣으려면 값의 뜻과 503 판단 포함 여부를 클라이언트와 합의해 계약을 먼저 고친다 | DECISIONS DEC-C15 |
| **분류 비전검사항목은 요청한 클라이언트에만 보인다** | 카탈로그·버전에 `include=classification` 을 준 클라이언트에만 `CLASSIFICATION` 이 나온다. 0.1.7 은 요청해 분류 결과를 표시하고, 0.1.6 이하에는 보이지 않는다 | DECISIONS O-14·DEC-031 |
| **이미지 보존 정책 없음** | 이미지를 자동으로 지우는 기능이 없다. 저장소는 계속 늘어난다 | DECISIONS O-10 |
| **공정·제품은 합성값** | 테이블이 없고 카탈로그 응답 시점에 `id=1, code="ALL"` 로 만든다. `process_id`·`product_id` 는 검증하지 않는다 | DECISIONS O-8·O-11 |
| **모델은 Wezard 배포 목록에서만 고른다** | AI 모델 등록 메뉴는 없다. 비전검사항목 관리의 AI 모델 매핑이 그 유형의 Wezard 배포 모델을 받아 보인다. Wezard 설정이 없거나 응답이 없으면 빈 목록과 안내다 | DECISIONS DEC-030 |
| **화면은 한국어만 노출** | 다국어 리소스(4개 언어)는 남아 있지만 사용자 화면에서 언어를 바꾸는 수단은 없다 | DESIGN §6 |

### 2-2. 운영 제약 (개발 서버 · 운영 서버)

근거: DECISIONS DEC-C11.

| 제약 | 내용 |
|---|---|
| **평문 HTTP** | `HTTPS_ENABLED` 기본값이 `False` 다. 개발 서버(:8123)와 운영(ALB HTTP 리스너, 인증서 전, 3-1) 모두 TLS 없이 돈다 — 인증 헤더와 촬영 원본이 평문으로 오간다. 사내 베타 범위로만 쓴다 |
| **개발 서버 DEBUG 켜짐** | `DEBUG` 기본값은 `False` 이고 운영도 `False` 다. 개발 서버(:8123)만 `.env` 로 켜 둔다. `/api/v1` 아래는 404 봉투로 답하므로 DEBUG 페이지가 나가지 않는다 |
| **`/api/v1` rate limit 없음** | 인증 실패 횟수 제한·Client 잠금이 없다. `429` 를 내지 않는다. 웹 로그인 잠금(§1)과는 별개다. 도입 여부는 3-1 표의 4 다 |
| **추론 동기 처리** | `POST /api/v1/inspections` 가 추론을 마친 뒤 응답한다(Wezard 조회 5초 + 추론 15초 상한, 개발 장비 실측 0.2초). 그동안 gunicorn 워커 하나를 점유한다 |

### 2-3. 검증 공백

| 공백 | 내용 |
|---|---|
| **raw SQL 경로가 단위 테스트로 검증되지 않는다** | 단위 테스트(SQLite)가 닿지 않는 PostgreSQL 전용 SQL·RLS 는 `tests/pg` 가 본다. 그 `tests/pg` 가 `maip_test` 를 기다리는 동안(3-2) e2e(실제 DB)가 화면을 통해서만 본다 |
| **nginx 파일 전송(`FILE_ACCEL_REDIRECT`)** | 이 개발 머신에 nginx 가 없어 응답 헤더만 단위 테스트로 본다. 운영 서버에서 화면 이미지 표시는 확인했고(첫 배포 파이프라인 점검), Range·이어받기·`max_ranges 1` 은 아직 `curl` 로 보지 않았다(DEPLOYMENT §9) |
| **워커 다중 실행 잠금** | `select_for_update(skip_locked=...)` 는 PostgreSQL 에서만 걸린다. SQLite 테스트에서는 잠금 없이 돈다 — 워커 2개 동시 실행은 단위 테스트로 검증되지 않는다 |

| 1 | TLS 인증서 방식(공인 / 사내 CA / 자체 서명) — 인증서는 NCP ALB 에 둔다(사용자 결정 2026-10-23, DEPLOYMENT §5) | 인프라 | 사내 CA·자체 서명이면 CA PEM 을 클라이언트에 전달하고 클라이언트 코드를 고쳐야 한다. IP 접속이면 SAN 에 `IP:<서버 IP>` 를 넣는다 |
| 2 | 운영 최종 주소와 전환 일정 | 인프라 + 클라이언트 | `licenses/sources` 주소가 0.1.4·0.1.5 의 LGPL 고지문에 박혀 있다. 바뀌면 클라이언트 재빌드다. 평문 포트를 닫아도 이 경로는 리다이렉트를 남긴다 |
| 3 | LGPL 소스를 사외에 공개할지 · 3년 보존을 운영 정책 문서에 올릴 주체 | 법무 + 운영 | 공개하면 1·2 와 같은 일정으로 묶는다 |
| 4 | `/api/v1` 인증 실패 rate limit·잠금 도입 | 인프라 | 도입하면 오류 코드·`retryable` 을 계약 문서에 먼저 적는다 |

결정이 나면 계약 문서 client/SERVER_API_CONTRACT.md 를 먼저 고치고 클라이언트에 알린다.

운영 서버를 세울 때 계약에 함께 적을 것: nginx `client_max_body_size 40m` 을 넘는 요청은 앱의 413 봉투가 아니라 nginx 413 HTML 을 받는다("봉투 없는 응답"). Wezard 의 `HEAD` 요청은 405 다(`maip-api.md` 에 적었다).

세우는 절차는 DEPLOYMENT 에 있다.

### 3-2. PostgreSQL 통합 테스트 설정

| 항목 | 내용 |
|---|---|
| 무엇 | PostgreSQL 로 도는 별도 테스트 설정 — 있다(`configurations/pg_test_settings.py`·`tests/pg`) |

실행법과 이 계정이 `maip_test` 를 직접 만들지 못하는 이유는 DEVELOPMENT §2.1-1 에 있다.
