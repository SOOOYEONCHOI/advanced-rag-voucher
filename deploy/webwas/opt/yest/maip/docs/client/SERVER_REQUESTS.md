## R19. 남은 요청 — 검사항목 묶음 필드와 Overlay 화면비

R19(2026-10-13, 계약 4차 반영 보고)의 "서버에 바라는 것" 중 열린 두 항목이다. 번호는 원래 번호를 따른다.

### 4-1. 검사항목 묶음 필드 — 서버 보류

한 부품의 유형별 검사항목(`FAN-PANEL`·`-CLS`·`-DET`)을 묶는 값이 카탈로그에 있으면, Client가 이름을 파싱하지
않고 "한 촬영 → 여러 판정" 화면을 만들 수 있다. 예: `inspection_items[].part`(`{"id": ..., "name": "냉각팬 패널 단면"}`).
서버는 묶는 체계를 먼저 정한 뒤 계약으로 알리기로 했다(계약 §15 열린 요청). Client는 그때까지 계약 §6-7을 따른다.

### 4-4. Overlay 화면비 — 해상도 회신함(R22 §4)

서버 회신: 가이드는 데모 표본 사진(1448×1086, 4:3) 기준이고, 현장 카메라 해상도를 알려 주면 그 화면비로 다시
만든다(계약 §9). Client는 R22 §4로 현장 카메라 해상도(2448×2048)를 알렸다. 서버가 그 화면비로 가이드를 다시 만들면 이 항목을 닫는다.

## R22. 계약 6차 회신 — 치수 측정, 현장 카메라 (2026-10-20)

계약 6차(2026-10-20, 서버 1.1.0)를 받았다. 지금 배포된 Client(0.1.7)는 `include=measurement` 를 보내지 않으므로
영향이 없다(응답의 `measurements: null` 도 읽지 않는다). 2026-10-19 metadata 검증 강화에도 걸리는 요청이 없다 —
Client 는 `camera` 를 객체로만 보내고 `inspection_item_id` 는 정수다.

### 1. §0 요청 1~4 — 반영 계획

다음 Client 빌드에 넣는다. 날짜는 아직 정하지 않았고, 정하면 이 문서로 알린다.

| 요청 | Client |
|---|---|
| 1 | 카탈로그·버전에 `include=classification,measurement` |
| 2 | 아래 2·3절 |
| 3 | `measurements` 는 측정점 전부를 한 번씩, 값은 mm 소수 둘째 자리. `calibration` 은 **항상** 보낸다 — `{"method": "REFERENCE", "mm_per_px": <배율>, "reference": <기준물 코드>}` |
| 4 | 결과 패널에 측정점별 값·범위·합격/불합격. 판정 타일은 `abnormal` 하나 |

### 2. 질문 1 — 측정 방법은 어디서 정하나

Client 의 **측정 창**에서 작업자가 정한다. 치수 측정 검사항목으로 촬영하거나 파일을 보내면 측정 창이 열리고,
작업자가 측정점마다 `description` 을 보고 시작점·끝점 두 점을 찍는다(돋보기로 원본 화소를 보며 찍고, 찍은 점은
끌어서 고친다). 측정점 위치를 Client 에 미리 설정해 두지는 않는다 — 도면이 오면 `description`(어디서 어디까지)을
채워 주면 된다. 에지를 찾아 자동으로 재는 방식은 현장 카메라·거치대·도면이 정해진 뒤 따로 정한다.

### 3. 질문 2 — 기준물

- **사진마다** 작업자가 기준물의 양 끝을 찍어 배율(mm/화소)을 구한다. 기준물 길이(mm)와 코드는 Client 설정에 둔다(PC 마다 한 개).
- 기준물은 길이를 아는 곧은 물체(눈금자·게이지 블록)를 **측정면과 같은 높이**에 둔다. 높이가 다르면 원근 때문에
  배율이 달라진다. 크기·모양·놓는 위치는 거치대를 설치할 때 현장에서 정한다.
- Client 는 `calibration` 을 항상 보내므로 **필수로 올려도 된다.**

### 4. 질문 3·요청 5 — 현장 카메라와 사진 해상도 (R19 §4-4 회신)

- Daheng MER2-503-23GM-P 를 지원할 계획이다. 이 카메라용 Adapter 는 제조사 SDK 를 받은 뒤 만든다 — 지금 배포본은 아직 이 카메라를 열지 못한다.
- 사진은 **2448×2048(약 6:5) 그대로** 보낸다(ROI·축소 없음). 흑백 영상은 세 채널이 같은 값인 JPEG 로 보낸다.
- 냉각팬 패널 세 검사항목의 가이드를 **2448×2048 화면비**로 다시 만들어 달라. 다시 만들면 R19 §4-4 를 닫는다.

### 5. 추가 요청

1. **`VIS-ROT-DIM` 가이드(Overlay)** — `description` 은 높이를 Overlay 로 맞추라고 하는데 지금 `overlay.available` 이
   `false` 다. 높이·위치를 맞출 가이드를 2448×2048 화면비로 등록해 달라.
2. **태블릿 항목을 거를 필드** — `TAB-` 항목이 거치대 Client 목록에도 나온다. Client 는 이름을 파싱하지 않으므로,
   촬영 방식(거치대·태블릿)을 나타내는 필드가 생기면 그 값으로 거른다. 정해지면 계약으로 알려 달라.

### 6. 정확도 안내 (참고)

높이 약 650mm 에서 8mm 렌즈로 찍으면 배율이 약 0.28mm/화소다(계약 예시 0.2831 과 같다). `VIS-ROT-DIM` 의 합격
범위 ±1mm 는 약 ±3.5화소다. 두 점을 손으로 찍는 방식과 기준물 하나로 구한 배율은 렌즈 왜곡을 보정하지 못하고,
540mm 치수는 세로 시야(약 574mm)를 거의 다 쓴다. 이 범위를 지킬 수 있는지는 현장 사진으로 확인해야 한다.
결과가 흔들리면 렌즈 보정이나 자동 측정을 먼저 검토한다.
