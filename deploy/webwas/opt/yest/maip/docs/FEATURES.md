# 기능

제조AI플랫폼이 사용자에게 무엇을 제공하는지 적는다. 메뉴, 역할별로 할 수 있는 일,
검사 이미지가 학습 데이터 파일이 되기까지의 흐름, 비전 검사 화면, 품목·BOM 조회·인터페이스 이력·입고와 수입검사 대상, 대시보드를 다룬다.

구조와 인가 방식은 [ARCHITECTURE.md](ARCHITECTURE.md), 테이블은 [DATA_MODEL.md](DATA_MODEL.md),
비전검사 클라이언트가 부르는 `/api/v1` 은 [client/SERVER_API_CONTRACT.md](client/SERVER_API_CONTRACT.md) 에 있다.

## 1. 메뉴 트리

근거: DECISIONS 사용자 결정 2026-10-19·2026-10-21, O-13.

좌측 메뉴는 `seed_initial.MENU_TREE`(폴더 6개 · 메뉴 행 29개)와 `app/views/system/menus.py` 가 만든다.
폴더 순서가 화면 순서다. **업무 흐름 기준으로 묶는다** — 현장 검사 작업이 맨 위, 그 기준(검사 관리)과 학습 데이터(비전 데이터 관리)가 다음, 조회·운영이 아래다.
메뉴 코드는 옛 화면 그대로라 권한·즐겨찾기가 남는다. 이름은 단어 단위로 띄우고 검사 종류는 "수입검사"·"품질검사"로 붙인다.

```text
대시보드                      wm_dashboard           ← 폴더 없는 1단계 링크(아이콘). 로그인 첫 화면. 내 할 일·현황(§10)

검사 작업                                             ← 현장 검사원. 수입검사 흐름 → 품질검사 흐름 → 비전 검사 이력(결과 화면을 한곳에)
├── 수입검사 작성             wm_dig_form_incoming_write   ← 디지털 입력 전환(§8.6). 옆에 검사 대기 건수 배지(§8.2)
├── 수입검사 결과             wm_dig_form_incoming_result
├── 품질검사 작성             wm_dig_form_outgoing_write   ← 검사 작업 목록(대기 = 작업지시, §8.2)
├── 품질검사 결과             wm_dig_form_outgoing_result
└── 비전 검사 이력            wm_vis_inspection      ← §6

검사 관리                                             ← 검사 기준과 비전 검사 설정. 위 셋은 양식 쪽, 아래 셋은 비전 쪽
├── 검사양식 관리             wm_dig_form_incoming_form ← 수입·품질 양식 한 목록(구분 열, §8.3). 코드는 옛 수입 검사양식 관리
├── 검사양식 코드 관리        wm_dig_form_judge_code ← 디지털 양식 판정 선택지(§8.5)
├── 수입검사 품목 지정        wm_product_form        ← 양식 기준 품번 지정, N:M(§8.2)
├── 비전검사항목 관리         wm_data_item           ← 대분류 › 중분류(양식 매핑) › 비전검사항목(AI 모델 매핑, §3.3)
├── 비전검사 Overlay 관리     wm_vis_overlay         ← §6
└── 비전검사 클라이언트 관리  wm_vis_client          ← 비전검사 클라이언트(장비) 등록(§6)

비전 데이터 관리                                      ← 첫 메뉴 다음에 검사 분류 트리(동적, §3.3)
├── 비전 데이터 등록          wm_data_register       ← 카메라·파일로 바로 등록(§5.7)
└── <대분류>                                          ← 수입검사·품질검사·미분류(고정). 볼 수 있는 비전검사항목이 있는 분류만. 소속 없는 항목은 "미분류" 아래(그 중분류 다음)
    └── <중분류>
        └── <비전검사항목 이름>   wm_data_item_detail    ← 끝 메뉴 = 비전검사항목 탭 하나. 그 안 내부 탭이 홈 · 데이터 목록 wm_data_image ·
                                                          라벨링 작업 wm_data_labeling · 검수 작업 wm_data_review · 스냅샷 관리 wm_data_snapshot

기준정보                                              ← 품목·BOM(PLM)·입고(ERP), 조회 전용(§9)
├── 품목·BOM 조회             wm_product_bom
└── 입고 내역                 wm_receipt             ← 검사 정보 없음(§9.3)

시스템 관리                                           ← 인터페이스 이력과 계정(부서·사용자)·권한·로그
├── 인터페이스 이력           wm_interface_log       ← PLM·ERP 수신건(§9.2)
├── 부서 정보                 wm_depart
├── 사용자                    wm_user
├── 사용자 그룹               wm_user_group
├── 메뉴 권한                 wm_user_group_menu
├── 메뉴명 설정               wm_menu_language
├── 로그인 로그               wm_login_log
├── 메뉴 로그                 wm_menu_log
└── 시스템 로그               wm_system_log
```

트리에 무엇이 보이는지는 네 규칙이 정한다.

| 대상 | 보이는 조건 |
|---|---|
| 일반 메뉴 | 사용자 그룹이 그 메뉴에 `R` 권한을 가졌다 |
| 비전검사항목 노드 | 모든 비전검사항목이다(삭제 승인 대기 항목은 플랫폼 관리자만). 하위 화면 R 이 하나도 없으면 노드도 없다. 누르면 홈(홈 권한이 없으면 권한 있는 첫 화면) |
| 대분류·중분류 노드 | 그 아래 볼 수 있는 비전검사항목이 있을 때만 |
| 비전검사항목 하위 5개 | 메뉴 트리에는 나오지 않는다. 비전검사항목 탭 안의 내부 탭으로 메뉴 권한을 받은 것만 보인다(치수 측정은 홈·데이터 목록만) |

- 하위 5개의 메뉴 행은 트리에서 감춰도 지우지 않는다. 메뉴 권한 화면과 그 화면 API(`/api/item/<view>`) 인가의 기준점이다.
- `wm_data_item` 은 코드가 데이터 관리 시절 그대로지만 메뉴는 검사 관리의 "비전검사항목 관리"다. 등록·수정·삭제 승인은 플랫폼 관리자만(§2.1). 데이터 화면은 자기 메뉴의 API 만 부르므로 작업자 그룹에는 이 권한이 필요 없다.
- 비전검사항목 하위 화면은 주소의 `?inspection_item=<비전검사항목 id>` 를 읽는다. 비전검사항목마다 셸 탭이 따로 열리고(제목 = 항목명), 하위 화면은 그 탭 안의
  내부 탭이다 — 머리 카드(항목명·작업 유형) 아래 탭을 누르면 그 화면을 `?embed=1` iframe 으로 처음 한 번 싣고 그 뒤로는 그대로 둔다(작업 상태 유지).
- 로그인하면 메뉴 맨 위 **대시보드**(`wm_dashboard`)가 닫을 수 없는 첫 탭으로 열린다.
  시스템 옵션 `main_menu` 에 메뉴 코드를 넣으면 그 화면으로 바뀐다. 그 메뉴 권한이 없으면 트리의 첫 화면이 열린다 —
  대시보드는 `seed_initial` 이 모든 사용자 그룹에 `RW` 로 준다(새로 만든 그룹은 `seed_initial` 을 다시 돌리거나 메뉴 권한 화면에서 준다).
- `menus.TOP_LEVEL_MENU_CODES` 에 든 메뉴(지금은 대시보드)가 혼자인 폴더는 폴더 없이 1단계 링크로 보인다(폴더의 아이콘을 쓴다).
- 메뉴에서 내린 화면(`seed_initial.RETIRED_FROM_MENU`)은 다루지 않는다. superuser·`dev` 그룹만 주소로 열 수 있다.

## 2. 역할

근거: DECISIONS 사용자 결정 2026-10-21.

권한은 **메뉴 권한 하나**로 본다 — 사용자 그룹 × 메뉴의 `R`/`W`. 조회(GET)는 `R`, 변경(POST·PUT·PATCH·DELETE)은 `W` 를 요구한다.
비전검사항목은 모두 보이고,
누가 무엇을 하는지는 그 사람의 그룹에 준 메뉴 권한이 정한다.

| 구분 | 정체 | 정해지는 곳 |
|---|---|---|
| 일반 사용자 | 사용자 그룹의 메뉴 권한 | 메뉴 권한 화면 |
| 플랫폼 관리자 | superuser, 또는 사용자 그룹 코드가 `admin`·`dev` | 계정·사용자 그룹 |

- 삭제 승인 대기 비전검사항목은 플랫폼 관리자만 본다.
- `seed_initial` 은 `admin` 그룹에 전 메뉴 `RW` 를, 모든 그룹에 대시보드 `RW` 를 준다. 작업자가 속할 그룹의 나머지 메뉴 권한은 메뉴 권한 화면에서 준다.
  예: 라벨러 그룹은 데이터 목록·라벨링 작업 `W` 와 홈·검수·스냅샷 `R`, 검수자 그룹은 검수 작업 `W` 까지.

더 볼 곳: 인가 판정 방식은 ARCHITECTURE §4.

### 2.1 할 수 있는 일

| 하는 일 | 필요한 메뉴 권한 |
|---|---|
| 비전검사항목 홈 보기 | `wm_data_item_detail` R |
| 이미지 업로드 · 편집 · 삭제(검수 완료 전) | `wm_data_image` W |
| 검수 완료 이미지 삭제 | `wm_data_image` W 와 `wm_data_review` W (승인한 권한과 같은 권한) |
| 라벨링 (시작·임시 저장·제출) | `wm_data_labeling` W |
| 검수 (승인·재작업 요청) | `wm_data_review` W |
| 스냅샷 등록 · 실패한 스냅샷 다시 만들기 | `wm_data_snapshot` W |
| 스냅샷 목록·분석 보기 · zip 받기 | `wm_data_snapshot` R (zip 받기 `/media/export/<id>/` 는 로그인과 그 조직의 항목만 본다) |
| 비전검사항목 설정 · 라벨 클래스 · 측정점 · 상태 전환 · 삭제 요청 | `wm_data_item_detail` W (비전검사항목 홈의 편집 창) |
| 비전검사항목 추가 · 삭제 승인/반려 · AI 모델 매핑 | 플랫폼 관리자 + `wm_data_item` W (비전검사항목 관리) |
| 검사 분류(중분류) 등록 · 수정 · 삭제 · 양식 매핑 | `wm_data_item` W |
| 비전 검사 화면(비전 검사 이력·Overlay·클라이언트) | 각 `wm_vis_*` |

- 쓰기 버튼은 화면이 숨기기도 하지만(비전검사항목 홈 편집, 스냅샷 등록) 최종 판정은 서버다. 거부는 403 이다.
- 검사 결과의 이미지 보기(`/media/image/<id>/`)는 로그인과 그 조직의 비전검사항목인지만 본다.

## 3. 비전검사항목

근거: DECISIONS O-8.

비전검사항목은 비전 검사의 대상이자 데이터 저장소다. 라벨 클래스·이미지·스냅샷·Export·
Overlay·AI 모델 매핑이 모두 비전검사항목에 매달린다.

### 3.1 유형

근거: DECISIONS 사용자 결정 2026-10-20·2026-10-21, DEC-031, DEC-032, O-14.

| `InspectionItem.TaskType` | 화면 표기 | 라벨링 방식 | Export 형식 |
|---|---|---|---|
| `OBJECT_DETECTION` | 객체 탐지 | 결함 영역 BBOX. 영역이 없으면 정상(배경) 이미지 | COCO |
| `CLASSIFICATION` | 분류 | 이미지 전체에 클래스 하나 | ImageFolder |
| `ANOMALY_DETECTION` | 이상 탐지 | 결함 유형별 Polygon 영역. 영역이 있으면 이상, 없으면 정상이다 — 정상 라벨은 없다 | MVTec AD(+ `metadata.json`). 한 이미지의 결함 유형이 여럿이면 `combined` |
| `MEASUREMENT` | 치수 측정 | 하지 않는다. 클라이언트가 잰 측정값을 측정점 하한~상한으로 판정한다. 사진은 증빙으로만 남는다 | 없다(스냅샷·Export 를 만들지 않는다) |

**분류 비전검사항목은 클라이언트가 카탈로그에 `include=classification` 을 줄 때만 나온다.** 0.1.6 이하 클라이언트가
아는 유형은 `DETECTION`·`ANOMALY` 둘뿐이다. 판정은 1순위 클래스가 불량 클래스인지로 정한다.

**치수 측정 비전검사항목은 `include=measurement` 를 준 클라이언트에만 나온다**. 라벨 클래스 대신 **측정점**(코드·이름·기준값·하한·상한·단위·측정 방법)을
비전검사항목 홈에서 관리하고, 내부 탭은 홈·데이터 목록만 나온다 — 라벨링·검수·스냅샷 API 도 거절한다. AI 모델 칸이 없다. 양식 편집기의 이미지 칸에는 연결할 수 있지만 검사작성에서 거치대 결과 불러오기로만 넣는다.

라벨 클래스는 비전검사항목 홈에서 관리한다(홈 메뉴 W).

- 새 클래스의 도형은 BBOX 다. Polygon 클래스는 새로 만들 수 없고 기존 것만 유지된다.
  이상 탐지는 클래스 도형과 관계없이 Polygon 으로 그린다.
- 이미 라벨링에 쓰인 클래스는 지울 수 없다.
- `is_defect=False` 인 클래스가 정상 클래스다. 분류 비전검사항목에서 "라벨 작업 없이 업로드"를 쓰려면 정상 클래스가 정확히 하나여야 한다.

### 3.2 상태와 삭제

근거: DECISIONS Q9.

| `InspectionItem.Status` | 화면 | 뜻 |
|---|---|---|
| `ACTIVE` | 사용 | 정상. 카탈로그에 나오고 검사를 받는다 |
| `PAUSED` | 중지 | 카탈로그에서 빠지고 클라이언트 검사 전송을 거절한다. 데이터 작업은 계속된다 |
| `DELETION_PENDING` | 삭제 승인 대기 | 플랫폼 관리자 외에는 트리·목록에서 사라진다 |

```text
ACTIVE ⇄ PAUSED                       비전검사항목 홈 W(편집 창) 또는 플랫폼 관리자(비전검사항목 관리)
PAUSED ──삭제 요청──▶ DELETION_PENDING   비전검사항목 홈 W. ItemDeletionRequest = REQUESTED
DELETION_PENDING ──반려──▶ PAUSED         플랫폼 관리자. 요청 = REJECTED
DELETION_PENDING ──승인──▶ (삭제)          플랫폼 관리자. 요청 = APPROVED
```

- 삭제는 이미지·라벨·스냅샷·Export 파일까지 지우므로 승인을 거친다.
- 중지 상태에서만 삭제를 요청할 수 있다. 삭제 승인 대기 중에는 상태를 바꿀 수 없다.
- 검사 이력(`vision_inspection`)이 있는 비전검사항목은 삭제 승인 때 파일을 지우기 전에 거절한다(400). DB 도 `PROTECT`(`VisionInspection.item`)로 막는다.
- 비전검사항목 추가는 플랫폼 관리자만 한다. 입력은 이름·설명·유형·촬영 방식·검사 분류이고, 내부 업로드 데이터셋이 함께 생긴다.

### 3.3 검사 분류

근거: DECISIONS 사용자 결정 2026-10-21.

비전검사항목은 **대분류 › 중분류** 아래에 둔다. 대분류는 **수입검사·품질검사·미분류 셋으로 고정**이다(`category.FIXED_MAJORS` — 화면에서 만들거나 고치거나 지우지 않는다). 수입검사·품질검사는 양식 구분(수입/품질)을 갖고, 미분류는 구분이 없어 그 중분류에 양식을 매핑하지 않는다.
중분류는 검사 시트이고 그 구분의 **섹션 양식 하나**를 매핑한다(양식 코드 — 버전 무관. 양식 하나는 중분류 하나에만). 양식이 아직 없는 중분류도 둔다.

- 비전검사항목은 처음 공식 판정하는 시트의 중분류 하나에 속한다(없으면 미분류 대분류 아래에 바로 보인다). 다른 양식에서는 이미지 칸 연결로 같은 항목을 쓴다(Bolt I-Marking 처럼 여러 시트에 반복되는 확인)
- 비전검사항목 관리(검사 관리, `wm_data_item`): 트리 한 목록(대분류 › 중분류 › 비전검사항목)과 상세. 목록 머리 [중분류 등록]·[비전검사항목 등록](플랫폼 관리자). 상세는 고른 행 종류에 따라 대분류(이름·양식 구분·순서·설명 — 읽기만, [수정]·[삭제] 없음)·중분류(대분류·이름·매핑 양식·순서·설명)·비전검사항목(§5.1)이다
- 중분류 등록·수정·삭제·양식 매핑은 메뉴 W(`/api/item/category`), 비전검사항목 등록·수정·중지·삭제 승인은 플랫폼 관리자만(`/api/item/item_admin`)
- 비전검사항목이 있는 중분류는 지우지 않는다. 매핑을 풀어도 양식 이미지 칸의 연결은 그대로다
- 매핑한 양식에서 이 분류를 어떻게 쓰는지(이미지 칸 연결·사진 넣기)는 §8.8
- 클라이언트 카탈로그(`/api/v1`)에는 분류를 내보내지 않는다

## 4. 데이터 흐름

```text
 업로드(화면) ─┐
               ├─▶ 편집(선택) ─▶ 라벨링 ─▶ 제출 ─▶ 검수 ─┬─ 승인 ─▶ 스냅샷 등록 ─▶ zip 생성 ─▶ 받기
 클라이언트 ───┘    전처리        claim     SUBMITTED    │   APPROVED   manifest 고정   (워커)     (화면)
 검사 전송                                              └─ 재작업 ─▶ REWORK ─▶ 다시 라벨링
```

### 4.1 이미지 상태

화면은 `label_status` 를 다섯 단계 업무 상태로 바꿔 보인다.

| `ImageAsset.LabelStatus` | 화면 단계 | 들어가는 때 |
|---|---|---|
| `UNLABELED` 미작업 | 작업 대기 | 업로드 직후 |
| `IN_PROGRESS` 작업중 | 작업 중 | 라벨링 시작(claim) · 임시 저장 |
| `SUBMITTED` 제출됨 | 작업 완료 | 제출. 또는 "라벨 작업 필요"를 끄고 업로드 |
| `REWORK` 재작업 필요 | 작업 대기 | 검수에서 재작업 요청. 사유가 `rework_reason` 에 남는다 |
| `APPROVED` 작업완료 | 검수 완료 | 검수 승인 |

### 4.2 업로드

근거: DECISIONS Q4.

이미지가 들어오는 경로는 넷이고, 이미지마다 **등록 경로**(`channel`)와 **등록자**(`uploaded_by`)를 남긴다.

| 등록 경로 | 들어오는 곳 | 필요한 권한 | 등록자 |
|---|---|---|---|
| 클라이언트 | 비전검사 클라이언트 검사 전송(§6.2) | `X-Client-ID`·`X-API-Key` | 클라이언트 서비스 계정(`svc-<client_id>`, 이름은 클라이언트 이름) |
| 파일 업로드 | 데이터 목록의 업로드 창, 비전 데이터 등록의 [파일] | 데이터 목록 `W` / 비전 데이터 등록 `W` | 올린 사용자 |
| 카메라 촬영 | 비전 데이터 등록의 [카메라] | 비전 데이터 등록 `W` | 찍은 사용자 |
| 양식 사진 넣기 | 검사작성의 사진 넣기(§8.8, `capture`) | 그 구분의 검사작성 `W` | 넣은 사용자 |

옛 이미지는 Client 가 보낸 것(`source_inspection_id` 가 있음)이면 클라이언트, 아니면 파일 업로드이다. 등록자는 모두 비어 있다.
아래 표는 파일을 올리는 경로(데이터 목록·비전 데이터 등록)의 규칙이다.

| 항목 | 값 |
|---|---|
| 형식 | PNG, JPG/JPEG (확장자·MIME·실제 내용 모두 검사) |
| 크기 | 파일당 30MB, 5천만 화소 이하 |
| 개수 | 요청당 20개(`ImageService.MAX_FILES_PER_REQUEST`). 넘친 파일은 거절 목록에 "한 번에 20개까지 올릴 수 있습니다."로 돌아온다. 화면은 고른 파일을 20개씩 나눠 차례로 보내고, 묶음 하나가 실패해도 다음 묶음을 보낸다 |
| 중복 | 같은 비전검사항목에 같은 SHA-256 이 있으면 거절한다. 클라이언트 검사 전송은 허용한다 |
| 결과 | 파일별로 성공·거절 사유를 돌려준다. 일부 거절이어도 요청은 성공이다 |

파일마다 **라벨 작업 필요**를 끌 수 있다. 끄면 결함 없는 정상 이미지로 보고 `SUBMITTED` 로 올려 검수를 기다린다.
분류는 정상 클래스를 자동으로 붙이고, 객체·이상 탐지는 라벨 없이 올린다(영역이 없으면 정상).

### 4.3 편집(전처리)

데이터 목록 상세의 **이미지 편집**. 회전(90°·180°·270°)·자르기·원근 보정·크기 조정을 연산 목록(최대 20개)으로 저장한다.

- 원본을 `original_file` 에 보존하고 매번 원본에서 다시 계산한다. 빈 목록을 저장하면 원본으로 돌아간다.
- 라벨 좌표가 어긋나지 않도록 **라벨링 전 이미지만** 편집한다. 막히는 경우(400, 이유를 문구로 돌려준다):
  `UNLABELED` 가 아님 · 라벨이 있음 · 누가 작업 중 · 스냅샷에 포함됨.

### 4.4 라벨링

근거: DECISIONS DEC-032.

라벨링 작업 화면. 작업자가 이미지를 골라 직접 시작한다(관리자가 나눠 주는 기능은 없다).

| 단계 | 동작 | `LabelingTask.Status` |
|---|---|---|
| 작업 시작 | 30분 lease 를 받는다. 다른 사람의 유효한 lease 가 있으면 거절, 만료됐으면 넘겨받는다 | `CLAIMED` |
| 임시 저장 | 현재 영역 전체를 교체 저장한다 | `IN_PROGRESS` |
| heartbeat | 화면이 5분마다 보내 lease 를 30분 연장한다 | — |
| 작업 완료(제출) | 이미지가 `SUBMITTED` 가 되고 lease 가 풀린다 | `SUBMITTED` |

- 이미지 하나에 활성 작업(`CLAIMED`·`IN_PROGRESS`)은 하나뿐이다(DB 제약).
- `SUBMITTED`·`APPROVED` 이미지는 시작할 수 없다. `REWORK` 는 다시 시작할 수 있다.
- 객체·이상 탐지는 영역을 그리지 않고 제출하면 정상이다("결함 없음으로 제출하시겠습니까?"를 한 번 묻는다). 이상 탐지 라벨 목록에
  `정상` 은 없고 결함 유형만 있다. 분류는 정상 클래스를 고른다.

### 4.5 검수

검수 작업 화면. 제출된(`SUBMITTED`) 이미지만 나오고 검수 작업 W 가 있어야 처리한다.

| 버튼 | 결과 |
|---|---|
| 검수 완료 | `APPROVED`. 스냅샷 대상이 된다 |
| 재작업 요청 | `REWORK`. 사유가 필수다. 작업자의 대기 목록으로 돌아간다 |

### 4.6 스냅샷과 Export

근거: DECISIONS DEC-019, Q4.

스냅샷 관리 화면의 **스냅샷 등록**. 스냅샷 관리 W 가 있어야 등록한다.

1. Export 형식은 **비전검사항목 유형마다 하나로 고정**이다(§3.1). 등록 창·목록·상세 어디에도 형식을 보이지 않는다. 목록 열은 버전·등록일·이미지 수·상태·다운로드다.
2. 등록하는 순간 **검수 완료(`APPROVED`) 이미지만** manifest 에 고정한다. 태그는 `v1.0`, `v2.0` … 순번이다.
   검수 완료 이미지가 없으면 등록하지 않는다("검수 완료된 이미지가 없어 스냅샷을 만들 수 없습니다.").
   같은 내용(sha256)의 이미지가 여럿이면 먼저 들어온 한 장만 넣는다.
   **직전 스냅샷과 이미지·주석이 같으면 등록하지 않는다**("직전 스냅샷 v1.0 과 데이터가 같아 새 스냅샷을 만들지 않습니다."). 이미지 수가 같아도 주석이 바뀌었으면 새로 만든다.
3. 같은 요청에서 Export 작업이 적재되고 워커(`run_worker`)가 zip 을 만든다.
4. 목록의 상태가 `완료` 가 되면 **받기** 링크가 붙는다. 화면은 대기·실행 중인 행이 있으면 3초마다 다시 읽는다.

- 스냅샷은 바뀌지 않는다. **스냅샷에 든 이미지는 삭제도 편집도 할 수 없다.**
- 상세는 요약 수치와 유형별 분석(클래스 분포·편중 경고·정상/이상 수)을 보인다.
- 등록하면 Wezard 가 가져갈 **Wezard 전송용 zip**(`wezard-dataset/v1`)도 함께 만든다. 목록·받기는 고정 형식만 보이고, 상세에 "Wezard 전송용 zip" 상태(실패면 사유 — 주로 Wezard 최소 조건 미달)가 있다.
- **다시 만들기**는 고정 형식이나 Wezard 전송용 zip 이 실패했거나 없을 때 보이고, 그것만 다시 적재한다. 고정 형식이 아닌 예전 zip 은 다시 만들기 전까지만 받을 수 있다.
- MVTec AD zip 에는 이미지별 정보(플랫폼 이미지 ID·정상/이상·결함 유형·마스크) `metadata.json` 이 함께 든다.
- 파일은 `/media/export/<id>/` 로 권한을 확인하고 내려준다.
- Wezard 는 전송용 zip 을 `/api/v1/datasets/snapshots` 로 받아 간다.

더 볼 곳: 워커 상태와 멈춘 작업의 재처리는 ARCHITECTURE §8, Wezard 계약은 Wezard/maip-api.md, Wezard 연동 키 운영(`integration_key`)은 DEPLOYMENT §8-2.

### 4.7 이미지 삭제 제약

데이터 목록 상세의 **데이터 삭제**. 상세 응답이 `can_delete` 와 막힌 이유(`delete_blocked_reason`)를 함께 준다.

| 막히는 경우 | 응답 |
|---|---|
| 누가 라벨링 중(활성 작업이 있음) | 400 |
| 검수 완료(`APPROVED`)인데 요청자에게 검수 작업 W 가 없음 | 403 |
| 스냅샷에 포함됨 | 400 |

## 5. 데이터 관리 화면

근거: DECISIONS DEC-028.

모두 MES 화면 구조(제목 카드 → 검색 카드 → 그리드 → 상세 카드)이고, 라벨링 작업대만 3열 구조를 유지한다.

### 5.1 비전검사항목 관리 (검사 관리, `data/item_list.html`)

- 검사 분류 트리(대분류 › 중분류 › 비전검사항목, §3.3). 목록 **매핑** 열: 중분류는 "양식 <코드> · <양식명>", 비전검사항목은 "AI 모델 <이름>"
- 중분류 등록·수정·삭제·양식 매핑은 메뉴 W(대분류는 고정)
- 비전검사항목 등록은 플랫폼 관리자 — 검사 분류 선택, 작업 유형(객체 탐지·분류·이상 탐지·치수 측정), 촬영 방식(고정 거치대·태블릿 — 태블릿 항목은 클라이언트 카탈로그에 나오지 않는다)
- 상세 [수정]에서 설명·사용 여부(토글)·촬영 방식·검사 분류·**AI 모델**(§6.5)을 저장한다(공통 CRUD). 삭제 승인 대기 항목은 [수정] 대신 삭제 요청 반려·승인

### 5.2 비전검사항목 홈 (`data/item.html`)

- 좌측 메뉴의 비전검사항목 하나가 셸 탭 하나다. 머리 카드(대표 이미지·항목명·작업 유형 — 사용 여부는 보이지 않는다) 아래 **내부 탭**(홈·데이터 목록·라벨링 작업·검수 작업·스냅샷 관리 — 메뉴 권한이 있는 것만, 치수 측정은 홈·데이터 목록만)으로 하위 화면을 오간다
- 하위 화면은 처음 누를 때 `?embed=1` 로 싣고 그 뒤로는 그대로 둔다(작업 상태 유지, 바깥 스크롤 없이 남은 높이를 채운다)
- 홈: 설명(기본 접힘, 펴고 접기), 요약 카드(전체 이미지·작업 대기·작업 중·작업 완료(검수 대기)·검수 완료), 라벨 클래스(결함 여부)와 최근 스냅샷(최근 5개, 받기)을 한 줄에 나란히, 그 아래 최근 데이터
- 최근 데이터·[전체 보기]는 그 내부 탭으로 열고, 홈으로 돌아오면 요약을 다시 읽는다
- 편집 창(홈 메뉴 `W`, 홈 탭에서만, 탭 2개): 이름·설명·대표 이미지·상태 전환·삭제 요청 / 라벨 클래스 추가·수정·삭제
- 치수 측정 항목은 라벨 클래스 자리가 측정점(추가·수정·삭제, 측정 결과가 있는 코드는 바꾸거나 지울 수 없다)이고 요약 카드는 전체 이미지만

### 5.3 데이터 목록 (`data/image.html`)

- 상태·라벨·등록일·파일명 검색, 썸네일 그리드(서버 페이징, 등록일 최신순 — 날짜 열도 등록일)
- **수집** 열(등록 경로 넷: 클라이언트·파일 업로드·카메라 촬영·양식 사진 넣기), **라벨 결과** 열(작업자가 제출한 라벨 기준 정상/이상, 제출 전은 `-`, AI 판정은 보지 않는다)
- 상세: 미리보기(휠 확대·끌어 이동·더블클릭 원래대로, BBOX·Polygon 에 결함 이름표), 수집 경로·진행 단계(재작업이면 사유)·라벨 결과·**결함 내역**(결함별 색 칩·이름·영역 수, 분류는 클래스 이름)
- 업로드(§4.2), 이미지 편집, 삭제

### 5.4 라벨링 작업 (`data/labeling.html`)

- 좌측 대기열은 작업할 이미지(대기·작업 중·재작업)를 먼저 들어온 순으로 **50장씩**
- 이미지 선택 → 작업 시작 → 그리기 → 임시 저장 → 작업 완료 → 다음 작업
- 확대는 50~400%(휠은 커서 자리 기준), 끌면 화면이 옮겨진다. [대표 이미지]를 켜면 왼쪽에 비전검사항목 대표 이미지, 오른쪽에 작업 이미지를 같은 배율·위치로 나란히 보인다(그리기는 오른쪽만)
- 그리기 방식은 라벨 클래스를 고르면 정해진다(객체 탐지는 라벨의 도형, 이상 탐지는 Polygon)
- 머리 왼쪽(제목 옆)에 **남은 작업** `지금 위치 / 남은 수`, 오른쪽에 작업 시간과 버튼. 작업 완료율은 두지 않는다

### 5.5 검수 작업 (`data/review.html`)

- 제출된(작업 완료) 이미지 그리드(화면 안 20건씩, **라벨 결과** 열은 데이터 목록과 같다)
- 상세: 미리보기·결함 이름표·라벨 결과·결함 내역(결함이 없으면 "결함 영역이 없습니다(정상).")
- 검수 완료 · 재작업 요청(사유 필수). 처리하면 다음 행이 이어서 열린다

### 5.6 스냅샷 관리 (`data/snapshot.html`)

- 스냅샷 등록(직전과 같으면 거절)·목록·분석, 완료된 zip 받기, 실패한 스냅샷 다시 만들기

### 5.7 비전 데이터 등록 (`data/register.html`)

근거: DECISIONS 사용자 결정 2026-10-23.

비전검사항목을 거치지 않고 카메라나 파일로 바로 등록하는 화면이다. 메뉴는 비전 데이터 관리의 첫 항목이다(§1).

- 권한: 이 메뉴 `R` = 목록·상세, `W` = 등록·편집·삭제. **데이터 목록 `W` 는 필요 없다.** 검수 완료 이미지 삭제는 지금처럼 검수 작업 `W` 도 있어야 한다
- 등록 대상: 사용 중(`ACTIVE`) 비전검사항목. 치수 측정 항목은 뺀다
- 조회: 비전검사항목·등록 경로·등록일 기간(기본 최근 7일)·파일명. 목록은 서버 페이징 50건, 등록일 최신순. 주소 `?inspection_item=<id>` 로 열면 그 항목으로 거른다(대시보드 줄에서 연다)
- 목록 열: 썸네일·비전검사항목·등록 경로·파일명·진행 단계·등록자·등록일시
- 상세: 왼쪽 원본(확대·이동), 오른쪽 표(항목·등록 경로·등록자·등록일시·원본 파일명·크기·진행 단계). [이미지 편집]·[삭제]는 데이터 목록과 같은 규칙이다 — 라벨링 전만 편집하고, 작업 중이거나 스냅샷에 든 이미지는 막는다(막히면 비활성과 이유)
- [데이터 등록]: 비전검사항목을 고르고 [카메라]/[파일]
    - 카메라: 항목 Overlay 가 표시 중이면 겹쳐 보인다. HTTPS·localhost 가 아니면 기기 카메라 앱을 연다(§8.8 과 같은 부품). 같은 사진도 허용한다
    - 파일: 여러 장을 올리고 올린 수·거절 목록을 알린다(나눠 보내기·중복 거절은 §4.2)
- 라벨링·검수·여러 장 일괄 삭제는 이 화면에서 하지 않는다
- 카메라 촬영(`data/camera_capture.html`)과 이미지 편집(`data/preprocess_modal.html`)은 다른 화면과 같이 쓰는 부품이다

### 공통

각 화면은 자기 메뉴의 API(`/api/item/<view>`, `domain/gui.py` `item/<view>` 매핑) 하나만 부른다.
그 화면을 쓰는 그룹에는 그 메뉴 권한만 있으면 된다(변경은 W).

## 6. 비전 검사

비전검사 클라이언트는 현장 검사 PC 에서 도는 별도 프로그램이다. 서버는 클라이언트를 등록하고,
클라이언트가 보낸 검사를 받아 저장하고, 결과를 보여 준다.

### 6.1 비전검사 클라이언트 관리 (`wm_vis_client`)

근거: DECISIONS Q5.

| 동작 | 내용 |
|---|---|
| 등록 | [등록] 모달에 Client ID·이름(필수)과 사용 여부를 넣는다. Client ID 는 중복될 수 없다 |
| API Key 발급 | 등록 응답에 **한 번만** 원문이 나온다. 서버는 SHA-256 해시만 저장하므로 다시 볼 수 없다 |
| 키 재발급 | [수정] 모드에서 API Key 칸 옆 [재발급]. 확인을 거쳐 새 키를 한 번 보여 주고 기존 키는 즉시 무효가 된다. 현장 설정을 바꿔야 한다 |
| 수정 | [수정] → 이름·"사용" 토글(활성화/비활성화) → [저장]. 비활성화한 클라이언트는 인증에 실패한다. Client ID 는 바꿀 수 없다 |
| 삭제 | 검사 기록이 없을 때만 된다. 서비스 계정도 함께 지운다. 기록이 있으면 "검사 기록이 있어 삭제할 수 없습니다. 사용을 해제해 주세요."(→ 비활성화) |
| 목록 | 마지막 접속 시각(`last_seen_at`). 20건씩. 검색 칸 없이 [조회]만 있다 |
| 배포본 받기 | 목록 위 [배포본 받기] → 배포본 zip 의 파일명·크기·SHA-256 과 [받기]. 현장 PC 와 같은 경로(`/api/v1/client-packages`, 인증 없음·이어받기)로 받는다. 올리기는 화면에 없다 — 서버에 반입한다 |

- 등록하면 서비스 계정 `svc-<client id 소문자>` 가 생긴다. 웹 로그인은 할 수 없고, 클라이언트가 보낸 이미지의
  업로더로 기록하는 데만 쓴다.

더 볼 곳: 배포본 반입은 DEPLOYMENT §8-1.

### 6.2 검사 수신 → 데이터 관리

근거: DECISIONS O-9.

클라이언트가 `POST /api/v1/inspections` 로 보낸 이미지는 접수와 함께 **데이터 관리 이미지로 저장되어**(`UNLABELED`) 바로 라벨링 대상이 된다.

|---|---|
| `RECEIVED` | 접수됨. 매핑이 있는데 추론하지 못했으면 "접수됨 (추론 미실행 · Wezard 미설정)" 또는 "… · 배포 모델 없음)" |
| `SUCCESS` | 판정 완료 |
| `FAILED` | 실패 — Wezard 시간 초과·연결 실패·오류. 사유는 상세의 비고 칸에만 보인다 |

### 6.3 비전 검사 이력 (`wm_vis_inspection`)

- 비전검사항목·클라이언트·상태·기간으로 거른다. 기간 기본값은 오늘을 포함한 최근 7일이다. 서버 페이징(20건씩, 최신순 고정 — 헤더 정렬 없음). 목록에 **판정** 열(정상/이상, 이상은 붉게)이 있다.
- 상세 정보: 왼쪽에 원본 이미지(휠 확대·끌어 이동·더블클릭 원래대로), 오른쪽 표는 이상 판정·상태·비고(오류 사유)·분류 결과(표시 이름과 확률)·검출 결함(표시 이름과 신뢰도)·치수 측정의 측정점별 줄(값 단위 (하한~상한) 합격/불합격, 불합격은 붉게)·이상 점수·임계값(소수 셋째 자리)·비전검사항목·클라이언트(버전)·모델·추론 시간·촬영 시각·카메라·검사 ID 순이다(줄 순서·빈 줄 숨김은 DESIGN §5.5). 치수 측정은 모델 줄도 숨긴다.
- 조회 조건 바로 아래가 검사 목록이다. 최근 7일 집계(`action=dashboard`)는 화면이 부르지 않는다(대시보드는 자기 API 로 센다, §10).

### 6.4 비전검사 Overlay 관리 (`wm_vis_overlay`)

근거: DECISIONS DEC-C14.

Overlay 는 클라이언트 화면에 겹쳐 보이는 기준 이미지다. 비전검사항목마다 하나다.
목록에는 Overlay 가 없는 비전검사항목도 나온다.

| 동작 | 내용 |
|---|---|
| 등록 · 교체 | 상세 정보는 비전 검사 이력처럼 왼쪽에 Overlay 이미지(휠 확대·끌어 이동), 오른쪽 표(비전검사항목·버전·표시·불투명도·이미지 파일·수정일)다. [수정] → 표시 토글·불투명도·이미지 파일 → [저장]. PNG/JPEG, 10MB 이하. 불투명도 0.0~1.0 (기본 0.7). Overlay 가 없는 비전검사항목은 이미지가 필수다 |
| 버전 | 처음 등록하면 1. **이미지를 교체할 때만** 1 오른다. 클라이언트가 이 값으로 캐시를 지운다. 불투명도·표시만 바꾸면 그대로다 |
| 표시 | 표시를 비활성화해 저장하면 클라이언트에는 Overlay 가 없는 것과 똑같이 보인다 |
| 삭제 | 없다 — 행이 곧 비전검사항목이다. 숨기려면 표시를 비활성화한다 |

### 6.5 AI 모델 매핑 (비전검사항목 관리)

비전검사항목마다 판정에 쓸 Wezard 모델 하나를 검사 관리 > 비전검사항목 관리에서 고른다 — 목록의 **매핑** 열(비전검사항목 행은 "AI 모델 <이름>")로 보고, 상세의 **AI 모델** 칸에서 고친다(§5.1).
로직은 `domain/services/vision/model_mapping.py`, API 는 `/api/item/item_admin`(`models`·`update`)이다. 치수 측정 항목은 모델을 쓰지 않아 칸이 없다.

- [수정]을 누르면 그 비전검사항목 유형의 **Wezard 배포 모델**(이름별 최신 버전)을 받아 선택지로 보인다. 비전검사항목 코드를
  소문자로 바꾼 이름이 맨 앞("· 권장")이다. 분류 비전검사항목은 Wezard 분류 모델에서 고른다.
- 모델 **이름**으로 매핑하고 추론 때마다 그 이름의 최신 배포 버전을 쓴다(다시 배포해도 매핑을 고치지 않는다). 배포가 풀린 모델은 선택지에 "(배포 없음)"으로 보인다.
- 새로 매핑하면 기존 매핑은 지우지 않고 비활성으로 남긴다(어떤 모델로 판정했는지 이력이 필요하다).
- 임계값 재지정은 화면에 칸이 없다. 저장하면 직전 재지정 값을 이어 받는다.
- 매핑을 해제하려면 "(매핑 없음)"을 골라 저장한다. 모델을 바꿨을 때만 저장 때 Wezard 에 확인하고, 배포되지 않은 모델이면 설명·사용 여부도 저장하지 않는다.
- 모델을 등록하는 메뉴는 없다. Wezard 설정이 없거나 목록을 받지 못하면 지금 모델만 두고 까닭을 칸 아래에 보인다.

## 8. 디지털 입력 전환

근거: DECISIONS 사용자 결정 2026-10-16 ~ 2026-10-21, DEC-034, DEC-035.

종이 점검표·성적서를 화면 양식으로 만들어 현장에서 작성하고 조회한다. 개발 중 기능이다.

### 8.1 개요

근거: DECISIONS 사용자 결정 2026-10-16·2026-10-19·2026-10-21.

**구분과 세 단계.** 양식은 수입검사(`INCOMING`)·품질검사(`OUTGOING`) 중 한 구분에만 속한다(`DigForm.FormType`).

디지털 전환 화면은 1024 폭에서도 가로 스크롤이 없다(양식 편집기 제외).

**용어**

| 용어 | 뜻 |
|---|---|

| 작성건 | 양식 하나로 쓴 검사 한 건(`dig_form_result`). 상태는 **작성 중**·**완료** 둘이고 완료는 되돌리지 않는다 |
| 차수 | 같은 양식코드·입고번호(WO)로 완료된 검사가 있는데 새로 쓰면 오르는 번호(`Round`) |
| 대기 | 아직 쓰지 않은 검사 작업. 저장하지 않고 그때 센다 — 수입은 매핑된 (입고 × 양식), 품질은 작업지시(아직 없음, 8.2) |

**권한**

| 하는 일 | 필요한 메뉴 권한 |
|---|---|
| 양식·작성 결과·사진 조회 | 디지털 양식 메뉴 5개(검사양식 관리 + 구분별 검사작성·검사결과) 중 하나의 `R` |

| 판정 선택지 관리 | 검사양식 코드 관리 `W`. 이 메뉴만으로는 작성·조회 API 가 열리지 않는다 |
| 수입검사 품목 지정 | 수입검사 품목 지정 `W` |

### 8.2 업무 흐름

근거: DECISIONS 사용자 결정 2026-10-19·2026-10-20·2026-10-21.

**수입검사**

```text
① 수입 검사양식을 만든다(8.3)
② 수입검사 품목 지정에서 양식마다 검사할 품번을 더한다(N:M, 리비전 무관)
③ ERP 구매요청을 받아 반영한다(import_interface → apply_interface) — 구매요청 한 줄 = 입고 한 줄(§9.3)
④ 매핑된 (입고 × 양식) 중 그 양식코드·입고번호로 쓴 작성건이 없는 것이 수입검사 작성의 "대기" 작업이 된다
⑤ 좌측 메뉴 "수입검사 작성" 옆 배지가 검사 대기 건수를 알린다
⑥ 대기 행 [작성](사용 중인 최신 버전 + 입고번호로 새 작성) → [저장] … → [완료](8.6)
⑦ 수입검사 결과에서 본다(8.7)
```

- 대기 = 매핑된 (입고 × 양식코드) 중 그 양식코드·입고번호로 쓴 작성건(상태·버전 무관)이 없는 것이다(`action=job_list`). 양식의 가장 높은 버전이 사용 중이 아니면 나오지 않는다
- 검사 1건 = 입고 1줄이다. 입고번호(요청번호`-`요청순번)가 작성건 `WorkOrderNumber` 에 들어간다
- 검사 대기 배지 = 대기 작업 + 매핑된 (입고 × 양식) 중 작성 중이고 완료가 없는 것(`action=job_count`). 메뉴를 그릴 때·5분마다·검사 [완료] 뒤에 다시 센다. 그 메뉴 권한이 있어야 보인다
- 입고와 무관한 **수기 작성**도 된다 — [신규 작성] 뒤 모달의 [자재입고 검색]이 검사 대상 입고(품번에 양식이 매핑된 입고, 입고일 앞뒤 30일, 100건까지)를 골라 입고번호를 채운다
- **수입검사 품목 지정**(`/api/system/product_form`): 공통 CRUD 구조다. 위 수입검사 양식 목록(사용 중인 최신 버전, 매핑 품목 수) → 고르면 아래 상세에 양식 정보와 검사할 품번(가장 나중 리비전의 이름). 양식은 검사양식 관리에서 만들므로 [수정]만 둔다. [수정] 중 [품목 추가]는 목록에 없는 품번을 검색해(100건까지) 체크한 것을 더하고, 행 [삭제]는 목록에서 뺀다. [저장]이 그 양식의 매핑을 목록대로 맞추고(`action=save`) [취소]는 되돌린다
- 판/가공품 입고 N건을 한 시트의 행 N개로 쓰는 것과 대분류(판금·가공) 규칙 매핑은 하지 않는다

**품질검사**

```text
작업지시 등록(품질 양식 선택 + WO) → "대기" → [작성] → [저장] … → [완료] → 품질검사 결과
또는 [신규 작성](사용 중인 최신 양식 선택, WO 검색으로 채움) → [저장] … → [완료]
```

- 작업지시는 품질검사의 출발점이고 품질검사 작성의 검사 작업 목록(대기 = 작업지시 중 아직 쓰지 않은 것 + 작성 중)에서 다룬다
- 작업지시 데이터 출처(ERP/MES 수신 또는 현장 등록)를 정하기 전이라 **테이블·API 가 없다** — 대기는 비어 있고(상태 "대기"로 거르면 빈 목록), [작업지시 등록]은 "준비 중" 안내만 띄운다. WO 검색은 작성건의 WO 를 임시 출처로 쓴다
- 연결하면 대기 행 [작성]이 그 양식(작업지시를 등록할 때 고른 품질 양식)·작업지시번호(WO)로 새로 쓴다. 품질 검사양식은 작업지시를 등록할 때 고르는 것으로 둔다(수입검사 품목 지정은 수입검사 전용)

### 8.3 검사양식 관리 (`wm_dig_form_incoming_form`)

근거: DECISIONS 사용자 결정 2026-10-16.

메뉴 코드는 옛 수입 검사양식 관리 그대로다(권한·즐겨찾기를 남긴다).

- 목록: 수입·품질 양식(**구분** 열). 구분·양식코드/명·사용여부·최신 버전만으로 조회, 50건씩 페이지
- 행의 [조회]로 **양식 상세 조회** 모달(화면 폭 최대)을 연다. 모달 오른쪽 위
    - [검사 작성]: 그 양식으로 그 구분의 검사작성 탭을 연다
    - [수정]: 섹션 양식이면 양식 편집기(8.4), 칸 단위 양식이면 **입력칸 설정**
    - [삭제]: 칸 단위 양식의 그 버전 하나를 지운다(섹션 양식은 편집기의 [삭제])
- 목록 위 [양식 작성]: 편집기에서 **구분**(수입검사·품질검사, 목록에서 거른 구분이 기본값)을 골라 새 양식을 등록한다. 수정·새 버전은 원래 구분을 잇는다
- 새 양식 코드는 순번으로 붙는다(`DF`+4자리)

**입력칸 설정**(칸 단위 양식): 본문 칸을 눌러 입력 여부·입력 방식(문자·숫자(상하한)·판정 — 판정은 판정 코드의 그룹을 고른다)을 정한다.
작성 결과가 있는 양식은 처음 적용할 때 같은 코드의 최신+1 새 버전을 만들어 거기서 바꾸고(지금 버전과 결과는 그대로), 모달은 새 버전으로 설정을 잇는다.
섹션 양식은 작성 결과가 있으면 칸 설정을 막는다(편집기로 고친다).

**버전 규칙**

- 점검항목(칸 구성 — 열·행·상하한·섹션 이미지·작업자 열, 점검항목 섹션 추가·삭제, 고정 이미지·그 병합, 이미지 칸의 비전검사항목 연결)을 바꿔 저장하면 같은 코드로 최신+1 새 버전을 만들고 원래 버전은 그대로 둔다
- 점검항목이 그대로면 작성 결과가 있어도 그 버전을 고친다(기본정보·머리글·머리글 섹션·참고사진·섹션 배치·크기·열 폭)
- 버전 삭제는 작성 결과가 있으면 막는다

**고객 양식**: 완성된 DF0012~DF0026 15종의 최신 버전(검사 분류에 매핑된 수입 DF0012 가공품·DF0015 Rotor·DF0016 전장 ASSY, 품질 DF0014 8계통·DF0020 Module·DF0021 출하검수 포함)은 `seed_dig_form` 이 기본 데이터로 넣는다 — 이미지 칸의 비전검사항목 연결과 중분류 매핑까지 넣는다.

### 8.4 양식 편집기 (검사양식 관리의 [양식 작성]·[수정])

근거: DECISIONS 사용자 결정 2026-10-20·2026-10-21.

섹션 양식을 섹션 단위로 편집한다. 칸 단위 양식은 여기서 고치거나 불러오지 않는다.
위쪽에 이 양식을 매핑한 검사 분류("검사 분류: 대분류 › 중분류", 없으면 매핑 안내)를 보인다(8.8).

**섹션 종류**

| 섹션 | 내용 |
|---|---|
| 참고사진 | 에디터·이미지. 사진은 `/media/dig-form-image/<id>/` 로 받고 디지털 양식 메뉴 `R` 이 있어야 한다. 본문 HTML 은 화면에 넣기 전에 스크립트·이벤트 속성을 지운다. 글자 크기(작게 11px·보통 13px·크게 16px·아주 크게 20px, 인라인 스타일)·굵게·색·목록·들여쓰기·정렬을 쓰고, 작성·조회 화면도 편집기와 같은 서식(들여쓰기·정렬·목록·공백·탭)으로 보인다 |
| 점검항목 | 표 하나. 머리줄 1~3행, 같은 값 병합. 열 종류는 아래 표 |
| 머리글 섹션 | 맨 위 머리글과 같은 편집기로 섹션 사이에 머리글 표를 하나 더 둔다. 입력 항목·입고번호/WO 입력칸은 맨 위 머리글과 통틀어 하나씩, 고쳐도 새 버전이 아니다 |

**머리글**

- 작성일·작성자 칸은 표시 칸이다(입력받지 않는다, 8.6)
- 양식명(제목) 칸은 표시 글자를 따로 적을 수 있다. 비우면 기본정보의 양식명을 보인다. [기존 양식 머리글 불러오기]는 표시 글자도 그대로 가져온다
- [기존 양식 머리글 불러오기](맨 위 머리글·머리글 섹션)와 머리글 섹션 [복사]는 입력 항목을 새 키로 바꾼다 — 같은 양식 머리글을 두 번 불러와도 입력칸이 겹치지 않는다. 입고번호/WO 입력칸은 복사하면 비우고, 불러오기는 다른 머리글에 이미 있을 때만 비운다
- 입력값의 선택지는 서버 항목 목록(`domain/services/dig_form_fields.py`)이다 — 양식정보·WO(수입은 입고번호)·품목·품번·입고번호(품질만)·작성 정보·결재와 **직접 입력**(항목 이름을 받아 자유 입력칸)
- 품목·품번·입고번호는 작성 화면에서 검색해 고르는 선택 상자다(`/api/dig_form/dig_form?action=header_lookup`, 디지털 양식 메뉴 `R`). 품목과 품번은 하나를 고르면 다른 칸도 채운다. 목록에 없는 값은 직접 써 넣고(Enter) 보기·결과에서는 글자로 보인다
- [+ 행]·[+ 열]은 선택한 칸 바로 아래·오른쪽에 넣는다(병합 칸은 병합 범위 다음, 넣는 자리를 지나는 병합은 늘어난다). 선택이 없으면 맨 아래·오른쪽에 붙인다

**점검항목 열 종류**

| 열 | 작성할 때 |
|---|---|
| 글자 | 행마다 고정 글자(작성자는 바꾸지 않는다). 여러 줄로 쓰고(Enter 로 줄바꿈) 줄 앞 들여쓰기도 작성·결과 화면에 그대로 보인다 |
| 입력 | 행마다 문자·숫자 입력. 숫자는 하한·상한으로 같은 행 판정을 자동 계산한다(8.5) |
| 판정 | 판정 코드 그룹 하나의 선택지(8.5) |
| 체크 | 체크 상자 |
| 첨부 이미지 | 행마다 사진 1장을 올리는 칸. 나중에 AI 가 사진을 분석해 같은 행의 값을 채우는 데 쓴다. 비전검사항목을 연결할 수 있다(8.8) |
| 고정 이미지 | 양식에 넣어 두는 그림(행마다 붙는 공정 사진·여러 행에 걸친 확대도). 작성자는 바꾸지 않는다. 칸마다 [이미지 넣기] 팝업에서 붙여넣기(Ctrl+V)·끌어 놓기·[파일 선택]으로 한 장을 골라 [적용](긴 변 1600px 로 줄여 올린다)·[지우기]. 여러 행에 걸친 그림은 아래 칸에서 [위 칸과 병합]([병합 해제]로 푼다 — 바로 위 칸도 고정 이미지일 때만 보인다. 열 설정의 같은 값 병합은 없다). 작성·결과·상세 조회 화면에는 칸 폭에 맞춰 보이고 누르면 크게 본다 |
| 행마다 지정 | 칸마다 종류(글자·입력·판정·체크·첨부 이미지·고정 이미지·비움)를 고르고 판정은 칸마다 선택지. 고정 이미지 칸은 고정 이미지 열과 같다 — 같은 열에 그림을 두고 아래 칸에 설명 글자를 둘 수 있다. 입력·판정·체크·이미지 칸은 앞뒤 글자(`부적합 건수 : {} EA` — `{}` 자리에 입력칸)를 둔다. 새 행은 마지막 행의 종류·선택지·앞뒤 글자를 이어받는다 |

- 섹션마다 켜는 **섹션 첨부 이미지**는 섹션 제목 오른쪽에 사진 1장을 올리는 칸이고, AI 가 그 섹션 표 전체를 채우는 데 쓴다
- 행의 순서 숫자를 바꾸면 표가 그 순서로 다시 놓이고 1부터 다시 매겨진다. 바로 위 행이 바뀌는 고정 이미지 병합 칸이 있으면 "병합된 칸이 있습니다. 순서를 바꾸면 병합이 해제됩니다." 하고 묻고, 바꾸면 그 병합을 풀고 [취소]면 숫자를 되돌린다
- [열 설정]은 모달로 열고 [적용]해야 섹션 표에 남는다([취소]는 연 때로 되돌린다)

**등록·삭제**

- 등록 팝업의 [기존 양식 불러오기]로 다른 섹션 양식의 머리글·섹션을 복사해 새 양식코드로 등록한다(수정 팝업에는 없다)
- 수정 팝업의 [삭제]는 그 버전 하나를 지우고 작성 결과가 있으면 막는다
- 고친 것이 있는데 X 로 닫으면 묻는다

### 8.5 판정 코드 (`wm_dig_form_judge_code`)

근거: DECISIONS DEC-035.

수입·품질이 같이 쓰는 판정 칸 선택지를 **항목결과 코드**(그룹 → 결과 코드)로 관리한다.

- 화면: 그룹 → 결과 코드 트리 한 목록. 목록 머리 [그룹 등록]·[결과 코드 등록]이 등록 모달을 열고, 상세는 [수정]·[삭제]다
- 결과 코드마다 **판정 의미**(합격·불합격·해당없음)와 순서를 둔다. 양식 칸이 쓰는 그룹, 작성 결과가 쓴 결과 코드는 코드값을 바꾸거나 지울 수 없다(이름·의미·순서는 바꾼다)
- 기본 그룹 5개 — OK/NG(`dig_form_okng`)·합격/불합격/N/A(`dig_form_pass_na`)·적합/부적합·사용 가능/불가·입고 완료/미입고 — 는 `seed_initial` 이 넣는다
- 양식 편집기의 판정 열은 이 그룹 중 하나를 고른다(편집기를 열 때 읽는다). 지워진 그룹을 쓰던 열은 "(없는 선택지)"로 보이고 다른 그룹을 골라야 저장된다
- **자동 판정**은 결과 코드가 아니라 판정 의미로 본다 — 같은 행 상·하한 숫자칸으로 합격·불합격을 계산해, 합격·불합격 의미 선택지가 둘 다 있는 판정 칸을 미리 채우고(같은 의미가 여럿이면 순서상 첫 선택지), 고른 의미가 계산과 다르면 경고한다. 해당없음은 경고하지 않는다. 조회의 결과 칩도 의미로 색을 정한다

더 볼 곳: 테이블 구조는 DATA_MODEL §2 "디지털 양식".

### 8.6 검사작성 (`wm_dig_form_incoming_write` / `wm_dig_form_outgoing_write`)

근거: DECISIONS 사용자 결정 2026-10-19·2026-10-20.

**목록**: 위는 조회 카드(양식·입고번호/품목(수입)·WO(품질)·상태(대기·작성 중), [조회]), 아래는 그 구분의 **검사 작업 목록**이다(작업·상태 칸, 행 [작성]·[열기]).
대기(붉게, 행 [작성])가 먼저, 작성 중(행 [열기], 입고·작업지시와 무관한 수기 작성 포함)이 다음이다(8.2). 품질검사는 목록 머리에 [작업지시 등록](준비 중 안내)과 [신규 작성]이 있다.

**작성 모달**(화면 폭 최대)

- 행의 [열기]는 보기 상태로 연다. 오른쪽 위 [수정]으로 입력 상태가 되어 [저장]하고, [수정 취소]는 저장하지 않은 수정을 버리고 보기 상태로 돌아간다
- [신규 작성]은 사용 중인 최신 양식을 골라 같은 모달을 입력 상태로 연다(검사양식 상세의 [검사 작성]도 같다)
- 새 작성의 머리글 입고번호/WO 칸은 모달의 자재입고 검색(수입)·WO 검색(품질)으로 채운다. 머리글에 입고번호/WO 칸이 없는 양식은 모달 위쪽 입력줄에서 넣는다
- 양식 편집기에서 만든 머리글·머리글 섹션의 입력 항목도 입력·저장한다(`result.extra.<키>`, 라벨이 `…일`·`일자`·`날짜` 면 날짜 선택, 그 밖은 글자)
- 저장하지 않은 수정이 있으면 모달을 닫을 때 묻는다

**작성 규칙**

- [저장]은 바뀐 칸만 저장한다. 칸의 작업자는 마지막으로 저장한 사람이다(행 끝 작업자 열은 그 행에서 가장 나중에 저장한 사람)
- [완료]는 빈 칸이 있어도 되고 되돌리지 않는다
- [삭제]는 작성 중인 검사를 작성자만 지운다(버튼도 작성자에게만 보인다)
- 같은 양식 코드·입고번호(WO)의 작성 중인 검사는 하나다(옛 버전으로 작성 중이어도 같다). 완료된 검사만 있으면 새로 써 차수(`Round`)가 오른다
- 작성일은 입력하지 않는다 — 처음 저장한 날로 들어가고 이어 써도 바뀌지 않는다(머리글의 작성일 칸은 표시만, 새 작성은 오늘)
- 머리글의 작성자 칸도 표시만 한다 — 작성건을 마지막으로 저장한(이어쓰기·완료 포함) 사람이고, 입력 중에는 지금 사용자다

**이미지 칸**: 첨부 이미지 칸·섹션 첨부 이미지는 아이콘으로 올리고(`/api/dig_form/dig_form?action=upload_image`, 검사작성 `W`) [저장] 때 칸에 연결한다.
칸에는 아이콘만 있고 누르면 팝업에서 확대해 본다. 사진은 `/media/dig-form-image/<id>/` 로 받는다. 원본 크기 그대로 올린다(최대 30MB, PNG·JPG·GIF).
비전검사항목이 연결된 칸은 8.8.

### 8.7 검사결과 (`wm_dig_form_incoming_result` / `wm_dig_form_outgoing_result`)

그 구분의 **완료된** 검사를 작성일·양식(옛 버전 포함)·입고번호/WO 를 함께(AND) 걸어 [조회]하고, 행의 [조회]로 양식 모양 그대로 **결과 모달**에서 본다.

결과 모달 오른쪽 위 **[PDF 저장]**은 그 결과서를 인쇄창으로 연다 — 대상 "PDF로 저장"을 골라 저장한다(근거: DECISIONS 사용자 결정 2026-10-27).

- 결과 모달 내용(정보줄·양식 머리글·섹션)만 담는다. 목록·조회 카드·메뉴는 들어가지 않는다
- 이미지 칸·섹션 이미지의 사진을 아이콘 대신 사진으로 넣는다(원본, 높이 최대 60mm). 받지 못한 사진은 알린 뒤 빈칸으로 둔다
- 용지 방향은 인쇄창에서 세로·가로를 고른다. 저장 파일명 기본값은 `<양식코드>_Rev<버전>_<입고번호|WO>_<차수>차` 다
- 섹션은 화면의 한 줄씩 묶어 같은 쪽에 두거나 줄째 다음 쪽으로 넘긴다(사진·표가 쪽 경계에서 갈라지지 않는다)
- 가로는 화면 배치 그대로다. 세로는 폭 6 이하 섹션을 6(한 줄에 둘), 7 이상을 12로 넓히고 화면의 줄이 바뀌는 곳에서 새 줄을 시작한다

### 8.8 비전 연결

근거: DECISIONS 사용자 결정 2026-10-19·2026-10-21.

비전검사항목과 양식은 아래 순서로 이어진다.

1. **검사 분류에 양식 매핑** — 중분류(검사 시트)에 그 구분의 섹션 양식 하나를 매핑한다(§3.3)
2. **이미지 칸 연결** — 양식 편집기 이미지 열의 선택 상자로 행마다 비전검사항목을 연결한다(새로 고르는 것은 사용 중인 항목만). 연결을 바꾸면 새 버전이다
    - 이 양식에 매핑된 중분류의 항목이 맨 위 묶음("이 양식 분류 — …")이고, 나머지는 "대분류 › 중분류" 묶음이다
    - 이미지 열이 있는 점검항목 섹션의 [이미지 칸 모두 연결]은 고른 항목을 그 섹션 이미지 칸 전부에 넣는다
    - 비전검사항목이 없는 이미지 칸이 있으면 저장 확인창이 개수를 알린다(막지 않는다 — 비전 대상이 아닌 증빙 사진 칸이 있다)
    - 연결된 칸은 검사양식 상세·검사작성·검사결과에 `비전: <코드>` 로 보인다
3. **사진 넣기**(검사작성) — 연결된 칸의 아이콘을 누르면 "사진 넣기" 팝업이 열린다. [파일 선택](JPG·PNG, 30MB) 또는 카메라 영상에 그 항목의 Overlay(표시 중일 때, 설정 불투명도)를 겹쳐 [촬영] → [다시 찍기]/[사용]
    - 파일을 고르거나 [사용]을 누르는 즉시 그 비전검사항목의 비전 데이터 이미지(라벨링 대기, 등록 경로는 양식 사진 넣기)가 되고(`action=capture`), [저장] 때 칸에 그 이미지 id 가 남는다
    - 칸에서 빼거나 검사를 지워도 데이터 관리의 사진은 남는다. 중지된 항목에는 넣지 않는다
    - 화면 안 카메라(영상 위 Overlay)는 HTTPS·localhost 접속에서만 열린다. HTTP 로 접속하면 [촬영]이 기기 카메라 앱을 연다(`capture` 파일 입력 — 태블릿·휴대폰, 가이드는 카메라 화면에 겹치지 않는다. PC 는 파일 선택)
    - 사진은 `/media/dig-form-asset/<id>/`, Overlay 는 `/media/dig-form-overlay/<칸 id>/` 로 받는다
4. **거치대 결과 불러오기** — 거치대(`RIG`) 비전검사항목 칸에는 [거치대 결과 불러오기]가 더 있다. 그 항목의 최근 30일 검사 결과(이미지가 있는 것, 최신순 50건: 검사 시각·클라이언트·판정·측정값)에서 [선택]하면 그 결과의 이미지가 칸 값이 된다(`action=rig_results`·`use_rig_result`, 썸네일은 없고 넣은 뒤 칸의 사진 보기로 본다). 같은 결과를 여러 칸에 넣어도 된다
    - 치수 측정 항목 칸은 이 버튼만 있다(사진 넣기는 거절)
    - 보기·결과 화면은 거치대 검사 이미지가 든 칸 아래에 판정(치수 측정은 측정점마다 값·범위·합불)을 보인다

### 8.9 아직 없는 것

- 작업지시 데이터(품질검사의 대기·[작업지시 등록]·WO 검색 출처)
- 검사 승인(승인 대기·승인·반려) — 대시보드에도 아직 없다(§10)
- 첨부 이미지의 AI 추론 결과로 같은 행 판정 칸 자동 체크, 불러온 거치대 측정값으로 같은 행 측정값 칸 채우기
- 입고 상태(취소·반납)·검사 결과 ERP 회신

더 볼 곳: 상세와 막는 것은 STATUS §3 우선순위 6 "디지털 입력 전환".

## 9. 기준정보·인터페이스 이력

품목·BOM 조회와 입고 내역은 기준정보 폴더, 인터페이스 이력은 시스템 관리 폴더 맨 위에 있다.

### 9.1 품목·BOM 조회 (`wm_product_bom`)

PLM 인터페이스로 받은 품목·BOM 을 보는 **조회 전용** 화면이다. 품목·BOM 은 `import_interface` → `apply_interface` 로만 들어오므로
등록·수정·삭제가 없다. API 는 `/api/definition/product_bom`(조회 action 만, 메뉴 `wm_product_bom` 의 `R`).

- 검색: 품목코드/품목명(일부), 품목유형(받은 값), **최상위 품목만**(부모 없이 자식이 있는 품목 = 장비). 목록은 코드순, 서버 페이징 50건씩
- 품목을 고르면 아래 탭 세 개를 채운다
    - **상세 정보**: 품번·리비전·버전·규격·자재그룹·재질·후처리·PLM 상태·일자, 3D(유형·번호·버전·상태·마지막수정일)·2D(번호·버전·상태·마지막수정일)
    - **하위 BOM**: 고른 품목에서 아래로 펼친 트리. 수량은 부모 하나에 드는 수, **소요량**은 위쪽 수량을 모두 곱한 수다. [모두 펼치기]·[모두 접기]
    - **사용처**: 고른 품목을 쓰는 상위 품목을 최상위까지 거슬러 올라간 트리. 수량은 그 상위 품목 하나에 드는 수다
- 같은 하위 조립품이 여러 곳에 쓰이면 트리에 쓰인 자리마다 나온다(행 id 는 위치 경로)

### 9.2 인터페이스 이력 (`wm_interface_log`)

외부 인터페이스로 받은 수신건과 그 반영 결과, 받은 원본을 보는 **조회 전용** 화면이다. 받기·반영은 지금 명령(`import_interface`·`apply_interface`)이 한다.
API 는 `/api/definition/interface_log`(조회 action 만, 메뉴 `wm_interface_log` 의 `R`). 받는 경로(파일·API·DB 연동)와 상관없이 같은 화면이다.

- 검색: 종류, 경로, 상태, 수신일(기간), 출처(일부). 목록은 최신순, 서버 페이징 50건씩
- 상태: 수신 실패 · 반영 대기 · 반영 완료 · 반영 실패(실패는 붉게). 반영 규칙이 없는 종류의 반영 대기는 "반영 규칙 없음"으로 보인다(지금 두 종류 모두 규칙이 있다)
- 수신자: 사람이 받지 않은 건은 파일이면 "명령", 그 밖은 경로 이름이다
- 상세 정보 머리 오른쪽에 고른 수신건 종류의 화면 버튼 하나가 보인다 — PLM 품목·BOM 은 [품목·BOM 조회], ERP 구매요청 현황은 [입고 내역]. 누르면 그 메뉴 탭을 열고 그리로 옮긴다. 그 메뉴 권한이 없으면(좌측 메뉴에 없으면) 버튼도 없다
- 수신건을 고르면 탭 두 개를 채운다
    - **요약**: 종류·경로·출처·행수·상태·수신일시·수신자·반영일시, 마지막 반영 건수(예: 품목 추가 248 · BOM 추가 271) 또는 실패 사유
    - **원본 데이터**: 그 수신건의 원본 행을 받은 값 그대로(서버 페이징 100건). 열 이름은 원본 머리글이고 종류마다 바뀐다

### 9.3 입고 내역 (`wm_receipt`)

ERP 구매요청 현황(= 입고의뢰) 한 줄이 입고 한 줄이다. 입고가 수입검사로 이어지는 흐름은 §8.2 다.

- 조회 전용(API `/api/definition/receipt`). 입고일(기간)·입고번호/품목·프로젝트로 찾는다. 입고일 최신순, 서버 페이징 50건씩. 검사 정보(양식·상태·[검사 작성])는 없다
- 이 API 는 수입검사 작성 권한으로도 열린다 — 검사작성의 [자재입고 검색] 팝업이 쓴다(§8.2)

## 10. 대시보드 (`wm_dashboard`)

근거: DECISIONS 사용자 결정 2026-10-21·2026-10-23(할 일·현황, 화면 보완).

로그인 첫 화면이다. 좌측 메뉴 맨 위에 폴더 없이 아이콘과 함께 있다(§1).
할 일(그 메뉴 `W`)과 현황(그 메뉴 `R`)을 나누지 않고 **1행 요약 띠 → 2행 차트 둘 → 3행 대기 목록 둘 → 4행 최근 비전 검사** 순으로 섞어 보인다. 머리 카드(이름·즐겨찾기·설명)는 감춘다. 값은 모두 `/api/vision/dashboard`(`summary`) 하나가
사용자의 메뉴 권한만큼 주고, 권한이 없는 칸은 `null` 이라 화면이 감춘다 — 다른 메뉴의 API 를 부르면 권한 없는 그룹에서 403 이다.
담당자 배정이 없어 대기 건은 전체를 센다.

| 요약 띠 칸(이동 없음) | 권한 | 숫자(할 일은 주황 `--brand-warning-ink`, 실적은 잉크, 0 은 회색) | 아래 구성(이름·값 쌍) |
|---|---|---|---|
| 작업해야 할 검사 | 검사작성 W | 합계 | 수입검사(대기+작성 중 — 수입검사 작성 목록과 같은 수. 좌측 배지는 매핑 안 된 수기 작성을 빼서 다를 수 있다) · 품질검사(작성 중) |
| 이번 달 검사 완료 | 검사결과 R | 합계 | 수입검사 · 품질검사 |
| 작업해야 할 비전 데이터 검사 | 라벨링·검수 W | 합계 | 라벨링(라벨링 대기열과 같은 상태) · 검수(검수 대기 = 제출됨). 치수 측정 항목은 뺀다 |
| 이번 달 비전 데이터 합계 | 비전 데이터 등록 R | 이번 달 등록 합계 | 미처리(라벨링하는 항목의 검수 완료 아닌 것) · 처리(검수 완료). 치수 측정 이미지는 합계에만 든다 |

- 요약 띠의 모양은 DESIGN §5.3 이다. 권한이 없는 칸은 빠지고 남은 칸이 폭을 나눈다
- 2행 차트: **최근 7일 검사 완료 · 부적합**(왼쪽. 수입·품질 누적 막대(결과 메뉴 R 이 있는 구분만)와 부적합 항목 선을 한 차트에 겹친다 — DESIGN §5.9 예외) ·
  **최근 7일 비전 데이터 등록**(오른쪽. 등록 경로별 누적 막대(API `series[].code`), [전체 조회] → 비전 데이터 등록 탭)
- 3행 최근 5행 목록: **대기·작성 중인 검사**(왼쪽. 대기는 입고일, 작성 중은 마지막 저장으로 섞어 최근 순. 행 → 그 검사작성 탭) ·
  **대기·작업 중인 비전 데이터 라벨링**(오른쪽. 라벨링 대기열 이미지 최근 등록 순 — 썸네일·비전검사항목·상태·등록일. 행 → 그 항목 탭의 라벨링 내부 탭에서 그 이미지, 항목 탭 주소의 `screen=<메뉴코드>&image=<id>`)
- 4행 **최근 비전 검사 이력**(5건, 썸네일·검사 시각·비전검사항목·판정·클라이언트. 행 → 비전 검사 이력 탭에서 그 검사 상세, 탭 주소의 `inspection=<id>`)
- 썸네일은 가운데 정렬이고, 파일이 이 서버에 없는 이미지는 서버가 주소를 비워 404 를 내지 않고 "이미지 없음" 아이콘을 보인다
- 완료 시각은 완료 작성건의 마지막 저장 시각이다(완료한 검사는 고칠 수 없다). 부적합 항목은 판정 칸 값의 판정 코드 의미가 `N` 인 칸이다
- 목록 행·패널 머리의 [전체 조회]를 누르면 그 메뉴 탭이 열린다. 좌측 메뉴에 없는 메뉴(권한 없음)는 열지 않는다(행·패널 모양은 DESIGN §5.8)
- 차트는 Chart.js 를 이 화면에서만 싣고 색은 토큰에서 읽는다(DESIGN §5.9)
- 아직 없는 것: 승인 대기(검사 승인)·품질검사 대기(작업지시) — STATUS 6 ①②
