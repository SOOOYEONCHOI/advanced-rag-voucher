# 치수 측정(MEASUREMENT) 비전검사항목 유형 — 설계

> 상태: **승인, 구현 중** (2026-10-20, §9 모두 권장안). 구현이 끝나면 `docs/archive/superpowers/specs/` 로 옮긴다.
> 근거: NEOCON C2 문서 대장 5번 시트 Rotor 수입검사 성적서(을지 외관검사 6 치수, 치수검사 POINT A~L, 일반공차표),
> 사용자 결정 2026-10-20(아래 §1).

## 1. 전제 (사용자 결정 2026-10-20)

| # | 결정 |
|---|---|
| E1 | **치수 계산은 클라이언트(거치대 PC)가 한다.** 서버는 측정점 정의·규격을 내려 주고, 받은 측정값을 저장·판정한다. 치수 유형을 넣을 때 클라이언트에 요청한다 |
| E2 | 촬영 높이는 **Overlay 에 맞추고, 크기를 아는 기준물을 함께 촬영**한다. 클라이언트가 기준물로 사진마다 배율(mm/화소)을 정한다 |
| 장비 | MER2-503-23GM-P(2448×2048, 3.45µm, 흑백) + LA0820A(8mm). 높이 650mm 에서 약 0.28mm/화소, 한 장 범위 약 690×580mm |

이 장비로 되는 것은 **평면 치수 ±0.3~±1mm 급**이다(카세트 540±1, 154±1, Rotor 외경 Φ450 중급 ±0.8). ±0.05mm 급 정밀 치수, 깊이(흠집 0.2·찍힘 0.1),
Seal Gap 0.08±0.03, 동심도·진직도, Belt Tension(Hz)은 이 유형의 대상이 아니다 — 지금처럼 게이지로 재고 디지털 양식 숫자 칸에 넣는다.

## 2. 범위

**이번에 하는 것**
1. 비전검사항목 유형에 **치수 측정** 추가, 항목마다 **측정점**(이름·기준값·상하한·단위) 정의
2. 클라이언트 계약: 카탈로그로 측정점을 내려 주고, 검사 업로드로 측정값을 받아 서버가 판정해 돌려준다
3. 화면: 측정점 관리, 검사 결과/이력에서 측정값 보기
4. 시드: `VIS-ROT-DIM` Rotor 치수(수입) — 5번 시트 치수검사 A·B·C

**이번에 하지 않는 것**(따로 설계)
- 측정값을 디지털 양식 칸(5번 치수검사 A~C)에 자동으로 채우기 — 검사 결과와 입고·작업지시·양식을 잇는 참조번호가 먼저 필요하다
- 치수 측정용 AI 모델(점 찾기). E1 로 계산은 클라이언트 몫이다
- 도면 기반 측정점(Rotor 외경 등) — 도면을 받은 뒤 화면에서 측정점을 더한다

## 3. 데이터

### 3-1. 비전검사항목 유형
`InspectionItem.TaskType` 에 `MEASUREMENT = '치수 측정'` 을 더한다. 클라이언트 유형 이름도 `MEASUREMENT` 다.
치수 측정 항목은 라벨 클래스·모델 매핑을 쓰지 않는다.

### 3-2. 측정점 `vision_data_measurementpoint` (새 테이블, 조직 구분·RLS 적용 — 다른 `vision_data_*` 와 같다)

| 필드 | 형식 | 설명 |
|---|---|---|
| `item` | FK 비전검사항목, CASCADE | 치수 측정 항목만 |
| `code` | 문자 20 | 측정점 코드(예: `A`). 항목 안에서 겹치지 않는다. 클라이언트가 값을 돌려보낼 때 쓴다 |
| `name` | 문자 100 | 표시 이름(예: `카세트 가로`) |
| `nominal` | 소수(18,3) | 기준값 |
| `lower` · `upper` | 소수(18,3) | 하한·상한(합격 범위, 경계 포함). 기준값±공차를 풀어 저장한다(540±1 → 539.000~541.000) |
| `unit` | 문자 10, 기본 `mm` | 단위 |
| `description` | 텍스트 | 측정 방법 안내(어디서 어디까지) — 클라이언트 화면에 보인다 |
| `sort_order` | 정수 | 순서 |

- 제약: `lower <= nominal <= upper`, (`item`, `code`) 유일
- 규격을 바꿔도 지난 검사 기록은 바뀌지 않는다(3-3 에 그때 규격을 함께 남긴다)

### 3-3. 검사 기록 `vision_inspection.measurements` (JSON, 새 컬럼)
```json
[{"code": "A", "name": "카세트 가로", "value": 540.32, "lower": 539.0, "upper": 541.0, "unit": "mm", "ok": true}]
```
- 그때의 규격을 함께 남긴다. 치수 측정이 아니면 `null`
- 배율 정보는 `metadata.calibration`(아래)을 그대로 `vision_inspection.calibration`(JSON, 새 컬럼)에 남긴다 — 나중에 "어떤 배율로 쟀나"를 되짚는다

## 4. 서버 동작

1. **카탈로그**: `?include=measurement` 를 준 클라이언트에만 치수 측정 항목을 내보낸다(분류의 `include=classification` 과 같은 방식, DEC-031).
   두 값을 같이 줄 수 있다(`include=classification,measurement`). 치수 측정 항목에는 `measurement_points` 를 붙인다
2. **검사 접수**: 치수 측정 항목이면 `metadata.measurements` 가 필수다
   - 항목의 측정점 **전부**가 한 번씩 있어야 한다. 빠지거나·모르는 코드·같은 코드 두 번·숫자가 아닌 값(NaN·무한대 포함)은 **422 `MEASUREMENT_INVALID`**, 이미지를 저장하기 전에 거절한다
   - 치수 측정이 아닌 항목에 `measurements` 를 보내면 무시한다
3. **판정**: 측정점마다 `lower <= value <= upper` 면 `ok`. 하나라도 벗어나면 `abnormal: true`. Wezard 추론을 부르지 않고 접수 즉시 `SUCCESS` 다(`model`·`inference_ms` 는 `null`)
4. **이미지**: 지금처럼 데이터 관리에 저장한다(증빙). 치수 측정 항목은 라벨링 대기열·검수·스냅샷·Export·Wezard 데이터셋 API 에서 뺀다.
   이미지 상태(라벨링 대기)는 그대로 두고 **항목 유형으로 막는다** — 라벨링·검수·스냅샷 API(`/api/item/labeling`·`review`·`snapshot`)는
   치수 측정 항목이면 거절하고, Wezard 데이터셋 API 의 `task_type` 필터는 `MEASUREMENT` 를 받지 않는다(스냅샷이 생기지 않으므로 목록에도 없다)
6. **디지털 양식 비전 연결**: 치수 측정 항목은 양식 편집기의 이미지 칸 연결 목록에서 빼고, 사진 넣기(`capture`)도 거절한다 —
   측정값은 고정 거치대 클라이언트만 낸다(E1). 태블릿 사진만 들어가면 측정값 없는 이미지가 쌓인다
5. 멱등성·인증·이미지 검사·오류 순서는 지금과 같다

## 5. 클라이언트 계약 변경 (초안 — `SERVER_API_CONTRACT.md` 에 반영해 전달)

### 5-1. 카탈로그 `GET /api/v1/catalog?include=measurement`
```json
{"id": 1701, "code": "VIS-ROT-DIM", "name": "Rotor 치수(수입)", "inspection_type": "MEASUREMENT",
 "overlay": {"available": true, "version": 1},
 "measurement_points": [
   {"code": "A", "name": "카세트 가로", "nominal": 540.0, "lower": 539.0, "upper": 541.0, "unit": "mm", "description": "…"},
   {"code": "B", "name": "카세트 세로", "nominal": 540.0, "lower": 539.0, "upper": 541.0, "unit": "mm", "description": "…"},
   {"code": "C", "name": "카세트 두께", "nominal": 154.0, "lower": 153.0, "upper": 155.0, "unit": "mm", "description": "…"}]}
```
- `measurement_points` 는 치수 측정 항목에만 있다(다른 유형은 **키가 없다**). 카탈로그 `version` 은 측정점이 바뀌어도 달라진다
- `catalog/version` 에도 같은 `include` 를 준다

### 5-2. 검사 업로드 `metadata` 에 더하는 필드
| 필드 | 필수 | 형식 |
|---|---|---|
| `measurements` | 치수 측정 항목이면 **예** | `[{"code": "A", "value": 540.32}, …]` — 측정점마다 하나, `value` 는 숫자(mm 등 측정점 단위) |
| `calibration` | 아니오(보내기를 권한다) | `{"method": "REFERENCE", "mm_per_px": 0.2831, "reference": "CAL-100"}` — 기준물로 정한 배율. 객체가 아니면 422 `METADATA_INVALID`. 문자열은 각 50자까지 |

### 5-3. 응답에 더하는 필드
| 필드 | 형식 |
|---|---|
| `measurements` | 치수 측정이면 `[{"code", "name", "value", "lower", "upper", "unit", "ok"}]`, 아니면 `null`(키는 있다 — `classification` 과 같다) |

- 판정 규칙 표(§6-3)에 `MEASUREMENT: 측정점 하나라도 ok 가 false` 를 더한다
- 오류 표(§6-6·§11)에 `422 MEASUREMENT_INVALID`(재시도 안 함)를 더한다
- 서버 버전 `1.0.0` → `1.1.0`

### 5-4. 클라이언트에 요청할 일 (E1)
1. 카탈로그에 `include=measurement` 를 주고 `MEASUREMENT` 유형을 받는다(모르는 유형에서 깨지지 않게 — 0.1.6 이 겪은 문제)
2. 측정점마다 **측정 방법(어디서 어디까지 재는지)을 클라이언트 쪽에서 설정**하고, 기준물로 배율을 구해 mm 값을 낸다
3. 측정값을 `metadata.measurements`, 배율을 `metadata.calibration` 으로 보낸다
4. 결과 화면에 측정점별 값·범위·합불을 보인다. 판정 표시는 지금처럼 `abnormal` 하나로 한다
5. 이 카메라(Daheng MER2-503-23GM-P, GigE PoE) 지원과 현장 해상도(2448×2048)를 확인해 알려 준다 — 열린 요청 R19 §4-4(Overlay 화면비)도 이것으로 끝난다

## 6. 화면

| 화면 | 바뀌는 것 |
|---|---|
| 비전검사항목 관리 | 등록 창의 작업 유형에 "치수 측정" |
| 비전검사항목 홈 | 치수 측정 항목이면 라벨 클래스 대신 **측정점** 목록(등록·수정·삭제 — 코드·이름·기준값·하한·상한·단위·설명). 측정 결과가 있는 측정점은 코드를 바꾸거나 지울 수 없다 |
| 비전검사항목 모델 매핑 | 치수 측정 항목은 목록에서 뺀다 |
| 검사 결과/이력 | 치수 측정 결과는 측정점 표(코드·이름·값·범위·합불)를 보인다. 벗어난 측정점은 불합격 색 |
| 데이터 관리(라벨링·검수·스냅샷) | 치수 측정 항목은 메뉴를 감춘다(데이터 목록·홈은 그대로). 홈의 요약 카드는 전체 이미지만 보인다 |
| 양식 편집기(이미지 칸 비전 연결) | 치수 측정 항목은 고를 수 없다 |

## 7. 시드 — `seed_vision_items` 에 더함

`VIS-ROT-DIM` Rotor 치수(수입), 치수 측정. 설명에 촬영 조건(고정 거치대, 높이 약 650mm, 기준물 함께 촬영)과 근거(5번 시트 을지 치수검사 A·B·C)를 적는다.

| 코드 | 이름 | 기준값 | 하한 | 상한 | 근거 |
|---|---|---|---|---|---|
| A | 치수 A | 540 | 539 | 541 | 치수검사 POINT A `540±1(mm)` |
| B | 치수 B | 540 | 539 | 541 | POINT B `540±1 (mm)` |
| C | 치수 C | 154 | 153 | 155 | POINT C `154±1 (mm)` |

측정점 이름(무엇의 길이인지)은 문서에 없어 `치수 A` 로 둔다 — 도면을 받으면 화면에서 고친다.
POINT D~G(Belt Tension Hz), H~K(Seal Gap)는 비전 대상이 아니라 넣지 않는다.

## 9. 정할 것 — 모두 권장안으로 결정(사용자 결정 2026-10-20)

| # | 질문 | 결정 |
|---|---|---|
| Q1 | 측정점 일부만 잰 검사를 받을 것인가 | **받지 않는다(422).** 빠진 점이 있으면 판정이 무의미하다 |
| Q2 | 측정 사진을 데이터 관리에 남길 것인가 | **남기되 라벨링·스냅샷·Export 에서 뺀다.** 증빙과 나중의 AI 측정 학습에 쓴다 |
| Q3 | `calibration` 을 필수로 할 것인가 | **선택**(보내기를 권한다). 기준물 방식이 클라이언트에서 정해진 뒤 필수로 올릴 수 있다 |
| Q4 | 측정점 이름 `치수 A/B/C` 를 그대로 둘 것인가 | 도면 확인 전까지 그대로 |
| Q5 | 디지털 양식 이미지 칸에 치수 측정 항목을 연결할 수 있게 할 것인가 | **연결하지 못한다**(§4-6) |
