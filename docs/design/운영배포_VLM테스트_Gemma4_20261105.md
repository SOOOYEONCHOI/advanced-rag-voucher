# VLM 테스트 모델 Gemma4-12B-it 추가 배포 (GPU 서버 yest-gpu, 2026-11-05)

> 흐름도·도면 이미지 인식 비교 테스트용. 운영 서비스(LLM·임베딩·리랭커·ASR·docling)는 건드리지 않는다.
> 기본 절차·계정·권한은 `운영배포_가이드_서버별_v1.1.md` §1을 따른다. 이 문서는 추가분만 적는다.

## 0. 배치

| GPU | 서비스 | systemd | 포트 | `--gpu-memory-utilization` | 모델(`--served-model-name`) |
|---|---|---|---|---|---|
| 1 | VLM 테스트 | `vllm@vlm` | 8110 | 0.45 (약 36GB) | `gemma-4-12B-it` (max-model-len 16384) |

- GPU 1 비율 합계: 임베딩 0.18 + 리랭커 0.05 + ASR 0.15 + VLM 0.45 = **0.83** (기준 0.9 이하). 11-05 측정 사용량 24.4GB + 36GB ≈ 60GB / 80GB.
- GPU 0은 LLM 0.70 + docling으로 여유가 약 8GB라 올리지 않는다.
- 8109는 TTS 자리(V-6)라 8110을 쓴다. **TTS를 GPU 1에 올리면 합계가 1.07로 넘는다** → 그 전에 `run-vlm.sh`의 `CUDA_VISIBLE_DEVICES`를 2로 바꿔 옮기거나 멈춘다(GPU 2는 할당 승인 후).
- 테스트용이라 `enable`(부팅 시 자동 시작)하지 않는다.

## 1. 추가·변경 파일

| 로컬 파일 | 서버 경로 | 소유자·권한 |
|---|---|---|
| `deploy/gpu/opt/yest/chatbot/vllm/app/run-vlm.sh` (새 파일) | `/opt/yest/chatbot/vllm/app/run-vlm.sh` | `vllm-admin 750` |
| `deploy/gpu/opt/yest/chatbot/vllm/app/check-vlm.sh` (새 파일) | `/opt/yest/chatbot/vllm/app/check-vlm.sh` | `vllm-admin 750` |
| `deploy/gpu/opt/yest/chatbot/vllm/app/env.sh` (`VLM_API_KEY` 한 줄 추가) | 서버 `env.sh`에 **그 줄만 추가** | `vllm-admin 600` |
| `deploy/gpu/tools/download_gemma4_model.sh` (새 파일, 개발 PC용) | – | – |
| 모델 폴더 `gemma-4-12B-it/` (+ `SHA256SUMS`) | `/mnt/a/chatbot/models/gen/gemma-4-12B-it/` | `vllm-admin`, 폴더 750 · 파일 640 |

`vllm@.service`(템플릿)와 `logrotate.d/vllm`(`*.log`)은 그대로 쓴다. 바꿀 것 없음.

## 2. 개발 PC(WSL)에서 준비

```bash
# 저장소 루트
pip install -U "huggingface_hub[cli]"
hf auth login                                        # Gemma 사용 동의한 계정
bash deploy/gpu/tools/download_gemma4_model.sh       # → deploy/gpu/mnt/a/chatbot/offline/vllm/models/gen/gemma-4-12B-it/
# 개발 서버의 모델을 쓰려면: SRC=<복사해 온 폴더> bash deploy/gpu/tools/download_gemma4_model.sh
```

WinSCP(남부권 SSL VPN, **바이너리 모드**)로 올린다.

| 왼쪽(로컬) | 오른쪽(서버) |
|---|---|
| `deploy\gpu\mnt\a\chatbot\offline\vllm\models\gen\gemma-4-12B-it\` | `/mnt/a/chatbot/offline/vllm/models/gen/gemma-4-12B-it/` |
| `deploy\gpu\opt\yest\chatbot\vllm\app\run-vlm.sh`, `check-vlm.sh` | `/mnt/a/chatbot/offline/gpu-config/opt/yest/chatbot/vllm/app/` |

`env.sh`는 올리지 않는다(서버 파일을 덮지 않고 한 줄만 추가한다, 3.2).

## 3. 서버(yest-gpu, sychoi)에서 설치

### 3.1 모델 배치

```bash
O=/mnt/a/chatbot/offline/vllm/models/gen/gemma-4-12B-it
(cd $O && sha256sum -c SHA256SUMS | grep -v ': OK$')          # 아무것도 안 나오면 정상
df -h /mnt/a                                                   # 약 30GB 여유 확인
sudo mv $O /mnt/a/chatbot/models/gen/
M=/mnt/a/chatbot/models/gen/gemma-4-12B-it
sudo chown -R vllm-admin:vllm-admin $M
sudo find $M -type d -exec chmod 750 {} \; ; sudo find $M -type f -exec chmod 640 {} \;
(cd $M && sudo -u vllm-admin sha256sum -c SHA256SUMS | grep -v ': OK$')
```

### 3.2 실행 파일·키

```bash
A=/mnt/a/chatbot/offline/gpu-config/opt/yest/chatbot/vllm/app
sudo install -o vllm-admin -g vllm-admin -m 750 $A/run-vlm.sh $A/check-vlm.sh /opt/yest/chatbot/vllm/app/
sudo sed -i 's/\r$//' /opt/yest/chatbot/vllm/app/run-vlm.sh /opt/yest/chatbot/vllm/app/check-vlm.sh

sudo -iu vllm-admin
grep -q '^export VLM_API_KEY=' /opt/yest/chatbot/vllm/app/env.sh || vi /opt/yest/chatbot/vllm/app/env.sh
#   맨 아래에 로컬 deploy/gpu/.../env.sh 의 "export VLM_API_KEY=..." 줄을 그대로 붙여 넣는다
grep -c '^export VLM_API_KEY=' /opt/yest/chatbot/vllm/app/env.sh   # 1
exit
```

### 3.3 실행

```bash
nvidia-smi --query-gpu=index,memory.used,memory.total --format=csv   # 실행 전 GPU 1 사용량 기록 (약 24GB)
sudo systemctl start vllm@vlm                                         # enable 하지 않는다(테스트용)
sudo tail -f /mnt/a/chatbot/vllm/logs/vlm.log                         # "Uvicorn running on http://0.0.0.0:8110" 까지 (수 분) → Ctrl+C
systemctl status vllm@vlm --no-pager
nvidia-smi                                                            # GPU 1 약 36GB 증가, GPU 0 변화 없음, 2~7 0MiB
```

기동 실패 시 `sudo tail -n 100 /mnt/a/chatbot/vllm/logs/vlm-error.log`.

| 증상 | 조치 |
|---|---|
| `No available memory for the cache blocks` / KV 캐시 부족 | `run-vlm.sh`에서 `--max-model-len` 8192로 낮추기(비율은 올리지 않는다) |
| `Free memory on device ... is less than desired` | GPU 1 다른 서비스가 예상보다 많이 쓰는 중 — `nvidia-smi` 확인 후 보고 |
| 모델 구조를 모른다(`not supported`) | vLLM 0.30.0 지원 여부 확인 필요 — 보고 |

### 3.4 확인

```bash
sudo -u vllm-admin bash /opt/yest/chatbot/vllm/app/check-vlm.sh
# 1. 모델 목록에 gemma-4-12B-it   2. 401   3. 한국어 한 문장   4. START → END 설명 + 응답 시간
for p in 8101 8102 8103 8107; do curl -s -o /dev/null -w "$p %{http_code}\n" http://127.0.0.1:$p/v1/models; done   # 기존 서비스 401(살아 있음)
```

도면 테스트(`adrag_backend/tests/test_qwen_vl_image.py`)는 개발 PC 또는 WAS에서 `--base-url http://<GPU_IP>:8110/v1 --model gemma-4-12B-it --api-key <VLM_API_KEY>`로 실행한다. **GPU 서버 밖에서 부르려면** ACG F-4 인바운드에 TCP 8110을 추가해야 한다(GPU 서버 안에서만 시험하면 필요 없음).

## 4. 운영·되돌리기

| 할 일 | 명령 |
|---|---|
| 멈춤 | `sudo systemctl stop vllm@vlm` (GPU 1 메모리 즉시 반환) |
| 재시작(인자 변경 후) | 저장소 `run-vlm.sh` 수정 → 다시 올려 3.2 `install` → `sudo systemctl restart vllm@vlm` |
| GPU 2로 옮기기(승인 후) | `run-vlm.sh`의 `CUDA_VISIBLE_DEVICES=2`, 비율은 0.85까지 가능 → restart |
| 완전히 제거 | `sudo systemctl stop vllm@vlm` → `sudo rm /opt/yest/chatbot/vllm/app/run-vlm.sh /opt/yest/chatbot/vllm/app/check-vlm.sh` → env.sh의 `VLM_API_KEY` 줄 삭제 → (필요 시) `sudo rm -rf /mnt/a/chatbot/models/gen/gemma-4-12B-it` |

다른 서비스 설정·`vllm@.service`는 바꾸지 않았으므로 위 단계만으로 원래 상태가 된다.
