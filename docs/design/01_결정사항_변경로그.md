## D-01 개정본 등록 — 관리자 지정 방식

**결정**
- **개정본은 문서 목록 행의 [최신본 변경]에서 올린다**(문서 관리 목업 10/12, 기존 AdminView 방식). 대화상자에서 새 파일을 고르고 [업로드 및 최신본 변경]을 누르면 그 문서의 다음 버전으로 처리한다. 상단 업로드 카드는 **새 문서 전용**이다.
  - (2026-10-15 수정: 처음 안의 "업로드 화면에서 [새 문서]/[개정본] 선택" 대신 목업 방식을 따른다.)
- 서버는 파일명·`doc_key`로 같은 문서를 추측하지 않는다. `revision_candidate` 응답과 [개정본으로 등록]/[새 문서로 등록] 선택 창은 만들지 않는다.
- 상단 업로드 카드로 올린 파일은 내용이 비슷해도 항상 **새 문서**로 등록한다.
- 그대로 유지: 같은 파일 해시면 `409 DUPLICATE_FILE`, 처리 중에는 기존본으로 답변, 모든 단계 완료 후 한 트랜잭션으로 최신본 전환, 이전 버전 보관(복원 기능은 2차), 같은 문서 직렬화(`pg_advisory_xact_lock`), 개정 차수 역행 시 경고.
- `doc_key`는 계속 저장한다(표시·검색 보조용). 다만 개정 판단에는 쓰지 않는다.

**API**
- 새 문서: `POST /api/admin/documents/uploads`(대화 주제=`model_id`(D-15), 문서 유형, 파서, `process_nm` 선택). 개정본: `POST /api/admin/documents/{doc_id}/versions`(파일) — 기존 AdminView에 같은 기능의 API가 있으면 그것을 확장한다(Phase 0에서 확인).
- 대상 문서가 없거나 권한이 없으면 `404`, 대상 문서에 처리 중 작업이 있으면 `409 JOB_IN_PROGRESS`.
- `confirm_upload` 2단계 호출은 없앤다(한 번에 job 생성).

**테스트**: 같은 내용의 `_1` 파일을 문서 행의 [최신본 변경]으로 올리면 같은 문서의 다음 버전, 상단 업로드 카드로 올리면 별개 문서가 된다. 자동 감지 결과로 버전이 붙는 경우 0건.

## D-02 등록 결과 리포트 화면 삭제

**결정**
- UI-13(등록 결과 리포트), UI-14(문서·개정본 관리), UI-18(인식 설정)은 만들지 않는다.
- UI-12 **문서 상세**(드로어 또는 하위 페이지)에 다음을 넣는다: 시트별 인식 결과(시트 유형·단계 수·사진 수), 경고 목록, 개정본이면 변경 시트 목록, 원본·변환 결과(md) 보기, **시트 유형 보정 후 재처리**, 버전 이력, 경고로 멈춘 버전의 [최신본으로 전환] 버튼.
- API-09는 이름을 **"문서 처리 결과 API"**로 바꾼다(`GET /api/admin/documents/{doc_id}/versions/{version_no}/result`). `ingest/report.py`는 결과 집계 모듈로 유지해도 된다.

## D-03 용어·동의어 사전 — 관리자 등록·즉시 반영

**결정**
- UI-19에서 표준 용어·동의어·약어(·발음)를 등록·수정·삭제한다. 엑셀(xlsx/csv) 일괄 등록을 지원한다(고객 현장 약어 목록).
- 저장하면 **재처리·재시작 없이 즉시** 검색 정규화(`query.normalize`)와 STT 보정에 반영한다(정규화 캐시 무효화 또는 버전 키 증가).
- 용어마다 `use_search_yn`(검색 적용), `use_stt_yn`(음성 인식 적용)을 둔다(설계서 v0.2 4.9 유지).
- 같은 표준 용어가 이미 있으면 새 용어를 만들지 않고 동의어로 병합하도록 안내한다.
- **만들지 않는 것**: 문서·질의 로그에서 후보 자동 추출, 승인 대기 후보 목록(목업의 "승인 대기 후보" 패널은 2차 기능). 초기 데이터 seed(`data/seed/`)는 사람이 만든 목록으로 넣는다.

**테스트**: "리액트 팬" 동의어를 화면에서 추가한 직후, 재시작 없이 "리액트 팬 조립 순서" 질의가 REACT FAN 문서를 찾고, STT 결과에 보정 표시가 나온다.

## D-04 문서 접근 권한 — 사용자별(모델·문서 단위)

**결정**
- 역할은 그대로 `ADMIN`·`WORKER`. ADMIN은 모든 문서를 본다.
- WORKER는 **허용받은 모델 또는 문서만** 검색·답변·출처·이미지·원본 다운로드에서 볼 수 있다.
- "모델" = 문서 그룹(예: NEOCON C2). **기본안은 기존 대화 주제(collection)를 그대로 문서 그룹으로 쓰는 것**(D-15). 이 경우 `tb_doc_model`을 새로 만들지 않고 기존 대화 주제 테이블을 참조한다.

**데이터 (마이그레이션으로 추가, 테이블 정의서 표기 규칙 따름)**
- 문서 그룹: 기존 대화 주제(collection) 테이블을 그대로 쓴다(D-15). 다른 단위로 확정되면 그때 `tb_doc_model` 추가
- `tb_user_doc_access(user_id, scope_cd: 'TOPIC'|'DOC', scope_id, granted_by, granted_at)` — PK `(user_id, scope_cd, scope_id)`
- Qdrant payload `acl`: `['topic:{collection_id}', 'doc:{doc_id}']` (청크·이미지 포인트 모두)

**규칙**
- `allowed_acl(user)` 한 함수가 사용자 허용 키 목록을 돌려주고, 검색 필터(`acl` any-match)·이미지 API·원본 다운로드·출처 조회가 모두 이 함수를 쓴다(설계서 v0.2 5.2의 "같은 함수" 원칙 유지).
- 사용자 권한을 바꿀 때는 재색인하지 않는다(필터 키만 바뀜). 문서의 대화 주제를 바꿀 때만 해당 문서 포인트 `set_payload`.
- 권한 없는 리소스는 `404`(존재 숨김). 권한이 없어 근거가 0건이면 일반 "찾지 못했습니다"와 같은 응답(권한 문서 존재를 암시하지 않음).
- 2차: 부서 단위(`scope_cd='DEPT'`) 추가 — 1차에서 스키마가 이를 막지 않게만 한다.

**테스트**: 대화 주제 A 권한만 가진 작업자가 주제 B 문서 내용으로 질문 → 근거 0건 응답, 주제 B 이미지 ID 직접 호출 → 404, 작업자 화면 대화 주제 목록에 B 없음. 권한 추가 직후 재색인 없이 검색됨.

## D-05 TTS 기본 기능 1차 적용

- `FEATURE_TTS` 기본값 `true`(설정으로 끌 수 있음). 모델: Qwen3-TTS(오픈소스, GPU 서버 자체 서빙, `TTS_API_URL`).
- 답변 화면(UI-03)에 [음성 답변] 버튼. **누를 때만** 합성·재생, 자동 재생 없음, 정지·다시 듣기.
- API-12 `POST /api/voice/speech` `{message_id}` → 오디오 스트림(또는 파일). 권한 확인 후 해당 답변 텍스트만 합성. 합성 결과는 캐시해도 되지만 원문 외 데이터를 담지 않는다.
- 1차 텍스트 처리: 마크다운·인용 번호·이미지 태그 제거, 너무 길면 앞부분 N자(설정 `TTS_MAX_CHARS`)까지만. **음성용 요약, 품번·규격 읽기 규칙(M4X10 등), 안전 항목 우선 읽기는 2차**(MOD-11).
- 실패·지연 시 텍스트 답변은 그대로 두고 "다시 시도" 안내.

## D-06 DXF 도면 기본 처리 모듈 (시범)

- 기준: DXF 기술검토 v0.1의 `dxf_ingest` PoC. 운영 코드는 **ezdxf**로 읽기 계층을 교체한다(교체 지점 `dxfreader.load()`).
- 1차 범위: 형식 판별·인코딩(G-1), 문자 정규화(G-2), 블록 전개(G-3), 표제란(G-4), BOM·개정이력 표(G-5), 주기(G-9), 렌더·크롭(G-13) → 청크(`drawing_overview`, `drawing_notes`, `drawing_bom`, `drawing_bom_item`, `drawing_revision`) → 같은 적재 파이프라인으로 색인.
- 치수·공차(G-6~8)는 추출만 되면 청크에 넣되 정확도 완료 기준에서 제외. 치수↔형상 연결(G-14), 엑셀 품번↔BOM 자동 연결, DWG 변환은 **2차**.
- 설정 `DRAWING_PARSE_MODE=off|backend`(기본 `off`), 확인용 md `{MD_SAVE_DIR}/drawing/{doc_key}/{job_id}/`, 키워드 사전 `drawing_keywords.yaml`.
- 개정은 D-01과 같은 관리자 지정 방식(도번 자동 판단으로 버전을 붙이지 않음).
- 완료 기준: 합성 샘플 2종 PoC 결과 재현 + 테스트 17개 통과. 실제 도면(협의 #3)을 받으면 표제란 필수 3필드(도번·품명·개정) 100%, BOM 행 누락 0을 별도 보고.

## D-15 권한 "모델" 단위 = 대화 주제 (기본안, 확인 필요)

- 챗봇 목업의 대화 주제가 "NEOCON C2 제조관리", "안전 규정"처럼 모델·업무 단위로 나뉘어 있어, 이것을 권한의 "모델" 단위로 쓰면 새 개념 없이 D-04를 구현할 수 있다.
- `tb_user_doc_access.scope_cd`는 `'TOPIC'|'DOC'`(모델 = 대화 주제). Qdrant payload `acl`은 `['topic:{collection_id}', 'doc:{doc_id}']`.
- 작업자 화면의 대화 주제 목록에는 **권한이 있는 주제만** 보인다.
- 고객 확인 전까지 이 기본안으로 개발하고, 다른 단위로 바뀌면 `scope_cd` 값만 추가한다.

## D-20 엑셀 사진 전부 자동 연결, 검수 화면 1차 제외 (2026-10-22)

- 배경: 고객은 검색된 청크와 관련된 사진이 **자동으로** 답변에 나오기를 원한다. 10-22 dev 점검(C2 샘플)에서 사진 53장이 어떤 답변에도 나올 수 없었고, 재생 Heater 시트 Step 0 청크에 Step 1 사진이 연결돼 있었다(Step 0 중복 + 같은 그림 교차 연결).
- 규칙(`app/ingest/excel_images.py` `link_excel_images`, 설정 `EXCEL_IMAGE_LINK_ALL`, 기본 true): 장식·양식 머리글을 뺀 **모든 사진**을 청크에 연결한다.
  1. 파서가 Step을 정한 사진 → 같은 Step 번호 청크(Step 번호가 겹치면 사진 시작 행이 드는 청크)
  2. 사진 행 범위와 겹치는 청크 전부
  3. 같은 시트에서 행 거리가 가장 가까운 청크(같으면 위쪽). 거리 제한 없음
  4. 위치가 있는 글자 청크가 없는 시트 → excel_ingest 이미지 청크(위치 설명)를 적재하고 연결
  - 청크 위치: Step·공정단계 = Step 행 범위, 표 = 행 범위, 안내문 = 도형 범위, 개요 = 머리 정보 행. 체크박스·흐름도 청크는 위치가 없어 대상이 아니다.
- 장식·양식 머리글(`decoration`·`form_header`)은 연결하지 않는다(답변에도 원래 나오지 않음).

- 이미 적재한 문서는 바뀌지 않는다. 반영하려면 삭제 후 다시 등록한다(재연결 스크립트는 만들지 않음).
