## 3. 시험 데이터 파일

평가 > 데이터셋 > 다운로드 칸의 **시험 데이터셋** 버튼(`GET /api/eval/datasets/{id}/test-set.xlsx`)으로 받은 xlsx를 그대로 쓴다.

| 시트 | 쓰는 열 | 비고 |
|---|---|---|
| `질의` | `질의ID`, `질의문`, `법령`(합본), `컬렉션`(선택) | 질의ID 중복·빈 칸이면 시작 전에 중단 |
| `정답 근거` | `질의ID`, `청크ID` | 청크ID = Qdrant 포인트 ID(검색 결과 ID와 같은 값). 한 질의에 여러 행·한 칸에 여러 ID(쉼표·줄바꿈) 가능 → 합집합이 정답 |

질의별 검색 컬렉션은 `질의` 시트 `컬렉션` 열 → `--collection-map`(법령=컬렉션) → `--collection` 순으로 정한다.
합본 120문항은 `--collection-map "산업안전보건법=AIE_산업안전보건법,중대재해처벌법=AIE_중대재해처벌법"`.

## 4. 실행 방법

```bash
# 시험 1·2 — 백엔드 컨테이너에서 (컨테이너 이름은 환경에 맞게, 시험 파일은 docker cp로 넣는다)
docker cp 시험데이터셋_120.xlsx <백엔드 컨테이너>:/tmp/aiplus/
docker exec -w /app <백엔드 컨테이너> python scripts/aiplus_test1_recall10.py \
    --file /tmp/aiplus/시험데이터셋_120.xlsx \
    --collection-map "산업안전보건법=AIE_산업안전보건법,중대재해처벌법=AIE_중대재해처벌법" --out /tmp/aiplus/result
docker exec -w /app <백엔드 컨테이너> python scripts/aiplus_test2_ndcg5.py   (인자 동일)

# 시험 4 — 시험 PC에서 (aiplus_test4_latency.py, aiplus_common.py 두 파일을 같은 폴더에 둔다)
pip install httpx openpyxl
set AIPLUS_USER_ID=<시험 전용 계정>      # 계정은 환경변수로만. 명령 인자·결과 파일에 남지 않음
set AIPLUS_PASSWORD=<비밀번호>
python aiplus_test4_latency.py --base-url <We.RAG 주소> --file 시험데이터셋_120.xlsx \
    --collection-map "산업안전보건법=AIE_산업안전보건법,중대재해처벌법=AIE_중대재해처벌법" \
    --warmup-query "안전보건관리책임자의 업무는 무엇인가요" --out ./aiplus_result
```

| 옵션 | 뜻 |
|---|---|
| `--verbose` (시험 1·2) | 꺼 둔 노드 로그를 함께 출력 |
| `--warmup-query` (시험 4) | 시험 데이터가 **아닌** 질의를 먼저 보내고 평균에서 뺀다(여러 번 지정 가능). 시험 질의로 워밍업하지 않는다 |
| `--timeout` (시험 4) | 질의 1건 제한 시간(초, 기본 120). 넘으면 오류로 기록하고 걸린 시간을 평균에 포함 |

출력 파일(`--out`):

| 파일 | 열 |
|---|---|
| `test1_recall10_items.csv` | 질의ID, 법령, 컬렉션, 질의문, 상태, 정답포함(1/0), 정답 첫 순위, 정답 청크ID, 검색 상위10(순위. 청크ID \| 문서 > 조항), 검색시간(ms), 오류 |
| `test2_ndcg5_items.csv` | 질의ID, 법령, 컬렉션, 질의문, 상태, NDCG@5, 정답 순위, 정답 청크ID, 재랭킹 상위5(순위. 청크ID \| 점수 \| 정답 \| 문서 > 조항), 검색시간, 재랭킹시간, 오류 |
| `test4_latency_items.csv` | 질의ID, 법령, 컬렉션, 질의문, 상태, 첫 토큰 응답 시간(ms), 최종 답변 완료 시간(ms), 답변 글자 수, 인용 수, 생성 답변, 오류 |
| `test*_summary.json` | 전체 값, 법령별 참고 값, 오류 건수, 사용 모델·설정, 시작·종료 시각, 목표 만족 여부 |

## 7. 시연 순서

### 7.1 원칙
- 합의서의 시험 절차 순서(① 평가 데이터 확인 → ② 소스 코드 확인 → ③ 시험 PC에서 스크립트 실행)를 그대로 따른다.

3. 시험 1·2 실행 방식 합의: 시험 PC에서 백엔드 컨테이너에 접속해 실행(`docker exec`)하는지 확인. 시험 PC에서 직접 돌리려면 백엔드 패키지·.env·Qdrant/임베딩/Reranker 서버 접근이 필요하다.
4. 시험 4 계정: **시험 전용 계정**을 만들어 쓴다(시험 질의가 일반 사용 통계에 섞이므로 통계에서 그 계정을 빼고 본다). 대상 컬렉션 2개에 권한 부여.
5. 시험 4 판정 기준: 합의서 문구는 "최종 답변 생성 완료 시점까지"다. 첫 토큰 기준으로 판정하려면 합의서 문구를 그렇게 고쳐 합의해야 한다(스크립트는 두 값을 모두 낸다).
6. 시험 4 측정 중에는 다른 사용자 질의·평가 실행·시험 1·2 스크립트를 동시에 돌리지 않는다(같은 GPU 서버를 써서 시간이 늘어난다).

## 11. 마이그레이션·되돌리기

- 마이그레이션 없음. 기존 코드·설정·화면 변경 없음.
- 되돌리기: 위 2장의 새 파일 6개를 지우면 끝.

## 12. 남은 이슈

1. 시험 4 최종 완료 평균이 5초를 넘으면(5장) 합의서 판정 기준 협의 또는 답변 생성 시간 단축(출력 토큰 상한·답변 길이 등) 결정이 필요하다.
2. 시험 1·2에 LLM 질의 재작성을 넣을지 여부는 현재 "넣지 않음"(합의서 문구 기준)으로 구현했다. 넣어야 하면 옵션으로 추가 가능(재작성 LLM 호출이 들어가 결과가 매번 조금씩 달라질 수 있다).
3. 시험 3(LLM-as-a-Judge)용 답변 CSV는 시험 4 결과의 `생성 답변` 열로도 받을 수 있다(인용 표식 제거본은 기존 일괄 질의 결과 CSV에 있음).
