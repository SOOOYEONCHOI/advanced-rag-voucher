# 답변 생성 정확도 사전 점검(LLM-as-a-Judge) 설계 v2.0

- 작성일: 2026-11-19 (sooyeon.choi)
- 대체 문서: `eval-llm-judge-design-v1.0.md`(3종 LLM 점수 방식). v1.0은 이 문서로 대체한다.
- 근거: AI+ 인증 시험 합의서 시험 3(근거 기반 답변 생성 정확도), 2026-11-19 사용자 결정

## 1. 목적과 결정 사항

| # | 결정 (2026-11-19 사용자) |
|---|---|
| J1 | 이 기능은 **사전 점검용**이다. 실제 시험 3은 시험기관이 3종 LLM(GPT-6.1 Sol, Gemini 4 Argon, Claude Opus 5.5)으로 직접 심사한다 |
| J2 | 심사 모델은 **1개를 골라** 실행한다. 선택지는 ① vLLM에 띄워진 오픈소스 모델 ② GPT(GPT-6.1 Sol, OpenAI API) |
| J3 | 판정 기준과 계산식은 합의서 시험 3과 같게 한다(PASS/FAIL, 정확도 = PASS 수 ÷ 전체 평가 데이터 수) |

v1.0과 달라진 점
| 항목 | v1.0 | v2.0 |
|---|---|---|
| 심사 모델 | GPT·Claude·Gemini 3종 동시 | **1종 선택**(vLLM 모델 또는 GPT) |
| 판정 | 점수(충실성 비율, 관련성 1~5점) | **PASS/FAIL**(합의서 판정 기준) |
| 대상 | 일괄 질의 작업 | **평가 실행(전체 RAG 평가)** — 평가 화면의 지표 3 |
| 제공자 | OpenAI·Anthropic·Gemini 클라이언트 3개 | 기존 평가용 LLM 어댑터(`EvalLLM`: vllm·openai) 재사용 |

## 2. 판정 기준과 계산식

### 2.1 판정 (합의서 시험 3 판정 기준 그대로)
| 구분 | 기준 |
|---|---|
| PASS | 생성된 답변이 정답 근거 문서의 내용과 일치하고, 사실적 오류 없이 질의 의도에 부합하는 정보를 적절하게 제공하는 경우 |
| FAIL | 정답 근거 문서의 내용과 불일치하거나 사실적 오류가 있는 경우, 질의 의도에 부합하지 않는 경우, 답변이 누락된 경우 |

- 심사 모델은 **근거 충실성(Faithfulness)** 과 **답변 관련성(Answer Relevance)** 을 각각 PASS/FAIL로 판정한다.
- **최종 판정은 서버가 정한다.** 두 항목이 모두 PASS면 PASS, 하나라도 FAIL이면 FAIL. 모델이 최종 판정을 직접 쓰지 않게 해서 계산을 일관되게 한다.
- 정답 답변(gold answer)은 심사에 쓰지 않는다. 합의서는 "정답 근거 문서와 비교"이다.

### 2.2 지표 3 계산
```
답변 생성 정확도 = 최종 PASS 수 ÷ 평가 실행의 전체 질의 수
```
| 경우 | 처리 |
|---|---|
| 답변 생성 실패(항목 실행 오류), 답변이 비어 있음 | 심사 모델을 호출하지 않고 **FAIL**(답변 누락) |
| 답변 거절(근거 없음·가드레일 차단, `outcome_code`가 `no_context`·`guardrail_blocked` 등) | 호출하지 않고 **FAIL**(질의 의도에 맞는 정보 미제공) |
| 심사 호출 실패(시간 초과, 응답 해석 실패 2회) | **심사 오류**로 따로 센다. 정확도 계산에서는 PASS가 아니므로 분모에만 들어간다. 화면에 "심사 오류 N건"을 표시하고 **오류 건만 다시 심사**할 수 있게 한다 |

## 3. 심사 프롬프트 (`prompt_version = rag-judge.2`)

### 3.1 시스템
```
당신은 산업안전보건 분야 질의응답 시스템의 답변을 심사하는 평가자입니다.
제공된 [정답 근거 문서]만을 사실 판단의 기준으로 삼고, 사전 지식으로 판단하지 않습니다.
한국어로 판단 이유를 쓰고, 지정된 JSON 형식으로만 출력합니다.
```

### 3.2 사용자
```
[질의]
{질의문}

[정답 근거 문서]
(1) {문서명} · {근거 조항} · p.{페이지}
{근거 내용}
(정답 근거가 여러 개면 (2), (3)… 으로 이어 붙임)

[생성 답변]
{생성 답변 본문}

[평가 항목]
1. 근거 충실성(faithfulness)
   - PASS: 답변의 사실 내용(수치·기간·대상·조건·의무·조항 번호 등)이 정답 근거 문서와 일치하고, 근거와 어긋나는 내용이 없다.
   - FAIL: 근거와 다른 내용이 있거나, 근거에 없는 사실을 단정적으로 제시한다.
   - "관련 부서에 확인하세요" 같은 안내 문구는 사실 주장이 아니므로 판단에서 뺀다.
2. 답변 관련성(answer_relevance)
   - PASS: 질의 의도에 맞는 정보를 직접적이고 적절하게 제공한다.
   - FAIL: 질의와 무관하거나, 핵심에 답하지 않거나, 답변을 거절·누락한다.

[출력] JSON만:
{"faithfulness": "PASS" 또는 "FAIL", "faithfulness_reason": "한두 문장",
 "answer_relevance": "PASS" 또는 "FAIL", "answer_relevance_reason": "한두 문장",
 "issues": ["근거와 다른 내용 또는 빠진 핵심(없으면 빈 배열)"]}
```
- 답변은 "본문" 정리본을 쓴다. 인용 번호 `[1]`, 사진 표식 `[IMG:…]`, 마크다운 기호를 뺀 것이다(`app/evaluation/batch/text_clean.py`의 `clean_answer_text` 재사용).
- 온도 0. JSON 해석에 실패하면 1회 다시 요청하고, 그래도 실패하면 심사 오류로 처리한다.
- 프롬프트는 `app/evaluation/judge/prompts.py`에만 둔다. 문구를 바꾸면 `prompt_version`을 올린다.

## 4. 심사 모델 선택

| 선택지 | 목록 출처 | 조건 |
|---|---|---|
| vLLM 오픈소스 모델 | 데이터셋 생성 모델 목록 재사용(`app/evaluation/adapters/gen_model_catalog.py`: 챗봇 기본 LLM + `EVAL_GEN_VLLM_MODELS`) | 모델 서버가 켜져 있을 것(`/v1/models` 확인) |
| GPT(GPT-6.1 Sol) | 설정 `EVAL_JUDGE_OPENAI_MODEL`(정확한 API 모델 ID) | ① `EVAL_JUDGE_EXTERNAL_ENABLED=true` ② 관리자 평가용 OpenAI 키 저장(기존 데이터셋 생성용 키 재사용) ③ 평가 대상 컬렉션이 `EVAL_JUDGE_EXTERNAL_COLLECTIONS`에 있을 것 |

- **자기 심사 경고**: 심사 모델이 답변 생성 모델(챗봇 LLM)이나 데이터셋 생성 모델과 같으면 화면에 "같은 모델이 자기 답을 심사하면 후하게 판정할 수 있습니다"를 표시한다(막지는 않음). 권장 심사 모델은 GPT, 또는 답변 모델과 다른 vLLM 모델.
- 화면에는 모델 이름과 켜짐 여부만 보낸다. 서버 주소·키는 보내지 않는다(기존 생성 모델 선택과 같은 방식).

### 4.1 외부 API 사용 범위 (절대 규칙 7 예외)
- 2026-11-17 결정(외부 AI API는 **개발 서버의 평가 심사 용도에 한해** 허용)을 따른다. 운영 서버는 기본값(꺼짐)을 그대로 둔다.
- 외부로 보내는 것: **질의문, 생성 답변 본문, 정답 근거 내용, 근거 문서명·조항·페이지**. 문서 원본·이미지·사용자 정보·내부 주소는 보내지 않는다.
- 컬렉션 허용 목록(`EVAL_JUDGE_EXTERNAL_COLLECTIONS`, 쉼표로 구분한 qdrant_name, 기본값 비어 있음 = GPT 사용 불가)으로 **공개 법령 컬렉션만** 허용한다. 사내 SOP 컬렉션은 목록에 넣지 않는다.
- GPT로 처음 심사를 실행할 때 화면에서 "질의·답변·근거 내용이 외부 AI 서비스(OpenAI)로 전송됩니다"를 한 번 확인받는다.
- `docs/design/01_결정사항_변경로그.md`에 이 예외를 결정 항목으로 추가한다(구현과 함께).

## 5. 실행 흐름

1. 전체 RAG 평가 실행이 **완료**된다(질의별 생성 답변이 `tb_eval_item_results.answer_text`에 저장됨).
2. 평가 실행 화면 → 지표 3 카드의 **[답변 심사]** → 심사 모델 선택 → 실행.
3. 서버가 백그라운드로 질의별 심사를 실행한다. 진행률 표시, 취소 가능. 같은 모델은 동시에 최대 `EVAL_JUDGE_CONCURRENCY`(기본 4)건.
4. 완료되면 지표 3 = 그 심사 결과로 계산해 저장하고, 화면 카드·항목별 결과·결과 Excel에 반영한다.
5. 다른 모델로 다시 심사할 수 있다. 답변을 다시 만들지 않는다. **화면 지표 3은 가장 최근에 완료된 심사**를 쓰고, 지난 심사 결과는 기록으로 남는다.

- 심사는 평가 실행이 끝난 뒤에만 돌기 때문에, 반환 시간(지표 4) 측정에는 영향이 없다.
- 일괄 질의 작업(시험기관 제출용 CSV) 심사는 이번 범위에서 뺀다. 필요하면 같은 모듈로 2단계에서 붙인다.

## 6. 저장 구조 (Alembic `0014_eval_judge`)

```sql
-- 심사 작업(평가 실행 1건에 여러 번 가능: 모델별·재심사)
CREATE TABLE tb_eval_judge_jobs (
  judge_job_id   bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  run_id         bigint NOT NULL REFERENCES tb_eval_runs(run_id) ON DELETE CASCADE,
  backend        text NOT NULL CHECK (backend IN ('vllm', 'openai')),
  model          text NOT NULL,
  prompt_version text NOT NULL,
  status         text NOT NULL DEFAULT 'pending'
                 CHECK (status IN ('pending', 'running', 'completed', 'failed', 'cancelled')),
  total_count    integer NOT NULL DEFAULT 0,
  done_count     integer NOT NULL DEFAULT 0,
  error_count    integer NOT NULL DEFAULT 0,
  summary_json   jsonb,                -- {pass, fail, judge_error, accuracy, by_reason:{answer_missing, refused, faithfulness_fail, relevance_fail}}
  error_message  text,
  created_by     text REFERENCES tb_users(user_id) ON DELETE SET NULL,
  created_at     timestamptz NOT NULL DEFAULT now(),
  finished_at    timestamptz
);

-- 질의별 심사 결과
CREATE TABLE tb_eval_judge_results (
  judge_job_id   bigint NOT NULL REFERENCES tb_eval_judge_jobs(judge_job_id) ON DELETE CASCADE,
  qa_id          bigint NOT NULL,
  verdict        text NOT NULL CHECK (verdict IN ('PASS', 'FAIL', 'ERROR')),
  faithfulness   text CHECK (faithfulness IN ('PASS', 'FAIL')),
  relevance      text CHECK (relevance IN ('PASS', 'FAIL')),
  fail_reason    text,                 -- answer_missing | refused | faithfulness | relevance | judge_error
  reason_json    jsonb,                -- 모델이 쓴 판단 이유·issues 원문
  latency_ms     integer,
  usage_json     jsonb,
  judged_at      timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (judge_job_id, qa_id)
);
```
- 지표 3 값은 `tb_eval_run_metrics`의 `answer.judge_accuracy`(세그먼트 all·유형·태그)로 저장하고, `metric_version`에 `rag-judge.2:{모델명}`을 남긴다. 다시 심사하면 덮어쓴다.
- 서버를 재시작하면 실행 중이던 심사 작업은 "서버 재시작으로 중단됨"으로 바꾼다(평가 실행과 같은 처리). 완료된 질의 결과는 남기고, "오류·미완료 건만 다시 심사"로 이어서 할 수 있다.
- downgrade: 두 테이블을 삭제하고 `answer.judge_accuracy` 지표 행을 지운다.

## 7. API (관리자 전용, `/api/eval`)

| 메서드·경로 | 설명 |
|---|---|
| `GET /judge/models` | 심사 모델 목록 `[{backend, model, available, is_default, reason}]`. GPT는 설정·키·허용 컬렉션 조건을 `reason`으로 알려 준다 |
| `POST /runs/{run_id}/judge` `{backend, model, only_failed?: bool}` | 심사 시작(202). 조건: 실행이 `full`이고 `completed`, 이 실행에 진행 중인 심사가 없음, GPT 조건 충족. `only_failed=true`면 직전 심사의 심사 오류·미완료 건만 |
| `GET /runs/{run_id}/judge` | 최근 심사 상태·진행률·요약 + 지난 심사 목록 |
| `POST /runs/{run_id}/judge/cancel` | 심사 취소(완료분 보존) |
| 기존 `GET /runs/{run_id}/results` | 질의별 `judge: {verdict, faithfulness, relevance, fail_reason, reason}` 추가(최근 완료 심사 기준) |

## 8. 화면·결과 파일

- **지표 3 카드**: 값(정확도 %), 심사 모델명, "심사 오류 N건"(있을 때), [답변 심사] / [다시 심사] 버튼. 심사 전이면 "미측정".
- **심사 모달**: 모델 선택(vLLM 모델 목록 + GPT), 자기 심사 경고, GPT 첫 실행 시 외부 전송 확인, 진행률·취소.
- **항목별 결과**: 지표 3 열에 PASS(초록) / FAIL(빨강, 사유 배지: 답변 누락·거절·근거 불일치·의도 불일치) / 심사 오류. "문제 항목만" 필터에 FAIL 포함.
- **상세 보기**: 근거 충실성·답변 관련성 판정과 이유, issues 목록.
- **결과 Excel**: 항목별 결과 시트에 "지표 3 판정", "근거 충실성", "답변 관련성", "판정 이유" 열. 지표 요약 시트에 심사 모델·프롬프트 버전·심사 일시.

## 9. 설정값 (`config.py`, `.env.example`, 기본값은 기존 동작을 깨지 않게)

| 설정 | 기본값 | 설명 |
|---|---|---|
| `EVAL_JUDGE_ENABLED` | false | 답변 심사 기능 켜기(꺼져 있으면 지표 3은 지금처럼 "미측정") |
| `EVAL_JUDGE_EXTERNAL_ENABLED` | false | GPT(외부 API) 심사 허용. 개발 서버에서만 true |
| `EVAL_JUDGE_EXTERNAL_COLLECTIONS` | (빈 값) | GPT 심사를 허용할 컬렉션 qdrant_name 목록 |
| `EVAL_JUDGE_OPENAI_MODEL` | (빈 값) | GPT-6.1 Sol의 정확한 API 모델 ID |
| `EVAL_JUDGE_CONCURRENCY` | 4 | 동시 심사 호출 수 |
| `EVAL_JUDGE_TIMEOUT_S` | 60 | 심사 1건 시간 제한 |
