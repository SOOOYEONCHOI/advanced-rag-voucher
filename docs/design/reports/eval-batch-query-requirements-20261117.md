# 시험 대응 추가 개발 요구사항 — API 일괄 질의·CSV 다운로드 (2026-11-17)

> 목적: 시험기관이 화면에서 질의를 하나씩 입력하지 않고, **API 호출로 질의 120개를 한 번에 넣고 질의별 생성 답변을 CSV로 내려받는다.**
> 관련: 시험 항목 1(검색 완전성 Recall@10), 3(LLM-as-a-Judge), 4(평균 응답시간) · R8-7 · N-4 · 앞선 문서 `eval-pipeline-review-20261117.md`
> 상태: 요구사항 정리. **최종 설계는 `eval-batch-query-design-v1.0.md`가 우선한다**(6장 결정 항목 확정 반영).

---

## 1. 가능 여부

| 질문 | 답 |
|---|---|
| 화면 입력 없이 API로 질의할 수 있나? | **지금도 가능.** 질의 API `POST /api/query/`는 1건씩 호출하는 방식이라 120번 반복 호출하면 된다 |
| 120개를 한 번에 넣는 API가 있나? | **없음 → 개발 필요(REQ-B-01~04)** |
| 질의별 답변을 CSV로 받을 수 있나? | **없음 → 개발 필요(REQ-B-05).** 평가 실행 결과 Excel에는 생성 답변이 없다 |
| 응답에 상위 10개 검색 결과가 있나? | **없음 → 개발 필요(REQ-B-06).** `/api/query/` 응답의 `chunks`는 재랭킹 후 상위 K(기본 5)개뿐 |

결론: 아래 요구사항을 구현하면 "API로 120개 일괄 입력 → 순차 실행 → CSV 다운로드"가 가능하다.

## 2. 처리 흐름

```
시험기관(또는 스크립트)
 ① POST /api/eval/batch-jobs        질의 파일(CSV/xlsx) 업로드 → job_id 반환(즉시, 202)
 ② GET  /api/eval/batch-jobs/{id}   진행률 확인(대기/실행 중/완료/실패, n/120)
 ③ GET  /api/eval/batch-jobs/{id}/results.csv   완료 후 CSV 다운로드 (xlsx도 제공)

서버(백그라운드)
 질의 1건씩 순차 실행: RAGService.query()  ← 화면 챗봇·/api/query/와 같은 경로
   문서 검색(하이브리드) → 재랭킹 → 답변 생성
 질의별로 답변·인용·상위 10개·응답시간 저장 → 다음 질의
```

- 120건 × 약 9초 ≈ 18분이 걸리므로, 한 번의 요청 안에서 다 처리하지 않고 **작업 등록 후 조회** 방식으로 한다(nginx `proxy_read_timeout 300s` 초과 방지).
- 운영 답변 경로를 그대로 쓴다. 평가 전용 그래프 실행(`rag_pipeline_adapter`)을 쓰지 않는다. 시험 조건 "We.RAG에 입력"을 충족하기 위해서다.

## 3. 기능 요구사항

| ID | 요구사항 | 상세 | 우선 |
|---|---|---|---|
| REQ-B-01 | 질의 파일 업로드·작업 등록 | CSV(UTF-8, BOM 허용)·xlsx. 필수 열 `질의ID, 질의문`. 선택 열 `컬렉션`(없으면 요청 파라미터의 컬렉션). 최대 500행. 형식 오류는 행 번호·사유를 담아 400으로 반환하고 등록하지 않음 | 필수 |
| REQ-B-02 | 순차 실행 | 한 작업 안에서 질의는 **1건씩 순차**. 동시에 실행되는 작업은 1개(대기열). 실행 전 워밍업 질의 N건(설정, 기본 3)은 결과·평균에서 제외 | 필수 |
| REQ-B-03 | 진행 조회·취소 | 상태 `pending/running/completed/failed/cancelled`, 완료 건수, 시작·종료 시각. 취소 시 완료된 질의 결과는 보존(SC 평가 중단 규칙과 동일) | 필수 |
| REQ-B-04 | 질의별 실패 허용 | 1건이 실패해도 작업 계속. 실패 행은 CSV에 `상태=오류, 오류내용`으로 남김. 일시 오류(LLM 타임아웃 등)는 설정 횟수만큼 재시도 | 필수 |
| REQ-B-05 | 결과 CSV/xlsx 다운로드 | 4장 열 구성. 파일명 `batch_{job_id}_{YYYYMMDD_HHMM}.csv`. Excel 수식 주입 방지(`safe_excel_text` 재사용) | 필수 |
| REQ-B-06 | 상위 10개 검색 결과 기록 | 재랭킹 **전** 하이브리드 검색 상위 10개(`retrieved_chunks`)와 재랭킹 후 상위 K개를 질의별로 저장. 시험 항목 1(Recall@10) 근거 | 필수 |
| REQ-B-07 | 응답시간 측정 | 질의별 `요청 시작 → 검색·재랭킹·답변 생성 완료` 시간(ms). 단계별 시간(검색·재랭킹·생성)도 함께. 작업 요약에 평균·p50·p90·p95·최대 | 필수 |
| REQ-B-08 | 답변 본문 정리본 | 원문 답변과 별도로 인용 표시 `[1]`, 사진 표식 `[IMG:…]`를 제거한 "본문" 열 제공(LLM 심사 입력용). 원문은 그대로 보존 | 필수 |
| REQ-B-09 | 정답 근거 대조(선택) | 정답 파일(`질의ID, 근거 문서명, 근거 위치, 근거 내용`)을 함께 올리면 출처+내용 겹침 규칙으로 정답 청크를 찾아 질의별 `Recall@10 적중`을 계산. 매칭 결과는 검토용 Excel로 내려받아 사람이 확인 후 확정 | 필수(시험 1) |
| REQ-B-10 | 화면(관리자) | 평가 메뉴에 "일괄 질의" 탭: 파일 업로드, 진행률, 작업 목록, 다운로드. API만으로도 전부 가능해야 하며 화면은 보조 | 권장 |
| REQ-B-11 | 일괄 호출 스크립트 | `scripts/eval_batch_query.py --file --collection --base-url --out` : 로그인 → 작업 등록 → 진행 조회 → CSV 저장. 시험기관 제공용 사용법 포함 | 필수 |

## 4. 결과 CSV 열 구성

| 열 | 내용 |
|---|---|
| 질의ID, 질의문 | 입력 그대로 |
| 상태, 오류내용 | 성공/근거없음/거절/오류 (`outcome_code` 한국어 변환) |
| 생성답변(원문) | 화면에 나가는 답변 그대로 |
| 생성답변(본문) | REQ-B-08 정리본 |
| 인용 출처 | 답변에 인용된 근거의 문서명·시트/단계/페이지 (여러 개는 줄바꿈) |
| 인용 근거 내용 | 인용된 청크 원문 |
| 검색 상위10 | 순위·문서명·위치·청크ID (재랭킹 전) |
| 재랭킹 상위K | 순위·문서명·위치·재랭커 점수 |
| Recall@10 적중 | REQ-B-09 사용 시 1/0, 적중 순위 |
| 응답시간(ms), 검색(ms), 재랭킹(ms), 답변생성(ms) | REQ-B-07 |
| 실행시각, 모델명 | 재현 근거 |

마지막 요약 행 또는 별도 시트: 건수, 성공 건수, 평균·p50·p90·p95·최대 응답시간, Recall@10(적중률).

## 5. 비기능·제약

| ID | 요구사항 |
|---|---|
| NFR-B-01 | 설정값 `eval_batch_query_enabled`(기본 false)로 켜고 끔. 끄면 API는 404, 기존 동작 변화 없음 (절대 규칙 6) |
| NFR-B-02 | 인증: 관리자 또는 **평가 전용 계정**만. 질의 실행은 그 계정의 문서 권한으로 판정(권한 판단 함수 공용, 절대 규칙 8) |
| NFR-B-03 | 질의 로그: `tb_query_logs`에 남기되 `input_mode='batch_eval'`로 구분해 사용 통계에서 제외 |
| NFR-B-04 | 작업 상태 저장: 신규 테이블 `tb_eval_batch_jobs`·`tb_eval_batch_items`(Alembic `0012`, upgrade·downgrade). Redis·Celery 금지 (절대 규칙 4). 앱 재기동 시 실행 중이던 작업은 `failed(interrupted)`로 정리하고, 이어서 실행할 수 있게 함 |
| NFR-B-05 | 외부 전송 없음. 이 기능은 사내 서버 안에서만 동작. 3종 LLM 심사는 별도 기능(앞선 문서 4장) |
| NFR-B-06 | 시험 중 문서 변경 금지 안내: 작업 등록 시점의 문서 버전 목록을 작업에 기록하고, 실행 중 문서가 바뀌면 결과에 경고 표시 |
| NFR-B-07 | 결과 파일은 업로드한 질의·답변만 담고 내부 IP·설정값은 넣지 않음 |

## 6. 결정 필요

| ID | 질문 | 제안 |
|---|---|---|
| DQ-B1 | 시험기관이 우리 서버 API를 직접 호출하는가, 우리가 스크립트로 실행해 CSV를 전달하는가 | 둘 다 가능하게 만들고, 시험 당일은 시험기관 입회하에 스크립트 실행 |
| DQ-B2 | 시험기관 접속 방법(폐쇄망 접근, 계정 발급) | 평가 전용 계정 1개 발급, 시험 기간만 활성 |
| DQ-B3 | Recall@10 "상위 10개"가 재랭킹 전 기준이 맞는지 | 재랭킹 전(하이브리드 검색) |
| DQ-B4 | 정답 청크 판정 규칙(내용 겹침 비율) | 근거 문장의 50% 이상 포함 + 출처 일치, 사람 확인 후 확정 |
| DQ-B5 | 응답시간 기준: 비스트리밍 완료 시점, 워밍업 제외 건수 | 비스트리밍 완료, 워밍업 3건 |
| DQ-B6 | CSV 인코딩(엑셀에서 바로 열기) | UTF-8 BOM |

## 7. 작업 범위·일정(안)

| 묶음 | 내용 | 규모 |
|---|---|---|
| 1 | 테이블·작업 실행기·API 3종(REQ-B-01~07) | 1.5일 |
| 2 | CSV/xlsx 출력·본문 정리(REQ-B-05·08) | 0.5일 |
| 3 | 정답 근거 대조·검토 Excel(REQ-B-09) | 1일 |
| 4 | 스크립트(REQ-B-11) + dev 120건 리허설 | 0.5일 |
| 5 | 관리자 화면 탭(REQ-B-10) | 1일(권장, 후순위) |

필수(1~4) 약 3.5일 → 11/23 데이터 수령 전 완료 가능. 수령 후: 정답 매칭·확인 → 문서 동결 → 리허설 1회 → 시험.
