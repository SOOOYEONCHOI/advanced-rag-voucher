세 스크립트가 하는 일

시험방식실행 위치
1 Recall@10운영 검색 노드 retrieve를 그대로 호출 → 상위 10개 안에 정답 청크가 있는지 확인백엔드 실행 환경
2 NDCG@5검색 노드 retrieve + 재랭킹 노드 rerank를 그대로 호출 → 재정렬 상위 5개로 NDCG 계산백엔드 실행 환경
4 평균 반환 시간챗봇 화면과 같은 POST /api/query/stream을 120회 순차 호출 → 첫 토큰·최종 완료 시간 측정시험 PC

시험 1·2는 운영과 한 가지만 다릅니다: LLM 질의 재작성을 하지 않고 시험 질의문 원문으로만 검색합니다(합의서 문구 "시험 데이터를 입력하여 의미 검색과 BM25 검색"). 시험 3(LLM-as-a-Judge)은 이 문서 범위 밖입니다.

시연 순서

원칙

  • 합의서의 시험 절차 순서(① 평가 데이터 확인 → ② 소스 코드 확인 → ③ 시험 PC에서 스크립트 실행)를 그대로 따릅니다.
  • 소스 코드는 스크립트 run()의 주석 번호(1~6)를 위에서 아래로 따라가며, 번호마다 호출되는 운영 코드로 들어갑니다. 이 페이지의 "확인 항목 ↔ 코드" 표를 옆 화면에 띄워 둡니다.
  • 실행 후 질의 1건을 골라 결과 CSV에서 그 행을 열어 "코드가 실제로 낸 값"을 보여 줍니다(정답 포함 1건, 미포함·순위 낮은 1건).
  • 시험 순서는 1 → 2 → 4입니다. 시험 4는 같은 GPU 서버를 쓰는 다른 실행과 겹치면 시간이 늘어나므로 마지막에 단독으로 돌리고, 도는 15~20분 동안 시험 4 코드를 설명합니다.

예상 질문과 답

질문답
BM25 검색은 어디서 하나요?Kiwi 형태소 분석으로 질의를 BM25 sparse 벡터로 바꾸고(kiwi_bm25_encoder.py:58), Qdrant의 kiwi_bm25 색인에서 검색합니다(vector_repository.py:618). 적재 때 같은 인코더로 색인을 만듭니다.
두 검색 결과를 어떻게 합치나요?Qdrant 서버에서 가중 RRF로 합칩니다(vector_repository.py:623). 순위 역수에 가중치를 곱해 더하는 방식이고, 가중치는 질의 유형별 표(retrieval_engine.py:25 RRF_WEIGHTS)를 따릅니다.
운영 챗봇과 같은 결과인가요?검색·재랭킹은 운영 함수를 그대로 부릅니다. 차이는 시험 1·2에서 LLM 질의 재작성을 하지 않는 것 하나입니다(합의서 문구 기준). dev에서 산안 NDCG@5가 기존 평가 결과(0.94424)와 같게 나왔습니다.
모델을 불러오는 코드가 따로 있나요?모델은 GPU 서버에서 자체 서비스합니다. 스크립트는 그 서버에 연결하는 클라이언트를 만듭니다(aiplus_search.py:35). 외부 AI API는 호출하지 않습니다.
오류가 난 질의는 어떻게 계산하나요?시험 1·2는 0점, 시험 4는 오류까지 걸린 시간으로 넣습니다. 분모는 모두 전체 시험 데이터 수입니다.
첫 토큰과 최종 완료 중 어느 값으로 판정하나요?합의서 문구는 최종 완료입니다. 스크립트는 두 값을 모두 출력합니다.

시험 전 준비 사항

  • 시험 환경에서 시험 데이터셋을 다시 만든다. 청크ID가 Qdrant 포인트 ID라 문서를 다시 등록하면 ID가 바뀝니다. 순서: 시험 서버 등록 → 데이터셋 생성·검수·확정 → 합본 → 시험 데이터셋 xlsx 다운로드. 이후 시험이 끝날 때까지 문서 등록·삭제·버전 변경 금지.
  • 고아 포인트 정리. AIE_산업안전보건법 컬렉션에 DB에 없는 문서의 포인트 647개가 남아 있습니다. 정리하거나 새 컬렉션에 등록합니다(삭제는 되돌릴 수 없어 승인 필요).
  • 시험 1·2 실행 방식 합의. 시험 PC에서 백엔드 컨테이너에 접속해 실행하는지 확인합니다. 시험 PC에서 직접 돌리려면 백엔드 패키지·.env·Qdrant/임베딩/Reranker 서버 접근이 필요합니다.
  • 시험 4 전용 계정. 시험 질의가 일반 사용 통계에 섞이므로 전용 계정을 쓰고 통계에서 그 계정을 빼고 봅니다. 대상 컬렉션 2개에 권한을 줍니다.
  • 시험 4 판정 기준. 합의서 문구는 "최종 답변 생성 완료 시점까지"입니다. 첫 토큰 기준으로 판정하려면 합의서 문구를 고쳐 합의해야 합니다(스크립트는 두 값을 모두 냅니다).
  • 시험 4 측정 중 다른 작업 금지. 다른 사용자 질의·평가 실행·시험 1·2 스크립트를 동시에 돌리면 같은 GPU 서버를 써서 시간이 늘어납니다.

남은 이슈

  1. 시험 4 최종 완료 평균이 5초를 넘으면 합의서 판정 기준 협의 또는 답변 생성 시간 단축(출력 토큰 상한·답변 길이 등) 결정이 필요합니다.
  2. 시험 1·2에 LLM 질의 재작성을 넣을지는 현재 "넣지 않음"(합의서 문구 기준)으로 구현했습니다. 넣어야 하면 옵션으로 추가할 수 있습니다(재작성 LLM 호출 때문에 결과가 매번 조금씩 달라질 수 있음).
  3. 시험 3(LLM-as-a-Judge)용 답변은 시험 4 결과의 생성 답변 열로도 받을 수 있습니다(인용 표식 제거본은 기존 일괄 질의 결과 CSV에 있음).
