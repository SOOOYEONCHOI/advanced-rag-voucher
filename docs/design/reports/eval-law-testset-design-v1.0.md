# 법령 시험 데이터셋 생성·다운로드 설계 v1.0

> **구현 반영(2026-11-19, 보고서 `eval-law-testset-20261119.md`)**: 아래 본문과 다르게 구현한 점
> - 일반 문서도 유형 구분 없는 단일 출처 생성(`single_section`)을 추가했다(사용자 요청).
> - 법령은 컬렉션별로 등록되어 있다(`AIE_산업안전보건법`, `AIE_중대재해처벌법`=법률+시행령). 그래서 `per_doc_target` 대신 **데이터셋(컬렉션)당 `target_count`=60**으로 하고, 컬렉션 안의 문서(법률→시행령 순)에 조항 수 비율로 자동 배분한다.
> - 조문이 모자라면(중대재해처벌법: 조항 26개 + 별표 4개) **같은 청크에서 다른 내용을 묻는 두 번째 질문**(`max_questions_per_chunk`=2)으로 채운다. 출처는 여전히 1곳이다.
> - 질의ID 접두어는 데이터셋 생성 설정(`query_id_prefix`)으로 정한다.

- 작성일: 2026-11-19 (sooyeon.choi)
- 근거: AI+ 인증 시험 합의서(시험 1~4), 2026-11-19 사용자 결정
- 관련: `eval-batch-query-design-v1.0.md`(일괄 질의·정답 대조), `eval-llm-judge-design-v1.0.md`(3종 심사)

## 1. 목적과 결정 사항

시험 질의 120개(법령별 60개)와 정답 데이터는 **우리가 직접 만든다**. 기존 평가 데이터셋 생성 기능에 "법령 시험용" 방식을 추가한다.

| # | 결정 (2026-11-19 사용자) |
|---|---|
| D1 | 질문 유형(사실·절차·비교·멀티홉) 구분 없이 생성한다 |
| D2 | **법령별 60개를 조항에 고르게 배분**하는 것이 핵심이다 |
| D3 | **질의 1건 = 출처 1곳**(청크 1개). 여러 출처를 합쳐야 답할 수 있는 질의는 만들지 않는다 |
| D4 | 생성 모델은 `gemma-4-31B-it-FP8`(기존 생성 모델 선택 기능 사용) |
| D5 | 시험 데이터셋에는 질의문(질문·답변)과 정답 데이터(근거 문서명·조항·페이지·청크ID·근거 내용)가 있어야 하고, **기존 데이터셋 다운로드 위치에서 내려받는다** |

## 2. 코드·데이터 확인 결과 (2026-11-19 dev)

| F4 | 검색 결과의 청크 ID는 **Qdrant 포인트 ID(UUID)**다. 평가 데이터셋의 `gold_chunk_ids`도 같은 UUID다. 그런데 11-18에 만든 일괄 질의의 정답 대조(`gold_matcher`·`eval_batch_repository`)는 `tb_chunks.chunk_id`(`문서:버전:키#순번`)를 쓴다 | **일괄 질의 Recall@10·NDCG@5가 항상 0이 된다**(ID 형식 불일치). 이번에 함께 고친다. `tb_chunks.point_id`로 서로 변환할 수 있다 |

## 3. 생성 방식: `generation_mode = "law_article"`

`gen_config.generation_mode`의 기본값은 `"typed"`(기존 동작)이다. `"law_article"`일 때만 아래 흐름을 쓴다.

### 3-1. 청크 수집
1. Qdrant scroll 결과 중 **DB의 활성 버전 청크만** 남긴다(`tb_chunks.point_id`와 활성 문서 버전을 대조). 이렇게 해서 고아 포인트와 이전 버전을 제외한다.
2. 제외 대상:
   - 목차, 부칙
   - 본문 길이가 `min_chunk_chars` 미만인 청크(법령 모드 기본값 80자. 짧은 조문이 많기 때문)
   - 조항 머리글(`header_path`)만 있고 본문이 없는 청크
3. 별표는 `include_annex`(기본값 false)로 선택한다. false이면 조문이 모자랄 때만 보충에 쓴다.

### 3-2. 배분: 법령별 목표 수 + 조항 단위 고르게
1. 문서별 목표 = `per_doc_target`(기본값 60). 전체 목표 = 문서 수 × 60.
2. 문서 안에서 청크를 **조항(`header_path`의 마지막 조 단위)으로 묶고**, 조항을 문서 순서대로 놓는다.
3. 목표 수가 조항 수보다 적으면 **같은 간격으로 조항을 고른다**. 예를 들어 조항 105개에서 60개를 고르면 약 1.75조마다 1개를 골라, 장(章) 전체에 퍼지게 한다.
4. 조항 안에서는 청크 1개를 고른다(가장 긴 본문 우선, 같은 길이면 seed 기준).
5. 조항 수가 목표보다 적으면 2바퀴째에 조항당 두 번째 청크를 고른다. 그래도 모자라면 별표로 보충하고, 그래도 모자라면 생성 가능한 수만큼만 만들고 경고를 남긴다. **같은 청크는 재사용하지 않는다.**
6. 생성 실패(JSON 오류, 지시어 포함, 단일 출처 검사 실패)가 나면 같은 조항의 다른 청크로, 없으면 아직 안 쓴 조항으로 대체한다. 문서별 목표 수를 유지한다.

### 3-3. 단일 출처 보장 (D3)
- 생성 대상은 **청크 1개**뿐이다(멀티홉 생성 경로를 쓰지 않음).
- 프롬프트 규칙: "제공된 조문 하나만으로 완전히 답할 수 있는 질문만 만든다. 다른 조문·시행령·별표를 함께 봐야 하는 질문은 만들지 않는다. 본문이 다른 조문을 참조만 하는 경우(예: 'ⅹ조에 따른 ~') 참조된 조문 내용을 묻지 않는다."
- 생성 후 자동 검사(실패 시 재생성 1회, 그래도 실패면 대체 청크):
  - 답변에 나온 **숫자·기간·금액 표현이 모두 근거 본문에 있는지** 확인한다.
  - 질문·답변에 근거 본문에 없는 "제N조"가 나오면 실패로 처리한다.
- 정답 청크 ID는 **1개만** 저장한다.

### 3-4. 질문 형태
- 실무자가 묻는 자연스러운 질문을 만든다. 조항 번호를 넣은 질문과 넣지 않은 질문을 섞는다.
  - `article_ref_ratio`(기본값 0.3): 30%는 "산업안전보건법 시행령 제115조에서 …"처럼 조항을 직접 언급하고, 70%는 내용만으로 묻는다.
- 답변은 근거 조문 내용만으로 하십시오체로 작성한다. 답변 문장에는 출처를 넣지 않는다. 출처는 정답 데이터 열에 따로 둔다.
- 기존 공통 규칙(지시어 금지, 한자 금지, JSON 출력)은 그대로 쓴다.

### 3-5. 검증과 모델
- 검색 미검출 재생성(F5)은 법령 모드에서 **끈다**. `self_valid_rank`는 참고용으로만 기록한다.
- 생성 모델은 화면의 생성 모델 선택에서 `gemma-4-31B-it-FP8`를 고른다(`EVAL_GEN_VLLM_MODELS`에 등록된 이름). 코드에 모델명을 고정하지 않는다.
- 문항은 `question_type = "law"`로 저장한다. `source_meta_json`에 `law_name`, `article`(조항), `header_path`, `page_number`, `document_id`, `version_no`를 저장한다.

## 4. 시험 데이터셋 다운로드 (D5)

- API: `GET /api/eval/datasets/{dataset_id}/test-set.xlsx` (관리자, **승인·수정 문항만** 포함)
- 화면: 데이터셋 목록에서 기존 "승인 QA 다운로드" 옆에 **"시험 데이터셋 다운로드"** 버튼을 둔다(법령 데이터셋일 때만 보임).
- 질의ID 형식: `{약칭}-{3자리}`. 예: `산안-001`~`산안-060`, `중처-001`~`중처-060`. 약칭은 문서명에서 자동으로 만들고, 생성 설정에서 바꿀 수 있다.

| 시트 | 열 | 용도 |
|---|---|---|
| 질의 | 질의ID, 질의문, 정답 답변 | 그대로 **일괄 질의 업로드 파일**로 쓴다(`질의ID`·`질의문` 열 이름 호환) |
| 정답 근거 | 질의ID, 근거순번(=1), 근거 문서명, 근거 조항, 페이지, 청크ID, 근거 내용 | 그대로 **일괄 질의 정답 파일**로 쓴다(청크ID가 있으면 자동 매칭 없이 바로 확정) |
| 요약 | 법령별 문항 수, 조항 분포(장별 건수), 생성 모델, seed, 생성일시, 컬렉션·문서 버전 | 시험 문서화·재현용 |

- 청크ID는 검색 결과와 같은 **Qdrant 포인트 ID**를 쓴다(F4).
- 문서 버전이 바뀌면 청크ID가 무효가 되므로, 요약 시트에 문서 버전을 남기고 다운로드할 때 현재 버전과 다르면 경고 행을 넣는다.

## 7. 테스트 기준
1. 문서 2개(조항 105개, 40개)에 문서별 60개를 요청한다.
   - 문서별 60개가 정확히 나온다.
   - 같은 청크가 중복되지 않는다.
   - 조항이 105개인 문서는 60개 조항에서 1개씩 고르고, 장별 분포가 조항 수 비율과 ±1 이내다.
   - 조항이 40개인 문서는 1바퀴째 40개, 2바퀴째 20개를 고른다.
2. 고아 포인트와 비활성 버전 청크는 뽑히지 않는다.
3. 답변의 숫자가 본문에 없거나 본문에 없는 조항 번호가 나오면 실패로 처리하고 대체 청크로 다시 생성한다.
4. 다운로드한 `질의` 시트를 일괄 질의에 올리고, `정답 근거` 시트를 정답 파일로 올린다.
   - 매칭 없이 확정된다.
   - Recall@10 분모가 전체 질의 수다.
5. 기존 유형별 생성과 승인 QA 다운로드 테스트는 그대로 통과한다.
