# 문서 관리 모델명 1단계 — 2026-10-19

사용자 요청: Phase 4.5 전에 문서 관리 화면의 모델명 입력·수정을 먼저 구현한다. 상세 기준은 `docs/design/문서 관리 모델명·버전 관리 개선 요청서.md` 9절이다.
관련 ID: UI-12, SC-06(후속 버전 관리의 전제), D-01·D-04·D-14·D-16.
**버전 관리(최신본 변경·버전 이력)는 구현하지 않았다.** 이 단계는 모델명까지만 한다(요청서 9.2의 1~4단계).

## 1. 요약

- 화면 표기는 **모델명**으로 하고, 저장 위치는 기존 `tb_documents.product_model`을 다시 쓴다. API 키도 `product_model`이다. `model_name` 컬럼은 추가하지 않았다.
- **업로드**
  - 공통 "제품 모델(선택)" 입력을 없애고 파일마다 모델명 입력칸을 두었다.
  - 기본값은 파일명에서 마지막 확장자만 뺀 값이다. 업로드 전에 행마다 고칠 수 있다.
  - 앞뒤 공백을 빼고 1~100자인지 검사한다. 오류가 있으면 그 행에 표시하고 전송을 막는다.
  - 전송을 시작할 때 값을 확정하고 입력칸을 잠근다.
- **서버 검증**
  - 기존에는 `strip()[:100]`으로 조용히 잘랐다. 이것을 명시적 검증으로 바꿨다.
  - 필드를 보내지 않으면(구 클라이언트) 파일명 기본값을 쓴다. 명시적으로 보낸 빈 값·공백·101자는 422로 거절한다.
  - FastAPI는 빈 문자열 폼 값을 "필드 없음"으로 바꾼다. 그래서 원본 폼에 키가 있는지를 따로 확인한다.
- **목록**
  - 첫 컬럼에 모델명과 연필 아이콘을 두었다. 저장·취소, Enter 저장, Esc 취소를 지원한다.
  - 저장에 실패하면 입력값과 오류를 그대로 보여 준다. 취소하면 원래 값으로 돌아간다.
  - "현재 버전"(`version_no`)과 "최근 변경일"(`updated_at`, KST) 컬럼을 추가했다.
  - 파일명 헤더는 "파일명(최신본)"으로 바꿨고, 원본 열기 링크는 유지했다.
- **수정 API**
  - `PATCH /api/ingest/documents/{document_id}/model-name` `{"product_model": "…"}`를 새로 만들었다.
  - 권한 규칙은 삭제와 같다(관리자는 모든 문서, 그 외 사용자는 본인 업로드 문서만).
  - 볼 수 없는 대화 주제의 문서는 404로 응답해 존재를 숨긴다(D-04). 볼 수는 있지만 본인 문서가 아니면 403이다.
  - 값이 실제로 바뀐 경우에만 `updated_at`을 갱신하고 `tb_document_events`에 `update` 이력(전후 값)을 남긴다.
- **기존 데이터:** Alembic `0004_document_model_name`이 삭제되지 않은 문서 중 비어 있는 모델명만 파일명 기본값으로 채운다. 이미 입력된 값과 최근 변경일은 그대로 둔다.

## 3. 모델명 수정이 검색에 미치는 영향 (동기화 범위)

- 모델명만 고치면 **버전 증가, 재파싱, 재임베딩, Qdrant 변경을 하지 않는다.** dev E2E에서 수정 전후의 `version_no`, 버전 행 수, 청크 수, Qdrant 포인트 수, 청크 텍스트 해시가 같은 것을 확인했다.
- Qdrant payload에는 모델명이 없다. 따라서 검색 필터·권한·출처 표시와 RDB가 어긋날 일이 없다.
- 이미 만든 **엑셀 청크의 머리말 텍스트에는 업로드 당시 모델명이 남는다.** 확인용 md도 마찬가지다. 검색 품질에만 영향이 있고 권한·표시에는 영향이 없다. 제안은 1차에서는 그대로 두고, 다음 [최신본 변경] 때 현재 모델명으로 다시 만드는 것이다(Q-MN-1).
- **업로드 기본값이 생기면서 바뀌는 점:** 화면이 항상 모델명을 보내므로, 앞으로 올리는 엑셀 문서는 청크 머리말에 모델명(기본값=파일명)이 들어간다. 기존에는 비워 두면 머리말에 모델이 없었다. 같은 파일이라도 모델명 길이에 따라 긴 청크 분할 결과가 조금 달라질 수 있다(dev E2E에서 243/241개). 엑셀 검색 평가(`scripts/eval_excel_retrieval.py`) 수치는 다음 평가 때 다시 측정해야 한다.

  - dev 컨테이너는 기동할 때 `init_database.py`가 upgrade head를 실행한다.

- **버전 관리:** 10-19에 이어서 구현했다 → `document-versions.md`. 아래는 이 단계 작성 당시 기록이다.
  - 기존 `document_id`와 모델명을 유지하고, 새 버전 활성화에 성공했을 때만 최신본을 전환한다.
  - 처리 중이거나 실패하면 기존 검색본을 유지한다.
  - [최신본 변경]·[버전 이력] 버튼과 대화상자, D-18 [이 버전 적용] 숨김을 다룬다.
  - 현재 버전은 모두 v1이다.
- Q-MN-1: 모델명을 수정해도 기존 엑셀 청크 머리말은 갱신되지 않는다(3절).
- 모델명 동시 수정은 마지막 저장이 이긴다. 모델명 검색·필터는 미구현이다(요청서 6절 권장).
- "최근 변경일"은 `updated_at`이다. 다른 문서 행 갱신(예: 검토 기한)도 이 값을 바꾼다. 최신본 활성화 시각은 버전 관리 단계에서 `active_activated_at`과 함께 정리한다.
- 테스트 순서 의존(기존 문제): voice 테스트 2개의 수집 오류가 전체 실행에서만 생긴다(6절).
