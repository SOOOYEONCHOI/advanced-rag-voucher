# 합본 평가 데이터셋 설계 v1.0

- 작성: 2026-11-20 (sooyeon.choi)
- 목적: AI+ 인증 시험 대응. 산업안전보건법 60문항과 중대재해처벌법 60문항을 **한 데이터셋(120문항)** 으로 합쳐, 기존 평가 화면에서 한 번에 실행하고 결과 화면과 결과 xlsx로 확인한다.
- 화면 목업: `docs/design/reports/mockup-eval-merged-dataset-20261120.html`
- 관련: 시험합의서 지표 1~4, `eval-law-testset-design-v1.0.md`(법령 조항 데이터셋), `eval-llm-judge-design-v2.0.md`(지표 3)

## 1. 원칙

1. **기존 기능은 그대로 둔다.** 단독 데이터셋 생성·검토·확정·평가·결과·다운로드는 바뀌지 않는다.
2. **합본도 보통 데이터셋 하나다.** 평가 실행, 결과 화면, 결과 xlsx는 기존 기능을 그대로 쓴다.
3. **지표는 항목별로 계산한다.** 120문항을 하나씩 실행하고, 문항마다 지표를 계산한 뒤 120문항 전체로 집계한다. 단독 실행 결과를 가져와 평균하지 않는다.
4. **검색 조건은 단독과 같다.** 문항마다 원래 데이터셋의 컬렉션에서 검색한다(산안 → AIE_산업안전보건법, 중처 → AIE_중대재해처벌법).
5. **DB 마이그레이션은 없다.** 기존 열(`gen_config_json`, `source_meta_json`)만 쓴다.

## 2. 사용자 흐름

| 단계 | 화면 | 동작 |
|---|---|---|
| ① | 데이터셋 목록 | 확정된 데이터셋 2개 이상을 체크한다 → [합본 데이터셋 만들기]를 누르고 이름을 입력한다 |
| ② | 데이터셋 목록 | 합본 데이터셋이 생기고 바로 확정(v1)된다. 원본 2개는 그대로 남는다. 상세 화면은 읽기 전용 |
| ③ | 평가 실행 | 골드셋 목록에서 합본을 고르고 [평가 실행](전체 RAG)을 누른다. 120문항이 순서대로 실행된다 |
| ④ | 평가 결과 | 지표 1~4 카드는 120문항 기준. 카드 아래에 같은 실행의 법령별 값을 보여 준다. 항목 표에는 질의ID·법령 열과 법령 필터 |
| ⑤ | 결과 xlsx | 기존 [결과 xlsx 내려받기]. 항목별 시트에 질의ID·법령·정답 답변·생성 답변·인용 출처 열이 추가되고, 요약 시트에 법령별 표가 붙는다 |

## 3. 지표 계산 (단독과 동일)

같은 `eval_runner` 코드를 쓰고, 문항 수만 120개다.

| 지표 | 계산 | 분모 |
|---|---|---|
| 지표 1 Recall@10 | 재랭킹 전 하이브리드 검색 상위 10개에 정답 청크가 든 문항 수 ÷ 전체 문항 수 | 120 |
| 지표 2 NDCG@5 | 문항별 재랭킹 상위 5개 NDCG의 합 ÷ 전체 문항 수 | 120 |
| 지표 3 답변 정확도 | PASS 문항 수 ÷ 전체 문항 수 (심사 기능 구현 후) | 120 |
| 지표 4 반환 시간 | 문항별 첫 토큰 반환 시간의 평균 (판정 기준 5초 이내) | 측정된 문항 |

- 법령별 값: **같은 실행의 항목 결과**를 법령으로 나눠 위 식을 그대로 적용한다(분모 각 60). 판정은 하지 않는 참고 값이다.
- 오류 문항 처리, 제외 규칙, 소수점 처리는 단독 평가와 같다.

## 4. 데이터 구조 (마이그레이션 없음)

### 4.1 합본 데이터셋 (`tb_eval_datasets`)
- `collection_id`: 첫 번째 원본의 컬렉션. NOT NULL 열을 채우기 위한 값이고, 검색에는 쓰지 않는다.
- `status`: `finalized`
- `gen_config_json`:
  ```json
  {
    "dataset_kind": "merged",
    "merged_from": [
      {"dataset_id": 4, "dataset_name": "…", "goldset_id": 7, "goldset_version": 1,
       "collection_name": "AIE_산업안전보건법", "law_label": "산업안전보건법", "item_count": 60},
      {"dataset_id": 3, "...": "..."}
    ]
  }
  ```

### 4.2 합본 문항 (`tb_eval_qa_items`)
- 각 원본의 **최신 확정본(골드셋) 스냅샷**에서 문항을 복사한다. 확정 이후에 고친 내용은 들어가지 않는다.
- 질문, 정답 답변, 정답 청크(포인트 ID), 유형, 기대 동작, 검토 상태를 그대로 복사한다.
- `source_meta_json`에 다음 값을 추가한다.

| 키 | 값 | 용도 |
|---|---|---|
| `qdrant_name` | 원본 컬렉션 | 문항별 검색 컬렉션 |
| `query_id` | 원본 시험셋과 같은 질의ID(예: `산안-001`) | 시험셋·결과 xlsx·화면의 ID를 일치시킴 |
| `law_label` | 법령 이름 | 화면 열·필터, 법령별 집계 |
| `merged_source` | `{dataset_id, goldset_id, qa_id}` | 원본 추적 |

- 질의ID는 원본 시험셋 다운로드와 같은 규칙(앞머리 + 정렬 순서)으로 합본을 만들 때 한 번 계산해 저장한다.
- 합본 생성 후 바로 골드셋 v1을 만든다(`create_goldset` 재사용).

## 5. 수정 내용

### 5.1 백엔드

| 파일 | 수정 |
|---|---|
| `app/routes/evaluation.py` | `POST /eval/datasets/merge` 추가: `{name, dataset_ids}` 입력 → 검증 → 합본 생성 → `{dataset_id, goldset_id, item_count}` 반환 |
| | 문항 수정·승인·다시 생성 API: 합본이면 409("합본 문항은 원본에서 수정해 주세요") |
| | 평가 실행 생성: 스냅샷에 들어 있는 컬렉션이 모두 있는지 확인. 없으면 400 |
| `app/repositories/evaluation_repository.py` | `create_merged_dataset(name, sources, created_by)`: 한 트랜잭션에서 데이터셋과 문항을 복사 |
| `app/evaluation/runner/eval_runner.py` | 문항의 `source_meta_json.qdrant_name`이 있으면 그 컬렉션, 없으면 지금처럼 골드셋의 컬렉션을 쓴다 |
| | 법령별 집계 추가: 합본일 때만 `law_label`별로 같은 집계 함수를 적용해 실행 요약에 넣는다 |
| `app/evaluation/excel_exporter.py` | 결과 xlsx 항목별 시트에 질의ID, 법령, 정답 답변, 생성 답변, 인용 출처 열 추가. 요약 시트에는 합본일 때만 법령별 표 추가 |
| | 시험셋 xlsx: `source_meta_json.query_id`가 있으면 그 ID를 쓰고, 합본이면 `질의` 시트에 `법령` 열 추가 |
| `app/core/config.py` | `eval_dataset_merge_enabled: bool = True`. 끄면 합본 API는 404, 화면 버튼은 숨김(기존 동작 영향 없음) |

합본 생성 검증:
- 데이터셋 2개 이상, 모두 확정본이 있어야 한다. 합본을 다시 합칠 수는 없다.
- 합칠 데이터셋끼리 질의ID가 겹치면 400을 내고, 겹치는 ID 목록을 알려 준다.
- 최대 문항 수는 기존 평가 실행 한도를 따른다.

### 5.2 화면

| 파일 | 수정 |
|---|---|
| `views/EvalDatasetView.vue`, `composables/useEvalDatasets.js` | 목록 체크 칸(확정된 단독 데이터셋만), 선택 안내 줄, [합본 데이터셋 만들기]와 이름 입력 창, `합본` 표시, 컬렉션 칸 `합본 (A + B)`, 합본 상세에서는 수정·다시 생성 버튼 숨김 |
| `views/EvalRunView.vue`, `composables/useEvalRuns.js` | 골드셋 목록에 `[합본]` 표시와 안내 한 줄. 결과 카드 아래 법령별 값 한 줄(합본일 때만). 항목 표에 질의ID·법령 열과 법령 필터 |
| `api/evalApi.js` | `mergeDatasets({name, dataset_ids})` |

### 5.3 결과 xlsx 항목별 결과 시트 열

`번호 · 질의ID · 법령 · 질문 · 정답 답변 · 생성 답변 · 인용 출처 · Recall@10 · NDCG@5 · 첫 토큰(s) · 전체 응답시간(s)`

- 단독 데이터셋의 결과 xlsx에도 질의ID, 정답 답변, 생성 답변, 인용 출처 열이 생긴다. 법령 열은 합본일 때만 넣는다.
- 셀 글자 수 제한과 수식 문자 방지 처리는 기존 `_limited_text`, `_safe_row`를 그대로 쓴다.

## 6. 테스트

1. 합본 생성: 문항 120개, 질의ID 유지, `qdrant_name`·`law_label` 저장, 골드셋 v1 생성
2. 검증: 확정본 없음, 1개만 선택, 합본 재합치기, 질의ID 중복 → 400
3. 합본 문항 수정·다시 생성 → 409
4. 평가 실행: 문항별 컬렉션으로 검색 호출(가짜 검색기로 컬렉션 인자 확인), 기존 단독 데이터셋은 골드셋 컬렉션 그대로
5. 집계: 전체 = 120문항 항목별 집계, 법령별 = 같은 실행 항목을 나눈 집계
6. 결과 xlsx: 열 머리글, 생성 답변 값, 합본 요약의 법령별 표. 시험셋 xlsx: 머리글은 시트마다 1행, 질의ID 일치
7. 설정을 끄면 합본 API 404
8. 기존 평가 테스트 전체 통과

## 7. 되돌리는 방법

- 설정 `EVAL_DATASET_MERGE_ENABLED=false`로 끈다.
- 코드를 되돌려도 DB 구조 변경이 없다. 만들어 둔 합본 데이터셋은 보통 데이터셋처럼 화면에서 삭제할 수 있다.

## 8. 남은 확인 사항

1. 합본을 만든 뒤 원본을 고치면 합본에 자동으로 반영되지 않는다. 원본 수정 → 확정 → 합본 재생성 순서로 쓴다(제안안).
2. 법령별 값(결과 카드 한 줄, 요약 시트 표)을 넣을지. 목업에는 포함했다.
3. 예상 작업 시간: 백엔드 1시간, 화면 1시간, 테스트 30분~1시간.
