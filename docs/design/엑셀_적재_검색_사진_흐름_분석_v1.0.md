## 1. 업로드 (API → 작업 큐)

### 1.1 업로드 API — `routes/ingest.py:257 upload_document`

| 순서 | 처리 | 코드 |
|---|---|---|
| 1 | 업로드 사용자의 `max_security_level`로 문서 보안등급 결정 | `:283-286` |
| 2 | 비관리자는 대상 컬렉션 접근 권한 확인(없으면 403) | `:289-296` |
| 3 | 모델명(`product_model`) 결정. 폼에 없으면 파일명(마지막 확장자 제외), 빈 값·100자 초과는 422 | `:300-306` |
| 4 | 확장자·파서·문서 유형 검사 `_validate_upload_options` | `:198` |
| 5 | 임시 저장 `_store_upload_tmp` → `{sqlite_db_path 상위}/ingest_jobs/{job_id}.{ext}` | `:233` |
| 6 | `tb_ingest_jobs`에 요청 내용 저장, 큐에 넣고 `202 {job_id, status: queued}` 반환 | `:327-330` |

- **엑셀 특례(D-16):** `EXCEL_PARSE_MODE=backend`이고 확장자가 xlsx·xlsm·xls면 `excel_ingest_upload=True`.
  문서 유형·파서(`docling`/`pdfplumber`) 선택은 검사하지도, 쓰지도 않는다.
- **파일 서명 검사** `ingest/file_router.py resolve_parse_route` (임시 저장 직후 1번, ChunkStep에서 1번 더)
  - xls: OLE2 서명이어야 함 → `needs_conversion=True`(LibreOffice로 xlsx 변환)
  - xlsx·xlsm: ZIP 서명 + `[Content_Types].xml`에 `spreadsheetml` 포함
  - OLE2 안에 `EncryptedPackage`가 있으면 암호 파일 → 400 `encrypted`
  - xltx·xltm 등 다른 형식은 backend 모드에서도 docling 경로

### 1.2 작업 실행 — `services/ingest_jobs.py`

- 큐: **앱 프로세스 안 `asyncio.Queue` + `tb_ingest_jobs` 상태 테이블**. 작업자 1개가 순서대로 처리한다.
  (Redis·Celery 없음. 기동 시 `requeue_interrupted`로 중단 작업을 다시 넣는다.)
- 진행 단계(`current_step`): `validate → parse → chunk → embed → index → completed`
- 각 단계가 끝나면 `IngestContext`를 `{임시파일}.checkpoint`(pickle)로 저장 → 재시도 시 실패 단계부터 다시 시작
  (`ingest_pipeline.py IngestPipeline.run`).
- 성공하면 임시 업로드 파일을 지운다. 실패하면 `status=failed`, 오류 문구 저장.

## 2. 파싱 (ParseStep · ChunkStep)

### 2.1 ParseStep — 원본 보관 (`ingest_pipeline.py:85`)

- 컬렉션 확인(`_validate_collection`, qdrant_name 또는 표시 이름).
- 원본 복사: `instance/data/{YYYY}/{MM}/{YYYYMMDD}_{document_id}[_v{n}].{ext}`
  (`ingest_service.py FileStorageManager.save`). DB에는 `/` 구분 상대 경로로 기록.
- 원본 sha256 계산 → `tb_document_versions.file_sha256`.

### 2.2 ChunkStep — 경로 분기 (`ingest_pipeline.py:110`)

```
resolve_parse_route(file, EXCEL_PARSE_MODE, filename)
 ├─ excel_ingest → _run_excel_ingest()   ← 이 문서의 대상
 └─ docling      → IngestService._parse_and_chunk() (DocumentChunkingProcessor, docling-parser API 호출)
```

### 2.3 excel_ingest 실행 — `ingest/excel_runner.py run_excel_ingest`

1. xls면 `soffice --headless --convert-to xlsx`(제한 `EXCEL_XLS_CONVERT_TIMEOUT`=120초).
2. `excel_ingest.parser.parse_workbook(path, doc_key, model=product_model)` 호출 (**추출 규칙은 수정 금지 대상**).
   - `doc_key` = 파일명(확장자 제외)을 안전 문자로 바꾼 값. 표시·md 폴더용이며 개정 판단에 쓰지 않는다(D-01).
3. 확인용 md 출력(실패해도 적재는 계속): `{MD_SAVE_DIR}/excel/{doc_key}/{job_id}/`
   - `00_summary.md`, `sheets/NN_시트명.md`, `chunks.md`, `ir.json`, `images/` + `LATEST`, 최근 `EXCEL_MD_KEEP_LAST`(5)회 보관
4. 요약(`summary()`): 시트 수, 청크 수, 사진 배치 수/고유 사진 수, 인쇄영역 밖 수, 검수 필요 수, 경고 수, 시트 유형, 시트별 개정 정보, md 위치
   → 나중에 `tb_document_versions.summary_json`, 작업 결과 `result_json.excel_ingest`에 들어간다.

## 3. 엑셀 파싱·전처리 상세 (`excel_ingest/`)

### 3.1 읽는 방법 — 두 가지를 동시에 쓴다

| 구분 | 도구 | 얻는 것 |
|---|---|---|
| 셀 | openpyxl `data_only=True`(값) + `data_only=False`(수식) | 셀 값, 병합 범위, 수식, 숨김 행·열 |
| 도형·사진 | `ooxml.py Workbook` — xlsx ZIP 안 drawing XML 직접 파싱(lxml) | 그림(`xdr:pic`), 텍스트 도형(`xdr:sp`), 연결선(`xdr:cxnSp`), 그룹 내부 실제 위치, 폼 컨트롤(체크박스), 인쇄영역(`_xlnm.Print_Area`) |

### 3.2 셀 값 정규화 — `sheet.py fmt_value / load_grid`

- 날짜 → `YYYY-MM-DD`(시간이 0이면), 정수형 실수 → 정수 문자열, 그 밖 실수 → `%g`
- `\r\n`→`\n`, 탭→공백, 앞뒤 공백 제거, 빈 값은 버림
- **병합 셀:** 좌상단 셀 1개만 값으로 보관하고 범위는 `merged`에 따로 둔다.
- **수식:** 캐시값이 없으면 `[수식 캐시값 없음] =…` 텍스트로 남긴다.

### 3.3 시트 유형 분류 — `sheet.py classify` (상단 40행, 30자 이하 셀 기준)

| 순서 | 유형 | 판정 |
|---|---|---|
| 1 | `sop` | 헤더 키워드 `no / 사진 / 작업내용 / checkpoint` 중 3개 이상 |
| 2 | `flowchart` | 텍스트 도형끼리 이은 연결선 8개 이상 |
| 3 | `register` | `제정일 / 개정일 / 공정명` 3개 모두 (관리대장) |
| 4 | `list` | 시트명에 LIST |
| 5 | `reference` | 시트명에 "기준" |
| 6 | `inspection` | 판정·합격·규격·검사·측정·성적서 등 키워드 |
| 7 | `other` | 그 외 |

### 3.4 시트 안 구조 인식 — `parser.py parse_workbook`

| 구조 | 방법 | IR 위치 |
|---|---|---|
| **번호 표** (SOP Step / 흐름도 공정단계) | `No` 셀이 있는 헤더 행 + 필수 헤더(`작업내용` 또는 `공정단계`) → 아래로 번호 행을 모아 Step 범위(r1~r2) 결정. 빈 행 2개 초과·두 번째 `No`·넓게 병합된 제목 행에서 종료 | `sections[].steps[]` : `no, rows, title, fields{헤더: 값}, sub_rows, image_ids, markers, callouts` |
| 표 위 머리말 | 번호 표 헤더 행 위의 셀들 | `header_kv[]` |
| **일반 섹션** | 번호 표 밖 행을 빈 행 2개 초과 간격으로 나눔(`split_sections`). 첫 3행 안에서 텍스트형 셀이 70% 이상인 행을 헤더로, 2단 헤더(위 병합 + 아래 세부)는 `상위 / 하위`로 합침 | `sections[].sections[]` : `rows, title, header, lines[{row, text}]` |
| 행 텍스트 | `labeled_row` : `헤더: 값 · 헤더: 값 …`, 셀 안 줄바꿈은 ` / ` | lines·sub_rows의 `text` |
| **안내문 도형** | 40자 이상 또는 (줄바꿈 + 20자 이상) 텍스트 도형. 「이름」 또는 가까운 `■ / 1.` 제목 셀과 연결 | `notes[]` |
| 짧은 라벨 도형 | 위 조건 미만. Q·S → Step `markers`, ①② → Step `callouts`, 사진 위에 겹치면 사진 `overlay` | `labels[]` |
| 폼 컨트롤 | 체크 여부 + 근처 라벨 | `form_controls[]` |
| 인쇄영역 밖 | 셀·안내문 중 인쇄영역 밖에 있는 것 | `out_of_print_area[]` |
| 흐름도 | 텍스트 도형 = 노드, 연결선 시작·끝 = 간선(화살표 방향 보정). OK/NG 도형은 라벨로 분리. 끝이 안 붙은 선은 `unresolved` | `flow_graph` (→ `tb_flow_graphs`) |
| 관리대장 | `공정명 / 제정일 / N차` 표를 읽어 시트명과 유사도 0.72 이상으로 매칭 | 시트 `revision{process_name, established, revision_no, revision_date, match}` |

### 3.5 사진 추출·역할 판정 — `parser.py _placement`

- drawing의 `a:blip r:embed`가 가리키는 `xl/media/…` 바이트를 읽어 sha256 계산. 외부 링크 사진은 경고만 남기고 제외.
- `assets[sha256]` = 고유 사진(바이트·확장자·배치 수·`needs_conversion`(emf·wmf)). `image_id` = sha256 앞 16자리.
- **배치(placement) 1개 = 시트 위 사진 1개.** 같은 사진이 여러 곳에 있으면 배치가 여러 개다.

| 조건 | role | link_method | 신뢰도 |
|---|---|---|---|
| SOP 표 안, 열 헤더에 "사진" | `step_photo` | `row_in_step_range` | 0.95 |
| SOP 표 안, 열 헤더에 "확대"·"point" | `detail_view` | `row_in_step_range` | 0.6 |
| SOP 표 안, 그 밖 열 | `step_related` | `row_in_step_range` | 0.7 |
| LIST 시트, "사진" 헤더 열 근처 | `part_photo` (같은 행 다른 셀 → `row_item`) | `row_item` | 0.95 |
| 6행 이내 & 15KB 미만 | `form_header` | — | 0.9 |
| 15KB 미만 & 그룹 아님 & 겹친 라벨 없음 | `decoration` | — | 0.6 |
| 그 외 | `figure` | `nearest_text`/`none` | 0.4 |

- 확대도 보정(`_fix_detail_views`): 확대도가 다른 Step의 Step 사진과 같은 파일이면 그 Step으로 옮김(`same_image_as_step_photo`, 0.85).
- 주변 텍스트 `context_text`(200자): Step이면 `Step 제목 / Check Point 앞 120자`, 부품이면 `row_item`, 그 외는 사진 3행 위~사진 끝 행의 가까운 셀 3개.
- 신뢰도 0.7 미만(장식·머리글 제외)은 `review_status=needs_review`. VLM은 **판정만**(`vlm_status`) 하고 호출하지 않는다.

### 3.6 청크 만들기 — `parser.py build_chunks`

모든 청크 텍스트 첫 줄에 **머리말 경로**가 붙는다: `[{모델명} > {시트명} > …]` (모델명이 없으면 `[{시트명} > …]`, 관리대장 개정 정보가 있으면 ` (개정 N차 날짜)` 추가).

| content_type | 블록 키 | 텍스트 구성 | meta |
|---|---|---|---|
| `summary` | `0` | `[… > 개요]` + 머리말 셀(`|` 구분) + `Step 목록: 1. 제목 …` | section_type, revision |
| `step` (SOP) / `flow_stage` (흐름도) | Step 번호 | `[… > Step N. 제목]` + 세부 행(`- 헤더: 값 …`) 또는 `헤더: 값` 줄 + `표시: Q(품질), S(안전)` | + step_no, prev, next, image_ids, callouts, markers |
| `table_section` | `{섹션순번}.{조각}` | `[… > 섹션 제목 또는 "행 N"]` + `(열: 헤더 | …)` + 행 텍스트, **25행마다 분할** | + rows[시작, 끝] |
| `guide_note` | 도형 ID | `[… > 작성 안내: 첫 줄]` + 안내문 전체 | + shape_range, in_print_area, linked_section |
| `form_control` | `0` | `[… > 양식 체크박스]` ☑/☐ 라벨 | is_form_default |
| `flow_overview` | `0` | `[… > 공정 흐름(XML 확정 연결, 검수 전)]` + `노드 → 노드` 줄 | vlm_status |
| `image` | `{image_id}@{셀범위}` | `[… > Step N 제목 또는 부품/셀] 이미지(role) 표시` + context_text | image_id, role, confidence |

- 관리대장(`register`) 시트는 청크를 만들지 않는다(다른 시트의 개정 정보로만 쓰임).
- 청크 ID: `{doc_key}:{시트순번 2자리}:{content_type}:{블록}`

## 4. 백엔드 전처리 (excel_ingest 결과 → 적재 청크)

`ingest_pipeline.py ChunkStep._run_excel_ingest` 순서:

| 단계 | 함수 | 하는 일 |
|---|---|---|
| ① | `plan_excel_images` (`ingest/excel_images.py:45`) | 배치마다 `resource_id = {document_id}-v{version_no}-i{순번:04d}` 발급, `tb_spreadsheet_resources` 행 준비(아직 저장 안 함) |
| ② | `link_excel_images` (`:200`) | 사진 → 청크 순번 연결(설정 `EXCEL_IMAGE_LINK_ALL`). 규칙: step → row_overlap → nearest → image_chunk. 장식·양식 머리글 제외 |
| ③ | `excel_chunks_to_documents` (`ingest/excel_chunks.py:79`) | LCDocument 변환, 메타 채우기, **`image` 청크 버림**(②의 4번 규칙 청크만 유지), 빈 텍스트 버림, `MAX_CHUNK_SIZE` 초과 시 줄 단위 분할 |
| ④ | `flow_graph_rows` (`ingest/records.py:73`) | 흐름도 → `tb_flow_graphs` 행 준비 |

- 분할(`split_text`): 첫 줄 머리말과 `(열: …)` 줄을 **조각마다 반복**하고, 한 줄이 너무 길면 잘라 넣는다. 조각마다 `part_no` 0,1,2…, **사진 목록은 조각 모두 같다.**
- 같은 키가 두 번 나오면(Step 0 두 번 등) `source_key`에 `~2`, `~3`.
- 적재할 청크가 0개면 실패(“엑셀에서 적재할 내용을 찾지 못했습니다”).
- `parse_result` 형식은 docling 경로와 같게 맞춘다: `doc_type="spreadsheet"`, `doc_type_source="excel_ingest"`, `total_pages=시트 수`.

사진 연결 규칙의 세부(청크 위치 기준, 정렬, 집계 `summary_json.image_links`)는 `사진ID_청크연결_분석_v1.0.md` 3.1절 참고.

### 4.1 LCDocument 메타 (`excel_chunks.py:110-127`)

| 키 | 값 |
|---|---|
| `processing_engine` | `excel_ingest` |
| `chunk_key` | excel_ingest 청크 ID 원본 |
| `source_key` / `part_no` | 버전 무관 위치 키 / 조각 번호 |
| `sheet_name` / `sheet_index` | 시트 이름 / 시트 순번 |
| `block_type` = `chunk_type` = `content_type` | summary·step·table_section … |
| `source_range` | 표: `"시작행:끝행"`, 안내문: 도형 셀 범위, 그 외 None |
| `display_markdown` | 조각 텍스트와 같음(출처 표시용) |

## 5. 임베딩 (EmbedStep — `ingest_pipeline.py:224`)

네 가지를 **동시에**(asyncio.gather) 만든다. 입력은 모두 청크 `page_content`(머리말 포함 텍스트)다.

| 벡터·값 | 방법 | 코드 |
|---|---|---|
| **Dense** | GPU 서버 vLLM `/v1/embeddings`(OpenAI 호환), 배치 `EMBEDDING_BATCH_SIZE`(32). **문서에는 instruct 접두어 없음**. `EMBEDDING_MAX_MODEL_LEN×3`자 초과 시 잘라 내고 서버에도 `truncate_prompt_tokens` 전달. 결과 수 ≠ 청크 수면 실패 | `clients/embedding_client.py embed_texts` |
| **Kiwi BM25** | Kiwi 형태소 토큰을 공백으로 이은 텍스트 → Qdrant `Document(model="qdrant/bm25")`. 컬렉션의 IDF 수정자로 서버에서 점수 계산 | `clients/kiwi_bm25_encoder.py encode_document` |
| sparse(선택) | `SPARSE_ENCODER_TYPE`가 `none`이 아니면 BM42/SPLADE. 실패해도 건너뜀 | `_encode_sparse` |
| 시맨틱 보강(선택) | `ENABLE_SEMANTIC_ENRICHMENT`(요청값 우선)면 LLM으로 summary·keywords·topics·intent 추출. 실패해도 건너뜀 | `parsers/semantic_enricher.py` |

### 6.4 적재와 DB 기록 순서 — `ingest_pipeline.py IndexStep.run`

1. `ensure_collection` → `upsert_points`(100개씩).
2. (최신본 변경이면) 새 버전 점 수 = 청크 수인지 확인 → 버전 `ready`.
3. `instance/chunk/{컬렉션}/{document_id}/…_chunks.md` 확인용 기록.
4. **한 트랜잭션:**
   - 새 문서: `tb_documents` INSERT + `doc_key`·`product_model` / 최신본 변경: `activate_version`(이전 active → retired, `tb_documents.version_no` 갱신)
   - `_commit_resources`: **사진 원본 파일 저장**(`write_excel_images`) + `tb_spreadsheet_resources` INSERT
   - `tb_document_versions`(새 문서는 v1 active, `summary_json`=excel 요약 + `image_links`)
   - `tb_chunks`(청크 텍스트·위치·`point_id`·`meta_json`)
   - `tb_chunk_resources(chunk_id, resource_id, sort_order)` — 사진 행이 있을 때만
   - `tb_flow_graphs`
5. 최신본 변경이면 전환 후 이전 버전 점 삭제 → `vectors_purged_at` 기록.
6. 실패 보상: 새 문서는 Qdrant 점·리소스 파일 삭제, 최신본 변경은 그 버전 점·사진 폴더만 삭제하고 기존 최신본 유지.

## 9. 검색 (질문 → 컨텍스트)

LangGraph 그래프 `graphs/rag_graph.py`. 엑셀 사진과 관련된 노드 중심으로 정리한다.

### 9.1 질의 준비

- `analyze_and_rewrite`: LLM 1회로 검색용 재작성 질의(`rewritten_queries`) 생성, 임베딩을 병렬 계산. 실패하면 원 질의 사용.
  질의 임베딩에는 Qwen3 instruct 접두어(`EMBEDDING_INSTRUCT_TEMPLATE`)를 붙인다.
- `build_metadata_filter` (`graphs/nodes/build_metadata_filter.py`): 사용자 권한으로 **must 필터** 생성
  - `source_collection` ∈ 접근 가능 컬렉션(요청 컬렉션과 교집합, 없으면 차단)
  - `security_level` ∈ 사용자 최대 등급 이하(`SECURITY_HIERARCHY`)
  - 사용자별 추가 `metadata_filters`
  - 비로그인: `public` + `ANONYMOUS_DEFAULT_COLLECTIONS`

### 9.2 retrieve — `graphs/nodes/retrieve.py` → `vector_repository.search_hybrid`

- Qdrant Query API 한 번 호출:
  - prefetch: 재작성 질의마다 Dense 1개(`limit=max(candidate_top_k, DENSE_PREFETCH_K=80)`) + Kiwi BM25 1개(80)
  - 모든 prefetch에 같은 권한 필터 + **활성 버전 필터**(`services/version_visibility.py`: 이전 버전 점이 남은 문서는 `version_no ≠ 활성 버전` 제외)
  - 결합: weighted RRF(`HYBRID_RRF_K`=60). Dense 가중치는 질의 수로 나눠 총합 유지. 질의 유형별 가중치 `RRF_WEIGHTS`(법령·개념·메뉴·사고 사례)
- `apply_soft_boost`: payload `keywords`·`tags`가 질의 키워드와 겹치면 점수 배율 가산(시맨틱 보강을 꺼 두면 효과 없음)
- 상위 `CANDIDATE_TOP_K`(40)개 → `ChunkResult{chunk_id=point_id, document_id, text, score, metadata=payload 전체}`

### 9.3 rerank — `graphs/nodes/rerank.py`

- 입력 텍스트: `[문서명] … / [섹션] … / [본문] text`. 엑셀 청크는 `filename`·`header_path`·`section_title`이 payload에 없어서 **접두어 없이 본문(머리말 포함)만** 들어간다.
- 상위 `RERANKER_TOP_K`(10). 재랭커 장애 시 상위 `RERANKER_DEGRADED_TOP_K`(3)개만 통과.

### 9.4 assemble_context — `graphs/nodes/assemble_context.py`

1. `RELEVANCE_THRESHOLD`(0.25) 미만 제거
2. 텍스트 해시 중복 제거
3. **문서당 최대 `CONTEXT_MAX_CHUNKS_PER_DOCUMENT`(기본 2)개**, 전체 `CONTEXT_TOP_K`(6)개
4. 형식: 스프레드시트는 `[번호] [파일명] {sheet_name} {source_range}\n{display_markdown}`
5. 글자 수(`MAX_CONTEXT_CHARS`)·추정 토큰 예산을 넘는 청크는 건너뜀
6. 결과: `final_context`, `context_chunks`(LLM에 실제로 넘긴 순서) → 이후 출처 번호·사진 후보의 기준

- 비스트리밍 응답·대화 이력에도 `images` 저장

### 10.5 화면 표시 — `adrag_frontend`

- `src/utils/textFormat.js`: 답변의 `[IMG:ref]` → 그 메시지 사진 뷰어를 여는 번호 배지(images 목록에 없는 ref는 지움)
- `src/views/ChatView.vue`, `src/components/CitationPanel.vue`: `GET /api/spreadsheet-resources/{resource_id}`를 blob으로 받아 표시
- 출처 패널의 문서별 사진 목록: `GET /api/documents/{document_id}/spreadsheet-resources`

### 10.6 사진 API 권한 — `routes/spreadsheet_resources.py _authorize_document`

- 사진 → 문서 → 컬렉션을 조회하고, 관리자가 아니면 **사용자 접근 컬렉션 + 보안등급**을 다시 확인(아니면 403, 삭제 문서면 404).
- 답변 단계에서 이미 권한 필터를 통과한 청크의 **같은 문서** 사진만 후보가 되므로, 권한 없는 사진은 후보·응답·이미지 API 어디에도 나오지 않는다(CLAUDE.md 절대 규칙 8).

## 11. 확인한 사항과 주의점

| # | 내용 | 영향 | 근거 |
|---|---|---|---|
| N-1 | **문서당 컨텍스트 최대 2청크**(`CONTEXT_MAX_CHUNKS_PER_DOCUMENT=2`). SOP 한 문서에서 여러 Step을 묻는 질문이면 3번째 Step부터 LLM에 안 들어가고, 그 Step 사진도 후보가 되지 않는다 | 절차 전체를 묻는 질문의 답변·사진 누락 가능 | `assemble_context.py`, `config.py:118` |
| N-2 | 재랭커 입력의 `[문서명]`은 payload `filename`을 읽는데 payload에는 `original_filename`만 있다. 엑셀은 `header_path`가 비어 있고, `section_title`은 시맨틱 보강을 켰을 때만 LLM 값으로 채워진다(개발 환경은 켜져 있음, `payload_구조_사진ID_조회_분석_v1.0.md` P-4) | 재랭킹 점수에 파일명 정보 없음 | `rerank.py:47-67`, `metadata_schema.py:84` |
| N-3 | 모델명은 payload 필드가 아니라 텍스트 머리말에만 있다. 모델명으로 필터 검색을 하려면 payload 필드·인덱스 추가가 필요 | 지금은 점수로만 반영 | `excel_chunks.py`, `metadata_extractor.py` |
| N-4 | `title`은 첫 청크 첫 줄(예: `[모델 > 시트 > 개요]`)이다. 화면에 문서 제목으로 쓰면 어색할 수 있음 | 표시 | `ingest_pipeline.py IndexStep`, `extract_doc_title` |
| N-5 | `ROLE_PRIORITY`의 `same_image_as_step_photo`는 실제로는 파서 `link_method` 값이라 `role_cd`로는 나오지 않는다(보정된 확대도는 `detail_view`로 남음). 동작에는 문제 없음 | 없음(코드 정리 대상) | `parser.py _fix_detail_views`, `images.py:27` |
| N-6 | 시맨틱 보강을 끄면 payload `keywords`가 비어 soft boost가 작동하지 않는다 | 순위 영향 없음 | `retrieval_engine.py apply_soft_boost` |
| N-7 | emf·wmf 사진은 저장은 되지만 답변·화면에 나오지 않는다(변환은 Phase 5) | 해당 사진 미표시 | `resource_labels.py DISPLAYABLE_MIME_TYPES` |
| N-8 | 답변 사진 연결은 payload 기준이라 `tb_chunk_resources`만 고쳐서는 바뀌지 않는다. 바꾸려면 재등록 | 운영 수정 방법 | `images.py _lookup_resources` |

N-1·N-2·N-3은 동작 변경이 필요한 항목이라 구현하지 않았다. 바꿀지는 결정이 필요하다.
