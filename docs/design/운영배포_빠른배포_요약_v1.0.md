|---|---|

## A. 화면(frontend)만 — 처음부터 끝까지

**① 화면 빌드 — PC, Windows PowerShell**
```powershell
cd D:\Dev\SVNLocal\advanced-rag-voucher\adrag_frontend
npm run build          # package.json 을 바꿨으면 npm ci 먼저. "500 kB" 경고·빨간 NativeCommandError 줄은 무시
```

**② 묶음 만들기 — PC, WSL (1~2분)**
```bash
cd /mnt/d/Dev/SVNLocal/advanced-rag-voucher

**③ 올리기** — 수도권 SSL VPN → WinSCP SFTP `<WAS_IP>`:22 `sychoi`, **바이너리 모드**
PC 결과 폴더 → 서버 `/mnt/a/chatbot/offline/`: `chatbot-<버전>.tar.gz` · `chatbot-<버전>.tar.gz.sha256` · `deploy.sh`

**⑤ 반영**

# 성공: "== 0-1. 백업 …_frontend" → 마지막 "배포 끝: … restart 필요 없음"
```

**⑥ 확인**
- [ ] 브라우저 **Ctrl+F5** → 로그인 → 바꾼 화면 → 질문 1건(답변·사진·출처)
- [ ] `tail -1 /opt/yest/chatbot/DEPLOYED` → 이번 묶음 `frontend`

**⑦ 되돌리기 (restart 없음)**

→ 브라우저 Ctrl+F5.

## B. 백엔드(backend)만 — 처음부터 끝까지

**① 화면 빌드 — 생략.** 묶음은 PC의 `adrag_frontend\dist`를 그대로 담지만 서버에서 `--backend-only`라 운영 화면은 안 바뀐다. (`dist`가 아예 없다는 오류가 나면 A①을 한 번 한다.)

**② 묶음 만들기 — PC, WSL**
```bash
cd /mnt/d/Dev/SVNLocal/advanced-rag-voucher
bash deploy/webwas/chatbot/build_package.sh --skip-frontend-build
# requirements.txt·Dockerfile.runtime 을 바꿨으면 끝에 --with-image (수백 MB~수 GB)
```

**②-1 런타임 이미지 태그 확인 (10초)**
```bash
cd deploy/webwas/mnt/a/chatbot/offline
for f in $(ls -t chatbot-*.tar.gz | head -2); do v=${f%.tar.gz}; echo "$v: $(tar -xzOf $f $v/RUNTIME_IMAGE)"; done
```
두 줄의 태그가 같으면 진행. 다르면 `--with-image`로 다시 묶는다(주석만 바뀐 경우는 부록 A).

**③ 올리기** — A③과 같다(3개 파일, 바이너리 모드).

**④ 확인·기록 — 서버(sychoi)**
```bash
cd /mnt/a/chatbot/offline
sha256sum -c chatbot-<버전>.tar.gz.sha256        # OK
grep -c "0-1. 백업" deploy.sh                   # 1
tail -3 /opt/yest/chatbot/DEPLOYED 2>/dev/null   # 지금 운영 판

# 지금 DB revision 적어 두기 (DB 되돌릴 때 필요)
DC="sudo docker compose --env-file /opt/yest/chatbot/compose.env -f /opt/yest/chatbot/docker-compose.prod.yml"
$DC run --rm --no-deps backend alembic current      # 예: 0005_... (head)

# 이번 묶음에 DB 변경(새 revision)이 있는지 — 출력이 없으면 DB 변경 없음, "> 0006_….py" 처럼 나오면 있음
diff <(ls /opt/yest/chatbot/backend/migrations/versions | grep '\.py$') \
     <(tar -tzf chatbot-<버전>.tar.gz | grep -o 'migrations/versions/[^/]*\.py$' | cut -d/ -f3 | sort)
```
- [ ] 관리 화면 **문서 관리**에 등록 처리 중인 문서가 없는지 확인한다(적재 큐가 프로세스 안에 있어 restart 하면 끊긴다).

**⑤ 반영 (백업 + DB 업그레이드 자동)**
```bash
chmod +x deploy.sh
./deploy.sh --backend-only chatbot-<버전>.tar.gz
# 성공: "== 0-1. 백업 …_backend" → "== 5. DB 스키마" → "config ok" → 마지막 "배포 준비 끝: … 다음: sudo systemctl restart chatbot"
```
실패하면 그 단계에서 멈추고 **실행 중인 서비스는 옛 코드 그대로**다(restart 하지 말고 원인부터 본다).
"…가 묶음의 config/… 와 다릅니다" 알림이 나오면 수정배포 가이드 4.5 표대로 해당 파일만 복사한다.

**⑥ 재시작**
```bash
sudo systemctl restart chatbot && sleep 5 && curl -s http://127.0.0.1:8081/health     # healthy
sudo docker ps --filter name=chatbot_backend                                          # (healthy)
```

**⑦ 확인**
- [ ] 브라우저 로그인 → 바꾼 기능 → 질문 1건(답변·사진·출처)
- [ ] `/mnt/a/chatbot/logs/<날짜>_LOG_ERROR.log`에 새 오류 없음
- [ ] `tail -1 /opt/yest/chatbot/DEPLOYED` → 이번 묶음 `backend` + 이미지 태그

**⑧ 되돌리기 (restart 필요)**

| 상황 | 명령 |
|---|---|
| 가. DB 변경 없었음(④ diff 출력 없음) | `./deploy.sh --backend-only chatbot-<이전 버전>.tar.gz` → `sudo systemctl restart chatbot` |
| 나. DB 변경 있었음 | ① 새 판 상태 그대로 `$DC run --rm --no-deps backend alembic downgrade <④에서 적은 revision>` ② `SKIP_MIGRATE=1 ./deploy.sh --backend-only chatbot-<이전 버전>.tar.gz` ③ restart |
| 다. 이전 묶음이 없음 | 아래 백업 복원 (DB 변경이 있었으면 나.의 ①을 먼저) |

```bash
B=$(ls -1d /mnt/a/chatbot/backup/*_{backend,all} 2>/dev/null | sort | tail -1); echo $B
R=$(mktemp -d) && tar -C "$R" -xzf "$B/backend.tar.gz" && rsync -rlt --delete --exclude /instance/ "$R/backend/" /opt/yest/chatbot/backend/ && rm -rf "$R"
find /opt/yest/chatbot/backend -user "$(id -un)" -exec chmod g+rX,g-w,o-rwx {} +
cp "$B/compose.env" /opt/yest/chatbot/compose.env          # 이미지 태그도 그때로
sudo systemctl restart chatbot && sleep 5 && curl -s http://127.0.0.1:8081/health
```
(같은 명령이 백업 폴더의 `RESTORE.txt`에도 있다.)

## 부록 A. 런타임 이미지 태그만 바뀐 경우 (이미지 재전송 없이)

`Dockerfile.runtime`의 주석만 바꾸면 이미지 내용은 같아도 태그가 바뀐다. 이때 서버의 `deploy.sh`는 "서버에 … 가 없고 묶음에도 이미지가 없습니다"라며 1단계에서 멈춘다.

1. **PC(WSL):** `docker image ls chatbot-backend-runtime` → 두 태그의 IMAGE ID가 같아야 한다. 다르면 `--with-image`로 다시 묶는다.
2. **서버:** `sudo docker image inspect --format '{{.Id}}' chatbot-backend-runtime:<직전 태그>` → 1번과 같아야 한다.
3. **서버:** `sudo docker tag chatbot-backend-runtime:<직전 태그> chatbot-backend-runtime:<새 태그>` (복사 아님, 용량 그대로)
4. B⑤ `deploy.sh`부터 진행한다.

예: 2026-11-02 배포. `cb63162cffc3` → `8e9be33989fa`. 주석만 바뀌었고 IMAGE ID는 같았다(`8257cfefdde8`).
