## 1. 목표

답변 하단 **관련 이미지**를 "LLM이 인용한 사진"에서 **"답변이 인용한 출처 청크의 연결 사진(payload `resource_ids`)"**으로 바꾼다.

| 보장할 것 | 내용 |
|---|---|
| G-1 포함 관계 | 관련 이미지는 **언제나** 참고 문서 카드 연결된 이미지의 일부다(출처 카드에 없는 사진은 나오지 않음) |
| G-2 결정적 동작 | 같은 검색·인용 결과면 같은 사진·같은 순서. LLM의 `[IMG:ref]` 인용 여부와 무관하게 사진이 나온다 |
| G-3 화면 혼잡 방지 | 하단은 최대 `RAG_MAX_IMAGES`장. 나머지는 "전체 N장 보기"로 출처 패널에서 본다 |
| G-4 중복 없음 | 같은 그림(`content_hash` 동일)은 하단·출처 카드 모두 1장 |
| G-5 기존 동작 보존 | 설정값 기본은 지금 동작(`llm`). 끄면 즉시 원래대로 |

남는 차이는 **상한(4장) 하나**뿐이다. 화면에서는 "관련 이미지 4 / 전체 7"로 드러낸다.

---

## 2. 바뀌는 흐름 한눈에

```
[지금]  컨텍스트 청크 전부 → 후보 8장(질의어 정렬) → LLM [IMG:ref] 인용분만 → 0건이면 자동 첨부 1장
[변경]  답변에 [n] 인용된 청크(출처 카드와 동일) → resource_ids 순서 그대로 → 같은 그림 합침
        → LLM이 [IMG:ref]로 인용한 사진을 맨 앞으로 → 앞에서 최대 4장 + 전체 장수(total)
```

- `[IMG:ref]` 인용은 **선택 기준이 아니라** 본문 배지와 순서 앞당기기에만 쓴다.
- 자동 첨부(C-4)는 출처 기준 모드에서 필요 없다. 인용 청크에 사진이 있으면 항상 나온다.

## 3. 설정값

| 설정(환경변수) | 값 | 기본 | 설명 |
|---|---|---|---|
| `ANSWER_IMAGE_SOURCE` (신규) | `llm` / `citation` | `llm` | `llm` = 지금 동작. `citation` = 출처 기준 |
| `RAG_MAX_IMAGES` (기존) | 정수 | 4 | 하단 최대 장수(두 모드 공통) |
| `RAG_IMAGE_CANDIDATES` (기존) | 정수 | 8 | LLM 프롬프트 사진 후보 수(본문 배지용, 두 모드 공통) |
| `ANSWER_IMAGE_AUTO_ATTACH` (기존) | bool | true | `llm` 모드에서만 의미. `citation` 모드에서는 무시 |

- `app/core/config.py` 사진 설정 묶음에 `answer_image_source: Literal["llm", "citation"] = "llm"` 추가, `.env.example`에 이름·설명만 추가.
- 개발 환경에서 `citation`으로 켜서 확인한다. 운영 반영 여부는 확인 후 결정.

## 4. 백엔드 변경

### 4.1 `app/graphs/images.py`

| 변경 | 내용 |
|---|---|
| ref 생성 함수 분리 | `collect_image_candidates` 안의 ref 생성 루프를 `_assign_refs(resources, used_refs)`로 빼서 두 모드가 같은 규칙으로 ref를 만든다(본문 배지 호환) |
| 신규 `collect_citation_images(cited_chunks, *, cited_refs, candidates, max_images, db)` | ① 인용 청크를 **출처 번호 순**으로 돈다 ② 각 청크의 `resource_ids`로 `_lookup_resources` 조회(**행 범위 대체 조회는 쓰지 않음** — 7절 Q-3) ③ `_image_key`로 같은 그림 합침(먼저 나온 것 유지) ④ LLM이 인용한 ref의 사진을 앞으로 ⑤ 후보에 있던 사진은 그 ref를 재사용, 없으면 `_assign_refs`로 새 ref ⑥ 반환 `(images[:max_images], total)` |
| `_lookup_resources` | 인자 `allow_row_fallback: bool = True` 추가. 출처 기준 모드는 `False`로 호출. 기존 호출은 그대로 |
| 응답 필드 | 각 사진에 `citation_id`(어느 출처 카드의 사진인지) 추가, `_PUBLIC_FIELDS`에 포함. `cited`는 "LLM 본문 인용 여부"로 의미 유지 |

- DB 오류는 지금처럼 경고만 남기고 빈 목록(답변은 계속).
- 권한: 인용 청크는 이미 검색 단계 권한·활성 버전 필터를 통과했고, 조회는 청크와 같은 문서·현재 버전만 본다(지금과 같음, 규칙 8 유지).

### 4.2 `app/graphs/nodes/format_citations.py`

- 출처 카드(`citations`)를 만든 뒤 사진을 정한다. 출처 카드와 같은 `context_chunks[citation_id-1]` 목록을 그대로 넘겨 G-1을 코드 구조로 보장한다.
- `citation` 모드:
  1. `validate_answer_images`를 `auto_step_image=False`, `max_images=후보 수`로 호출 → 후보 밖 태그 제거, LLM 인용 ref 목록 확보
  2. `collect_citation_images(...)` 호출 → `answer_images`, `answer_images_total`
  3. **하단 목록에 없는 `[IMG:ref]` 태그는 답변에서 지운다.** 예: 인용 안 된 컨텍스트 청크의 사진(C-6), 4장 밖으로 밀린 사진. 본문 배지 번호는 하단 번호와 항상 일치한다
  4. `outcome_code != "success"`(근거 없음 등)면 사진 없음(지금 자동 첨부 조건과 같음)
- `llm` 모드: 지금 코드 그대로.

### 4.3 `app/graphs/nodes/collect_answer_images.py`

- 변경 없음. 후보 수집·프롬프트 블록은 두 모드 공통(본문 배지를 위해 유지).

### 4.4 상태·응답·이력

| 파일 | 변경 |
|---|---|
| `app/graphs/state.py` | `answer_images_total: int` 추가(초기값 0) |
| `app/models/data_models.py` `QueryResponse` | `images_total: Optional[int] = None` 추가 |
| `app/services/rag_service.py` | 비스트림 응답(214행 부근)·이력 저장(316행 부근)에 `images_total` 추가. SSE `images` 이벤트(431행 부근)는 `{"type":"images","data":images,"total":n}` — `data` 모양은 그대로 두어 기존 화면과 호환 |
| `llm` 모드 | `images_total = len(images)` 로 채워 두 모드 화면 처리를 같게 한다 |

- 이전 대화 이력에는 `images_total`이 없다 → 화면은 `images.length`로 대체(5.2).
- DB 스키마 변경 없음(이력은 기존 JSON 컬럼에 필드만 추가) → **Alembic 마이그레이션 없음**.

## 5. 프런트 변경 (주석 규칙: `2026.11.xx(sooyeon.choi) 추가/수정 - 설명`)

- 버튼은 `emit('openSources')` → `ChatView.vue`가 그 메시지의 출처 패널을 열고, 사진이 있는 첫 출처 카드를 선택한다(기존 `selectCitation` 흐름 재사용).
- 카드 위치 표시에 출처 번호 `[n]`을 함께 보여 출처 카드와 연결되게 한다(`image.citation_id`).

- SSE `images` 이벤트의 `event.total`, 비스트림 `res.data.images_total`, 이력 `h.images_total`을 메시지 `imagesTotal`로 저장. 값이 없으면 `images.length`.

### 5.3 `src/components/CitationPanel.vue` (UI-05) — 개수 차이 분석의 B·C안

- `linkedImages`: **`citation.resource_ids` 순서로 정렬**(S-1 해소)하고, 카드 안에서 **`content_hash`가 같은 사진은 1장만**(C-3 해소). 문서 사진 목록 API는 이미 `content_hash`를 준다.
- 하단 관련 이미지와 같은 순서·같은 합침 규칙이라 하단 4장이 카드 앞쪽과 일치한다.

- `src/utils/textFormat.js`: 본문 `[IMG:ref]` 배지는 `msg.images`에서 ref로 찾는 구조 그대로 동작.
- `ImageViewer.vue`: 그대로.
