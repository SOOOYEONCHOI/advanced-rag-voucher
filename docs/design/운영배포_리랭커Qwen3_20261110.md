# 리랭커 비교 모델 Qwen3-Reranker-0.6B 추가 배포 (GPU 서버 yest-gpu, 2026-11-10)

> 기존 리랭커 bge-reranker-v2-m3(8103)와 검색 품질을 비교하는 용도. 운영 서비스(LLM·임베딩·리랭커·ASR·docling·VLM)는 건드리지 않는다.
> 기본 절차·계정·권한은 `운영배포_가이드_서버별_v1.1.md` §1, 형식은 `운영배포_VLM테스트_20261105.md`를 따른다. 이 문서는 추가분만 적는다.
> 2026-11-10: GPU 2·3번을 써도 된다는 사용자 확인이 있어 **GPU 2**에 올린다.

## 0. 배치

| GPU | 서비스 | systemd | 포트 | `--gpu-memory-utilization` | 모델(`--served-model-name`) | 모델 경로 |
|---|---|---|---|---|---|---|
| 2 | 리랭커 비교 | `vllm@rerank-qwen` | 8104 | 0.10 (약 8GB) | `Qwen3-Reranker-0.6B` (max-model-len 8192) | `/mnt/a/chatbot/models/reranker/Qwen3-Reranker-0.6B` |

- GPU 0(LLM·docling 약 58GB)·GPU 1(임베딩·리랭커·ASR·VLM, 비율 합계 0.73)은 그대로 둔다.
- 포트: 8000(MAIP Wezard)·8101~8103·8107~8110은 사용·예약 중이라 리랭커 옆 8104를 쓴다.
- 키: 기존 `RERANKER_API_KEY`를 같이 쓴다. `env.sh`·WAS `.env` 키는 바꾸지 않는다.
- 비교용이라 `enable`(부팅 시 자동 시작)하지 않는다. bge를 대신하기로 정하면 그때 enable하고 WAS `.env`를 바꾼다(5절).

## 3. 서버(yest-gpu, sychoi)에서 설치

### 3.1 GPU 2·포트 비어 있는지 확인

```bash
nvidia-smi --query-gpu=index,memory.used,memory.total --format=csv   # GPU 2 가 0MiB 근처여야 한다
nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name,used_memory --format=csv   # GPU 2 에 다른 팀 프로세스가 없는지
ss -ltnp | grep -E ':8104\b'                                          # 아무것도 안 나와야 한다
```

GPU 2에 다른 프로세스가 있으면 **여기서 멈추고** 보고한다(GPU 3으로 바꿀지 결정).

### 3.2 모델 폴더

```bash
cd /mnt/a/chatbot/offline/vllm/models/Qwen3-Reranker-0.6B && sha256sum -c SHA256SUMS   # 모두 OK
sudo cp -r /mnt/a/chatbot/offline/vllm/models/Qwen3-Reranker-0.6B /mnt/a/chatbot/models/reranker/
sudo namei -l /mnt/a/chatbot/models/reranker/bge-reranker-v2-m3/config.json      # 비교용(보기만)
sudo namei -l /mnt/a/chatbot/models/reranker/Qwen3-Reranker-0.6B/config.json
sudo -u vllm-admin find /mnt/a/chatbot/models/reranker/Qwen3-Reranker-0.6B -type f ! -readable   # 아무것도 안 나오면 OK
```

**읽기 불가가 나오면 여기서 멈추고** `namei -l` 결과를 담당자와 보고 정한다. 기존 모델 폴더와 `/mnt/a` 등 상위 경로는 `chown`·`chmod`·`setfacl`을 하지 않는다(2026-11-05 결정).

### 3.3 실행 파일


### 3.5 기동 실패 시

`sudo tail -n 100 /mnt/a/chatbot/vllm/logs/rerank-qwen-error.log`

| 증상 | 조치 |
|---|---|
| `hf_overrides` / `is_original_qwen3_reranker` 관련 오류 | vLLM 0.30.0 에서 옵션 이름이 바뀌었을 수 있음 — 오류 문구와 함께 보고 |
| `--attention-backend` 관련 오류 | `run-rerank-qwen.sh`에서 그 줄을 지우고 restart |
| `Free memory on device ... is less than desired` | GPU 2를 다른 프로세스가 쓰는 중 — 3.1 다시 확인 후 보고 |
| `Permission denied` (모델 파일) | 3.2 `namei -l` 결과로 새 폴더만 확인 |

### 3.6 확인

```bash
read -s K                                                        # RERANKER_API_KEY 를 기록 없이 입력
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8104/v1/models          # 401 (키 없음)
curl -s -H "Authorization: Bearer $K" http://127.0.0.1:8104/v1/models | head -c 200; echo
curl -s http://127.0.0.1:8104/v1/score -H "Content-Type: application/json" -H "Authorization: Bearer $K" \
  -d '{"model":"Qwen3-Reranker-0.6B","text_1":"볼트 체결 토크는?","text_2":["볼트는 규정 토크로 체결한다.","점심 메뉴는 김치찌개다."]}'
# 첫 번째 점수가 두 번째보다 확실히 높아야 한다(0~1 사이). 둘이 비슷하면 hf-overrides 가 안 먹은 것
for p in 8101 8102 8103 8107; do curl -s -o /dev/null -w "$p %{http_code}\n" http://127.0.0.1:$p/v1/models; done   # 기존 서비스 401
```

**GPU 서버 밖(WAS·개발 PC)에서 부르려면** ACG F-4 인바운드에 TCP 8104를 추가해야 한다.

## 4. 비교 방법 (백엔드 코드 변경 없음)

`reranker_client.py`는 vLLM `/v1/score`를 부르므로 주소·모델 이름만 바꾸면 된다.

| WAS `.env` | bge (현재) | Qwen3 (비교) |
|---|---|---|
| `RERANKER_API_URL` | `http://<GPU_IP>:8103` | `http://<GPU_IP>:8104` |
| `RERANKER_MODEL_NAME` | `bge-reranker-v2-m3` | `Qwen3-Reranker-0.6B` |

- 운영 `.env`를 바꾸기 전에 평가 러너(`app/evaluation/`)로 같은 질문셋에서 두 모델의 검색 정답률·지연 시간을 먼저 비교한다.
- Qwen3-Reranker는 지시문 형식 입력을 기준으로 학습됐다. 질문·문서를 그대로 넣는 현재 방식에서 점수가 떨어질 수 있으므로 비교 결과로 판단한다.

## 5. 운영·되돌리기

| 할 일 | 명령 |
|---|---|
| 멈춤 | `sudo systemctl stop vllm@rerank-qwen` (GPU 2 메모리 즉시 반환) |
| GPU 3으로 옮기기 | `run-rerank-qwen.sh`의 `CUDA_VISIBLE_DEVICES=3` → 다시 올려 3.3 → `sudo systemctl restart vllm@rerank-qwen` |
| bge 대신 쓰기로 정함 | `sudo systemctl enable vllm@rerank-qwen` → WAS `.env` 4절 값으로 변경(수정배포 가이드 4.8) → ACG 8104 확인 |
| 완전히 제거 | `sudo systemctl stop vllm@rerank-qwen` → `sudo rm /opt/yest/chatbot/vllm/app/run-rerank-qwen.sh` |

다른 서비스 설정·`vllm@.service`·`env.sh`는 바꾸지 않았으므로 위 단계만으로 원래 상태가 된다. 모델 폴더는 남겨 둔다.
