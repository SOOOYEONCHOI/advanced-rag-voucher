의존 순서대로 한다. 뒤 서버가 앞 서버에 연결한다.

### 0.4 모든 서버 공통 규칙

| 항목 | 규칙 |
|---|---|
| 계정 | 관리 계정 `sychoi`(sudo)로 작업한다. **`docker` 그룹에 넣지 않는다**(root와 같은 권한) → `sudo docker`로 쓴다 |
| 실행 계정 | 앱은 로그인 불가 서비스 계정으로 돈다: WAS `chatbot`, Vector DB `qdrant`, GPU vLLM `vllm-admin`, GPU docling `adrag` |
| 폐쇄망 | 서버는 인터넷에 나가지 않는다. 설치 파일·이미지·모델은 개발 PC(WSL)에서 만들어 반입한다. 서버에서는 빌드하지 않는다 |
| 반입 폴더 | 각 서버 `/mnt/a/chatbot/offline/` (`sychoi:sychoi 750`). OS 디스크(`/`)가 아니라 데이터 볼륨(`/mnt/a`)에 받는다 |
| 전송 | 남부권(GPU)·수도권(WAS·Vector DB) SSL VPN 연결 → **WinSCP SFTP, 바이너리 모드**(텍스트 모드는 `.sh`를 CRLF로 바꾸고 tar.gz 체크섬을 깬다). 끊기면 "이어 받기" |
| 체크섬 | 풀기 전에 항상 `sha256sum -c`. 출력에 `OK`가 아닌 줄이 있으면 멈춘다 |
| 서비스 조작 | `docker compose up/down`을 직접 쓰지 않고 **항상 `sudo systemctl start|stop|restart <서비스>`** |
| 비밀 값 | `.env`·`env.sh`는 편집기(`vi`)로 넣는다(셸 기록에 남지 않게). 문서·메신저에 남기지 않는다 |
| 마운트 폴더 | 컨테이너에 붙이는 서버 폴더는 **미리 만든다.** 없으면 Docker가 root 소유로 만들어 앱이 쓰지 못한다 |
| Docker 데이터 | `/etc/docker/daemon.json`의 `data-root`를 `/mnt/a/docker`로 둔다(이미지가 수~십 GB) |

### 0.6 개발 PC 폴더 — 서버 경로를 그대로 본뜬다 (2026-10-30 정리)

반입·설정 파일은 모두 저장소 `deploy/<서버>/` 아래, **서버에 놓일 경로 그대로** 둔다. 예: `deploy/gpu/etc/systemd/system/vllm@.service` → 서버 `/etc/systemd/system/vllm@.service`, `deploy/webwas/mnt/a/chatbot/offline/` → 서버 `/mnt/a/chatbot/offline/`.

│   ├── opt/yest/chatbot/docling/       docker-compose.yml, .env(실제 값), .env.example
│   ├── tools/                   개발 PC용: download_gpu_debs.sh, download_vllm_wheels.sh, docling-warmup/
│   └── mnt/a/chatbot/offline/   docker-nvidia-…tar.gz, docling-parser_…tar.gz, vllm/vllm-wheels_0.30.0.tar (+ .sha256)
├── vector-db/                   yest-vector-db
│   ├── etc/…  opt/…             qdrant.service, docker-compose.yml, compose.env.example
│   ├── package_qdrant.sh        → mnt/a/chatbot/offline/ 에 묶음을 만든다
│   └── mnt/a/chatbot/offline/   qdrant-chatbot-1.18.2.tar.gz, SHA256SUMS.top
├── webwas/                      yest-web
│   ├── etc/…  opt/…             chatbot.service, chatbot.conf, docker-compose.prod.yml, .env·compose.env(실제 값)
│   ├── chatbot/                 build_package.sh · download_docker_rpms.sh · deploy.sh · Dockerfile.runtime · check_rocky.sh
│   └── mnt/a/chatbot/offline/   docker-rocky96-…tar.gz(+docker-rpms/), SHA256SUMS.top, chatbot-<버전>.tar.gz(+.sha256), deploy.sh

- 묶음 스크립트 3개(`build_package.sh`, `download_docker_rpms.sh`, `package_qdrant.sh`)의 기본 출력이 각 서버의 `mnt/a/chatbot/offline/`이다.

- `mnt/` 아래 큰 묶음과 `.env`·`env.sh`는 SVN에 올리지 않는다(이 폴더를 SVN에 넣을 때 `svn:ignore` — 7장 끝).

### 5.4 SELinux를 켤 때 (MAIP와 같은 날)

지금은 Disabled다. MAIP가 켜는 날 같이 하지 않으면 화면이 502·403, 컨테이너는 `/data` 쓰기 거부가 난다.

```bash
sudo dnf install -y policycoreutils-python-utils container-selinux
sudo semanage fcontext -a -t httpd_sys_content_t '/opt/yest/chatbot/frontend(/.*)?'
sudo semanage fcontext -a -t container_file_t '/opt/yest/chatbot/backend(/.*)?'
sudo semanage fcontext -a -t container_file_t '/mnt/a/chatbot/(data|logs|cache)(/.*)?'
sudo semanage fcontext -a -e /var/lib/docker /mnt/a/docker
sudo restorecon -Rv /opt/yest/chatbot /mnt/a/chatbot /mnt/a/docker
# httpd_can_network_connect 는 MAIP 가 켠다(nginx → 127.0.0.1). daemon.json 에 "selinux-enabled": true 추가 후 docker 재시작
sudo ausearch -m avc -ts boot | grep denied     # 비어 있어야 enforcing 으로
```
