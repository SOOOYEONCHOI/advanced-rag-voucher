# 도면 업로드 저장 구조 v1.0 — 원본 파일·파생 파일·메타데이터 전체

> 작성 2026-11-12 · 기준: Phase 6 1단계 구현(`docs/design/reports/phase-6.md`), dev 환경 실제 업로드 2건으로 확인(값은 적지 않고 구조만)
> 설정 이름: `UPLOADED_FILES_BASE_DIR`(원본 저장 폴더, dev `instance/data`), `RESOURCE_STORAGE_ROOT`(이미지, dev `/app/instance/xl_res`), `MD_SAVE_DIR`(확인용 md, dev `instance/parsed_md`)

## 0. 한눈에 보기

```
화면 업로드(.dwg/.dxf)
 ├─ [임시] {원본 폴더 상위}/db/ingest_jobs/{job_id}.dwg (+ .checkpoint)      성공 시 삭제
 ├─ [원본] {UPLOADED_FILES_BASE_DIR}/{연}/{월}/{YYYYMMDD}_{document_id}.dwg
 ├─ [파생] {UPLOADED_FILES_BASE_DIR}/drawing/{document_id}/v{n}/derived/
 │         converted.dxf · sanitized.dxf · drawing_ir.json · render/*.png
 ├─ [이미지] {RESOURCE_STORAGE_ROOT}/documents/{document_id}/resources/{resource_id}/original/{sha256}.png
 ├─ [md]   {MD_SAVE_DIR}/drawing/{doc_key}/{job_id}/summary.md
 └─ [DB]   tb_ingest_jobs · tb_documents · tb_document_versions · tb_spreadsheet_resources
           · tb_document_version_activations · (검수 시) tb_document_events
           저장 안 함: tb_chunks · Qdrant(임베딩)
```

## 1. 파일

### 1.1 업로드 임시 파일
| 항목 | 내용 |
|---|---|
| 경로 | `{UPLOADED_FILES_BASE_DIR의 상위}/db/ingest_jobs/{job_id}.{확장자}` (dev `instance/db/ingest_jobs/`) |
| 함께 생기는 것 | `{job_id}.{확장자}.checkpoint` — 단계별 진행 상태(재시도용, pickle) |
| 수명 | 작업 **성공 시 둘 다 삭제**. **실패하면 남는다**(같은 작업 [재시도]가 이어서 처리). 실패 작업을 재시도하지 않고 새로 올리면 그대로 쌓인다 |

### 1.2 원본(DWG·DXF)
| 항목 | 내용 |
|---|---|
| 경로 | `{UPLOADED_FILES_BASE_DIR}/{YYYY}/{MM}/{YYYYMMDD}_{document_id}.{확장자}` — 새 버전은 `…_{document_id}_v{n}.{확장자}` |
| DB 기록 | `tb_documents.source_path`·`stored_filename`, `tb_document_versions.source_path`·`stored_filename`·`file_sha256`·`file_size` (경로는 저장 폴더의 두 단계 위 기준 상대 경로, `/` 구분) |
| 내용 | 올린 파일 그대로(변경 없음). 목록의 파일명 링크(원본 열기)가 이 파일을 내려준다 |
| 수명 | 문서 삭제 시 삭제 |

### 1.3 파생 파일(버전 폴더)
경로: `{UPLOADED_FILES_BASE_DIR}/drawing/{document_id}/v{n}/derived/`

| 파일 | 만드는 단계 | 내용 | 비고 |
|---|---|---|---|
| `converted.dxf` | 변환 | LibreDWG `dwg2dxf` 출력 그대로 | DWG만. 원본 DWG보다 수 배 큼 |
| `sanitized.dxf` | 변환 | 핸들 0 사전 항목을 지운 DXF — 이후 단계가 읽는 파일 | DWG만 |
| `source.dxf` | 변환 | DXF로 올린 경우 원본 복사본(위 두 파일 대신) | DXF만 |
| `drawing_ir.json` | 추출(이미지 단계에서 경고·시간 덧씀) | **도면 처리 결과 원천**(2.6절). 처리 결과 화면·다음 단계 검색 적용이 읽는다 | `summary_json.drawing.ir_path`에 경로 |
| `render/full.png` | 이미지 | 전체 도면(긴 변 `DRAWING_RENDER_MAX_PX`, 기본 4000px) | 1.4의 이미지로 복사됨 |
| `render/preview.png` | 이미지 | 미리보기(긴 변 1600px) | 〃 |
| `render/{영역}.png` | 이미지 | 영역 크롭: `title_block`, `bom`, `revision` (찾은 영역만) | 〃 |
| `convert/` | 변환 중 | 변환기 작업 폴더(입력 복사본) | 변환 후 삭제 |

### 1.4 이미지(화면·API에서 쓰는 사본)
| 항목 | 내용 |
|---|---|
| 경로 | `{RESOURCE_STORAGE_ROOT}/documents/{document_id}/resources/{resource_id}/original/{sha256}.png` |
| resource_id | `{document_id}-v{n}-d01`부터 순서대로(전체 → 미리보기 → 크롭) |
| DB | `tb_spreadsheet_resources` 1행씩(2.4절) |
| 조회 | `GET /api/spreadsheet-resources/{resource_id}` — 문서 열람 권한 확인 후 내려줌 |
| 수명 | 문서 삭제 시 삭제 |

### 1.5 확인용 md
| 항목 | 내용 |
|---|---|
| 경로 | `{MD_SAVE_DIR}/drawing/{doc_key}/{job_id}/summary.md` (`doc_key` = 표제란 품번, 없으면 파일명) |
| 내용 | 표제란 필드, 용지·축척, 표(마크다운 표), 주기·일반공차·규격 메모, 치수, 기타 글자, 경고·정보 |

## 2. DB

### 2.1 `tb_ingest_jobs` — 작업 1건당 1행
| 컬럼 | 값 |
|---|---|
| `job_id`, `created_by`, `created_at`, `updated_at` | 작업 ID, 업로더 |
| `operation_type` | `ingest` |
| `status` | `queued` → `running` → `completed` / `failed` |
| `current_step` | `queued` → `validate` → `parse` → `drawing_convert` → `drawing_extract` → `drawing_render` → `drawing_store` → `completed` (도면 단계 4개는 마이그레이션 `0010`으로 허용) |

## 3. 수명 주기

| 상황 | 파일 | DB |
|---|---|---|
| 업로드 성공 | 임시 파일·체크포인트 삭제, 원본·파생·이미지·md 생성 | 2.1~2.5절 행 생성 |
| 단계 실패 | 임시 파일·체크포인트 **남음**. 이미 쓴 이미지 파일은 지움 | 작업 `failed`+`error_code`. 문서·버전·이미지 행 없음(저장 단계 트랜잭션 롤백) |
| [재시도] | 실패한 단계부터(변환 결과가 있으면 재변환 안 함) | 같은 `job_id` |
| 새 버전 등록 | 원본 `…_v{n}`, 파생 `v{n}/`, 이미지 `-v{n}-d…` 추가. 이전 버전 파일 유지 | 버전 행 추가(이전 `retired`), 적용 이력 `replace`, 문서 행 갱신(모델명·doc_key·업로더 유지) |
| 검수 완료/취소 | 없음 | `summary_json.drawing.review` 갱신 + 이벤트 1행 |
| 문서 삭제 | 원본·이미지 삭제. **파생 폴더 `drawing/{document_id}/`와 md는 남음** | 문서 소프트 삭제, 버전 `retired`, 이미지 행 삭제 |

## 4. 실제 업로드로 확인한 것(dev, 2건)

| 항목 | 결과 |
|---|---|
| 저장 위치 | 1~2절과 같음(원본 `instance/data/2026/11/…`, 파생 `instance/data/drawing/{id}/v1/derived/`, 이미지 `instance/xl_res/documents/{id}/resources/{id}-v1-d01~d03/`, md `instance/parsed_md/drawing/{품번}/{job_id}/`) |
| 이미지 | 도면당 3장(전체·미리보기·**표제란 크롭만**) |
| 경고 | `W_SANITIZED`·`W_CONVERTER_WARN`·`W_FONT_FALLBACK`(info), **`W_TABLE_PARSE`(warn)** — 부품표·개정 표의 머리글은 찾았지만 행·열을 복원하지 못함 → 부품표·개정이력 크롭과 행이 없음 |
| `tb_chunks` | 0건 |
| 남은 임시 파일 | 실패 작업 4건의 임시 파일·체크포인트(재시도 대신 새로 올림) |

## 5. 확인된 개선 필요 사항

1. **실제 도면 표 복원 실패(`W_TABLE_PARSE`)**: 합성 도면과 실제 표 블록 구조가 다름. 실제 파일(또는 `drawing_ir.json`·변환 DXF)로 원인 분석·규칙 보정 필요.
2. **문서 삭제 시 파생 폴더 미삭제**: `drawing/{document_id}/`(변환 DXF 수 MB 포함)가 남는다. 삭제 경로에 추가 필요.
3. **렌더 PNG 이중 보관**: `derived/render/`와 이미지 저장소에 같은 파일. 저장 완료 후 `render/` 삭제 가능.
