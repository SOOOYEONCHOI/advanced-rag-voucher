## 2. 화면 흐름

```
① 파일 선택(.dwg·.dxf 포함) → 문서 유형 "도면" 자동·파서 비활성 안내
② [N개 업로드 시작] → 처리 현황 행: 파일 준비 → 변환·보정 → 항목 추출 → 도면 이미지 → 저장
③ 완료 → 행에 "품번 · Rev · 경고 N" 요약 + [처리 결과 보기]
   ├ 필수 항목 누락 → 완료(확인 필요) 칩
   ├ 같은 품번 문서 있음 → 안내 문구(자동 교체 없음, D-01)
   └ 실패 → 오류 문구 + [재시도](기존)
④ 문서 목록: "도면" 배지 · 품번·Rev · 검색 미적용 · 미검수/검수 완료 · 경고 N · [처리 결과]
⑤ 처리 결과 대화상자: 요약·부품표·개정이력·주기·경고·정보·처리 정보 → [검수 완료]
```

## 3. 영역별 설계

### 3.1 업로드 카드 (`AdminView.vue` 27~100행)

| 요소 | 현재 | 변경 |
|---|---|---|
| 끌어 놓기 안내 `drop-placeholder span` | `PDF · DOCX · PPTX · XLSX · 이미지` | 도면이 켜져 있으면(`drawing_ingest_extensions` 있음) `… · 이미지 · 도면(DWG·DXF)` |
| `accept` | `SUPPORTED_EXTENSIONS + excel_ingest_extensions` | `+ drawing_ingest_extensions` |
| 문서 유형 선택 | 선택 파일과 무관하게 활성 | **선택 파일이 모두 도면이면** 비활성 + 값 표시 "도면(자동)" + 안내 `도면은 전용 처리기로 처리됩니다. 처리 후 검수하며, 검색에는 아직 쓰이지 않습니다.` 섞여 있으면 활성(도면이 아닌 파일에만 적용) + 같은 안내를 hint로 |
| 파서 선택 | `allExcelIngestFiles`면 비활성 | 조건을 **"모두 전용 처리기 대상(엑셀·도면)"**으로 넓힌다. 도면이 있으면 안내 `도면은 도면 처리기로 처리됩니다.` |
| 파일별 검사 `validationError` | 엑셀 100 MiB, 유형 호환 | 도면: 크기 `drawing_max_upload_mb`(기본 100) 초과 시 `도면 파일은 100 MiB 이하여야 합니다.` 문서 유형 호환 검사는 하지 않음(서버가 `drawing`으로 정함). `DRAWING_PARSE_MODE=off`면 확장자가 목록에 없어 선택 자체가 안 됨 |
| 머리말 설명(`header-text p`) | "파싱 → 청킹 → 임베딩 → Vector DB 저장까지 자동" | 그대로 두고, 도면 안내는 위 hint로만(문구 변경 최소화) |

### 3.2 처리 현황 (`batch-progress`, 103~226행)

**단계 표시**: `UPLOAD_STEPS`를 처리기별 표로 바꾼다. 처리기는 파일 확장자로 판단한다(서버 `drawing_ingest_extensions` 기준).

| 처리기 | 칸 | 서버 `current_step` |
|---|---|---|
| 기존(docling·엑셀) | 파일 준비 / 파싱·청킹 / 임베딩 / 저장 | `validate`·`parse` / `chunk` / `embed` / `index` (변경 없음) |
| 도면 | 파일 준비 / 변환·보정 / 항목 추출 / 도면 이미지 / 저장 | `validate`·`parse` / `drawing_convert` / `drawing_extract` / `drawing_render` / `drawing_store` |

> Phase 6 계획의 단계 코드(`drawing_parse` 하나)를 `drawing_convert`·`drawing_extract` 둘로 나눈다(화면 칸과 1:1, 재시도 시 변환을 다시 하지 않음).

**행 구성**

| 요소 | 도면 행 |
|---|---|
| 아이콘 | `fa-regular fa-file-lines` → 도면이면 `fa-solid fa-compass-drafting` |
| 모델명 입력 | 기존 그대로(파일명 기본값, 1~100자). 도면은 파일명 ≠ 도번인 경우가 있어(샘플 1종) **완료 후 표제란 품번·품명을 따로 보여 준다.** 모델명을 표제란 값으로 자동으로 바꿀지는 Q-1 |
| 상태 칩 | 기존 `completed` + 도면 결과의 `needs_review`(필수 항목 누락)면 **"완료 · 확인 필요"**(요약 칩 `unknown`과 같은 색) |
| 결과 요약 `details.batch-result` | `처리 결과 · 3페이지 · 12개 청크` | 도면: `도면 처리 결과 · {품번} · Rev {개정} · 경고 {warn}` + 펼치면 품명·용지·축척·부품표 행 수·대화 주제, 그리고 **[처리 결과 보기]**(3.5 대화상자) |
| 같은 품번 안내 | — | 결과에 `same_part_no_documents`가 있으면 `같은 품번({품번}) 문서가 이미 있습니다. 개정본이면 그 문서의 [새 버전 등록]으로 올려 주세요.` (D-01: 자동 교체·선택 상자 없음) |
| 실패 | `item.error` + [재시도] | 서버 오류 코드를 한국어 안내로: `E_UNSUPPORTED_FORMAT` 도면 파일 형식이 아니거나 지원하지 않는 버전입니다 / `E_CONVERT_FAILED` DWG를 변환하지 못했습니다. 원본을 CAD에서 다시 저장해 올려 주세요 / `E_CONVERT_TIMEOUT` 변환 시간이 초과되었습니다 / `E_DXF_LOAD` 도면을 읽지 못했습니다 / `E_EMPTY_DRAWING` 도면에 내용이 없습니다 |

요약 토스트(`onSettled`)는 그대로 쓰되 "확인 필요" 수에 `needs_review` 도면을 더한다.

### 3.3 문서 목록 열 (`doc-table`, 현행 9열 유지)

| 열 | 도면 표시 |
|---|---|
| 모델명 · 파일(현재 버전) | 1줄 모델명(기존), 2줄 도면 아이콘 + 파일명 링크(원본 DWG 내려받기, 기존 `openOriginalDocument`), **3줄 작은 글씨 `{품번} · Rev {개정}`** |
| 문서 유형 | 배지 `도면`(`badge.drawing`, `docTypeLabel`에 추가) + 아래 작은 칩: `검색 미적용`(회색), `미검수`/`검수 완료`, `경고 N`(warn만, 0이면 숨김) |
| 총 페이지 | `1매 · A3`(도면은 `total_pages`=시트 수, 용지 크기 함께) |
| 대화주제·업로더·현재 버전·최근 변경일 | 기존 그대로 |
| 파서 | `도면 처리기` |
| 작업 | 기존 [새 버전 등록]·[버전 이력]·삭제 앞에 **[처리 결과]**(도면만). 새 버전 등록에 엑셀을 고르면 기존 `replaceFormatWarning`이 형식 차이를 알린다(막지 않음 — 서버가 도면 문서에는 도면 파일만 받도록 400, Q-3) |

### 3.4 필터

- 대화 주제 칩은 그대로. 목록에 도면이 1건 이상이면 칩 줄 오른쪽 끝에 **유형 칩 `도면 N`**(토글)을 더한다. 대화 주제 필터와 함께 걸린다(AND).
- 서버 조회 조건은 바꾸지 않고 `filteredDocuments` 계산에 `doc_type === 'drawing'` 조건만 더한다(현행 대화 주제 칩과 같은 클라이언트 필터).

### 3.5 처리 결과 대화상자 (신규 `components/DrawingResultDialog.vue`)

대화상자 규칙은 현행과 같다: `role="dialog"`, 바깥 클릭으로 닫지 않음, Esc 닫기, `v-focus`, 포커스 가둠(`utils/dialogKeydown.js`).

| 탭 | 내용 |
|---|---|
| 요약 | 왼쪽: 전체 도면 썸네일(`AuthenticatedImage`, 누르면 기존 `ImageViewer`로 확대) + 표제란·부품표·개정 크롭 썸네일. 오른쪽: 표제란 필드 표(품번·품명·개정·날짜·축척·재질·재질 그룹·후처리·PART SPEC·작성·검토·승인·용지) — 못 찾은 필드는 `미검출`(빨간 글씨) |
| 부품표 | 표(번호·품번·품명·수량·재질·재질 그룹·사양·후처리), [원본 영역 보기] = BOM 크롭 확대. 부품표가 없으면 `부품표가 없는 도면(가공품)입니다.` |
| 개정이력 | 표(개정·내용·날짜·작성·검토). 빈 표는 `개정 이력이 비어 있습니다.` |
| 주기 | 번호 항목 목록, 일반공차 규격, 규격 메모 |
| 경고·정보 | 탭 이름에 `경고·정보 2+2`. 경고(warn)·정보(info) 두 묶음, 코드별 한국어 설명과 건수 |
| 처리 정보 | 단계별 소요 시간, 변환기·버전, 보정 건수, 렌더 제외 건수, 확인용 md 경로, 원본·변환 파일 크기 |

목업 v0.5의 **풍선·하위 도면·치수·공차 분류 표시는 만들지 않는다**(Phase 6 범위에서 뺌).

**아래 버튼**

| 버튼 | 동작 |
|---|---|
| [검색 적용] | 비활성 + 툴팁 `검수한 도면은 다음 단계에서 검색에 적용됩니다.` |
| [검수 완료] / [검수 취소] | `can_edit` 또는 관리자만 활성. 필수 항목 누락 도면은 확인 창 `필수 항목({누락 필드})이 비어 있습니다. 원본 도면을 확인했으면 검수 완료로 기록합니다.`(값 입력은 하지 않음 — 추출값 편집은 범위 밖, Q-2) |
| [닫기] | 닫기 |

[다시 처리] 버튼은 두지 않는다. 다시 처리가 필요하면 [새 버전 등록]으로 같은 파일을 올린다(기존 흐름 재사용).

### 3.6 버전 이력 창 (`DocumentVersionHistoryDialog.vue`)

- 도면 문서도 버전 목록은 그대로 보인다(버전별 원본·처리 결과 확인).
- 서버가 도면 문서의 이력 응답에 `restore_supported=false`를 준다 → 기존 코드대로 [선택 버전 적용]·안내 문구가 숨겨진다. 버전 행 `restore_block_reason`: `도면은 아직 검색에 쓰이지 않아 이전 버전 적용 대상이 아닙니다.`
- 화면 코드 변경은 없다(서버 응답만).

### 3.7 챗봇 화면

변경 없음(도면은 Qdrant에 없으므로 검색·답변·출처에 나오지 않는다).

## 6. 화면 완료 기준

1. `DRAWING_PARSE_MODE=off`: `.dwg` 선택 불가, 기존 업로드·목록·버전 이력 화면이 그대로(회귀).
2. `backend`: 도면 3개 + 엑셀 1개를 함께 올리면 행마다 맞는 단계 칸이 표시되고 각각 완료된다.
3. 완료 행과 목록에 품번·Rev·검색 미적용·미검수·경고 수가 보인다. 유형 칩으로 도면만 거를 수 있다.
4. 처리 결과 대화상자 6개 탭이 합성 도면으로 표시되고, 검수 완료 → 목록 `검수 완료`, 이력에 기록된다.
5. 다른 사용자가 올린 도면은 결과 보기만 되고 검수 버튼이 비활성(서버 403도 확인).
6. 도면 문서 버전 이력에서 적용 버튼이 숨겨지고 사유가 보인다.
7. 화면 너비 1280·768에서 표·대화상자가 깨지지 않는다(스크린샷은 합성 도면으로).
