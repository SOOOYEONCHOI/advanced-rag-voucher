# A. 공통

## A-1. 호출 공통

- 기본 경로 `/api`. 개발: `adrag_frontend`에서 `npm run dev` → `http://localhost:3000` (vite가 `/api`를 백엔드 `localhost:8000`으로 프록시).
- 인증: `Authorization: Bearer <토큰>`. 토큰은 로그인 후 `sessionStorage.user_token`(관리자 `admin_token`). `src/api/http.js`의 `authConfig()` / `getAuthHeaders()`를 쓴다.
- 토큰이 없거나 만료되면: `/api/query/*`는 **익명 사용자로 처리**(주제 목록이 비거나 질문이 403), 그 외 API는 401 → 로그인 화면으로.
- **대화 주제 식별자는 항상 `qdrant_name`** 을 보낸다(파라미터·본문 이름은 `collection_name`이지만 값은 `qdrant_name`).
- **사진 파일은 인증 헤더가 필요**해서 `<img src="/api/…">`로 바로 쓸 수 없다 → A-4 방식으로 blob URL을 만든다.

## A-2. 질문 스트리밍 — 여러 영역이 같은 응답을 나눠 쓴다

`POST /api/query/stream` · 응답 `text/event-stream` (각 이벤트 `data: {JSON}` + 빈 줄)

요청 본문:

```json
{ "query": "질문", "collection_name": "<qdrant_name>", "llm_provider": "local", "llm_model": "<모델 ID, 선택>" }
```

- 생략 가능: `top_k`, `collection_filters`, `enable_metadata_filtering`(서버 설정값 사용). 1차는 `llm_provider: "local"`만 쓴다(외부 AI API 금지).
- 권한 없는 주제 → **403**(본문 JSON `detail`).

이벤트 순서와 쓰는 영역:

| 순서 | `type` | 데이터 | 쓰는 영역 |
|---|---|---|---|
| 1 | `progress` | `stage`: `"searching"` → `"generating"` | ⑤ 진행 표시 |
| 2 | `token` ×N | `content`: 토큰 조각(문자열) | ⑤ 본문 |
| 3 | `citations` | `data`: `Citation[]` (A-3) | ⑤ 인용 번호, ⑦, ⑧ |
| 4 | `images` | `data`: `Image[]` (A-3) — **사진이 있을 때만 옴** | ⑤ 배지·썸네일, ⑥, ⑨ |
| 5 | `meta` | `log_id`: 숫자 | ⑦ 👍/👎 |
| 6 | `done` | — | 종료 |
| 예외 | `error` | `message`: 사용자용 안내 문구 | ⑤ 답변 자리에 문구 표시 후 종료 |

예시(축약):

```
data: {"type":"progress","stage":"searching"}
data: {"type":"progress","stage":"generating"}
data: {"type":"token","content":"너트 4개로 체결합니다[1]"}
data: {"type":"token","content":"[IMG:2aa1b3]."}
data: {"type":"citations","data":[{"citation_id":1,"original_filename":"작업표준.xlsx","sheet_name":"시트A", "...":"..."}]}
data: {"type":"images","data":[{"ref":"2aa1b3","resource_id":"<문서ID>-v1-i0044","title":"시트A Step 6 단계명 Step 사진","sheet_name":"시트A","from_cell":"C18","to_cell":"C18","context_no":1,"cited":true, "...":"..."}]}
data: {"type":"meta","log_id":123}
data: {"type":"done"}
```

- `images` 이벤트가 안 오면 그 답변의 사진은 빈 배열.
- 서버는 답변을 저장할 때 `images`에 없는 `[IMG:…]`를 지운다. 화면도 ⑤ 규칙으로 같은 결과를 내므로 이력 재조회(③)와 일치한다.
- 비스트리밍 `POST /api/query/`(같은 요청 본문) → `{query, answer, citations, images, log_id, chunks, processing_time_ms}`. 화면은 스트리밍 기준.

## A-3. 데이터 객체

### Image (`images[]`) — 답변 1건 최대 4장

| 필드 | 형식·예 | 쓰는 곳 |
|---|---|---|
| `ref` | `"2aa1b3"` (영숫자 6자 이상) | ⑤ 본문 태그 매칭 |
| `resource_id` | `"<문서ID>-v3-i0044"` | A-4 사진 파일 조회 키 |
| `title` | `"시트A Step 6 단계명 Step 사진"` | ⑤ 썸네일 캡션, ⑥ 카드, ⑨ 제목 |
| `sheet_name`, `from_cell`, `to_cell` | `"시트A"`, `"B12"`, `"D18"` | **셀 위치 표기**(아래) |
| `surrounding_text` | 최대 200자 | ⑨ 주변 설명 |
| `original_filename` | `"작업표준.xlsx"` | ⑨ 출처 |
| `context_no` | `1` | 이 사진이 나온 근거 번호 = `Citation.citation_id` → ⑨ [문서 위치] |
| `cited` | `true`/`false` | `false` = 본문 인용 없이 서버가 자동 첨부한 사진 → ⑤ 배지 없음, ⑥에만 표시 |
| `role` | `step_photo`·`detail_view`·`drawing`·`part_photo`·`flowchart`·`step_related`·`figure` | (선택) 아이콘·라벨 |
| `step_no`, `step_title`, `document_id` | | (선택) |

- **사진 번호 = `images` 배열 순서 + 1** — ⑤ 배지, ⑥ 카드, ⑨ `n / N`이 모두 이 번호를 쓴다.
- **셀 위치 표기**: `to_cell`이 없거나 `from_cell`과 같으면 `시트A!C18`, 다르면 `시트A!B12:D18`.

### Citation (`citations[]`)

| 필드 | 쓰는 곳 |
|---|---|
| `citation_id` | 인용 번호. **스트리밍·이력은 숫자, 비스트리밍은 문자열** → 비교는 `String(a) === String(b)` |
| `original_filename`, `title`, `document_type`(`spreadsheet`·`manual`·…) | ⑦, ⑧ |
| `sheet_name`, `source_range`(`"12:18"` 등, 없을 수 있음) | ⑧ `시트 / 범위` |
| `display_markdown`(엑셀 우선) / `chunk_text`(300자) | ⑧ 근거 미리보기 |
| `highlight_text` | ⑧ 근거 문장 `mark` 강조 |
| `resource_ids` | ⑧ 연결된 사진 ID |
| `page_number`, `manual_display_mapped`, `display_filename`, `display_page_number` | ⑦ PDF 매뉴얼 페이지(기존 그대로) |
| `document_id`, `chunk_id`, `score`, `section_name`, `header_path`, `referenced_in_answer` | 보조 |

### 이력 메시지 (③)

```json
{ "role": "user", "content": "질문" }
{ "role": "assistant", "content": "마크다운 본문([1]·[IMG:ref] 포함)", "citations": [], "images": [], "log_id": 123, "feedback": "like" }
```

`feedback`: `"like"` / `"dislike"` / `null`. 10-19 이전 답변은 `images`가 없을 수 있다(빈 배열로 처리).

## A-4. 사진 파일 받기

`GET /api/spreadsheet-resources/{resource_id}` → 이미지 바이너리(png·jpeg·gif·webp·bmp)

```js
const res = await http.get(`/spreadsheet-resources/${encodeURIComponent(resourceId)}`, authConfig({ responseType: 'blob' }));
const url = URL.createObjectURL(res.data);   // <img :src="url">
```

- 같은 `resource_id`는 한 번만 받아 캐시(⑤·⑥·⑧·⑨가 같은 URL 공유). 화면을 떠날 때 `URL.revokeObjectURL`.
- 실패: 404(없음·삭제), 403(권한 없음 — 4-B에서 404로 바뀜) → 빈 썸네일 + "이미지를 불러올 수 없습니다." 답변은 그대로.
- 크기 옵션(`?size=thumb|preview`) 없음 — 썸네일도 원본을 CSS로 줄인다(생기면 쿼리만 추가).

## ⑤ 답변 말풍선 — 진행·본문·인용·사진 배지·썸네일 ✅ (ANS-01)

| 화면 요소 | 데이터 | 규칙 |
|---|---|---|
| "문서 검색 중… / 답변 생성 중…" | `progress.stage` | 첫 `token` 전까지 표시 |
| 본문 | `token.content` 누적 | 마크다운 렌더(`marked` + `DOMPurify`, 기존 `formatResponse`) |
| 인용 번호 `[1]` | 본문의 `[숫자]` + `citations` | 기존 `renderInlineCitations` — 클릭 → ⑧ |
| **사진 배지** | 본문의 `[IMG:ref]` + `images` | 아래 규칙 |
| **단계별 썸네일** | 같은 | 아래 규칙 |

**`[IMG:ref]` 렌더 규칙**
1. 찾기: 정규식 `\[IMG:\s*([A-Za-z0-9_-]{1,64})\s*\]`
2. `images`에서 같은 `ref`가 있으면 그 자리에 **사진 번호 배지**(🖼 n, n = 배열 순서 + 1). 클릭 → ⑨(n번).
3. `images`에 없는 `ref`는 **태그째 지운다**.
4. 그 태그가 들어 있는 **목록 항목(`li`) 안쪽 끝에 썸네일**(132px, 캡션 `n. title`)을 붙인다. 단락(`p`)·표는 닫는 태그 **뒤에** 붙인다(`p` 안에 `div`를 넣으면 HTML이 깨짐). 같은 사진은 썸네일 한 번만, 배지는 나올 때마다.
5. 썸네일 이미지는 A-4. 클릭 → ⑨.
6. `cited: false` 사진은 본문에 태그가 없으므로 ⑤에는 나오지 않는다(⑥에만).

**스트리밍 중**
- `images`가 아직 없으므로 완성된 태그는 숨긴다(3번 규칙과 같음).
- 토큰 끝에 걸린 미완성 태그(`[`, `[IM`, `[IMG:2a`)는 다음 토큰까지 숨긴다: 정규식 `\[(?:I(?:M(?:G(?::\s*[A-Za-z0-9_-]*)?)?)?)?$`를 렌더 전 본문 끝에서 제거.
- `images` 이벤트 수신 후(또는 `done` 후) 위 규칙으로 다시 그린다.

**오류**: `error` 이벤트 → `message`를 답변 자리에 빨간 글씨로. HTTP 403 → 응답 JSON의 `detail` 문구 표시. 네트워크 오류 → 기존 임시 오류 문구(`TEMPORARY_ERROR_MESSAGE`).

| 👍/👎 | `PATCH /api/query/{log_id}/feedback` `{ feedback: "like" \| "dislike" \| null }` → `{ log_id, feedback }`. 같은 버튼 다시 누르면 `null`(취소). `log_id`는 `meta` 이벤트(이력은 `log_id`). 없으면 버튼 비활성. 본인 질문 아니면 404 |

## ⑧ 출처 패널 (Sources) ✅ (ANS-03)

| 화면 요소 | 데이터 |
|---|---|
| 카드 헤더 | 번호 `citation_id`, 파일 아이콘(`document_type`), `original_filename` |
| 위치 | `sheet_name` / `source_range` (엑셀). 매뉴얼은 페이지 |
| 근거 미리보기 | `display_markdown`(없으면 `chunk_text`) |
| 근거 강조 | `highlight_text`와 같은 문장을 `<mark>` |
| [첨부 리소스 보기] | docling 처리 문서만: 미리보기 안 `⟦RESOURCE:{resource_id}⟧` 표시를 버튼으로 바꾸고 A-4로 연다(기존 `CitationPanel.vue`). **엑셀 처리기(현재 기본) 문서에는 이 표시가 없다** → 아래 "연결된 이미지"로 대신 |
| **연결된 이미지 N장** | 아래 |

**연결된 이미지 N장 ✅ (10-19 백엔드 필드 추가)**
1. `citation.resource_ids`로 사진 ID 목록을 얻는다(현재 버전 사진만 들어 있음).
2. `GET /api/documents/{document_id}/spreadsheet-resources` → `{ total, resources: [...] }`에서 **`resource_ids`에 있는 것만** 고른다.
   - 이 목록에는 이전 버전 사진도 들어 있으므로 반드시 `resource_ids`로 거른다.
   - 문서별 1회 조회 후 캐시해도 된다(같은 문서의 인용이 여러 개일 수 있음).
3. **`displayable: true`인 것만** 보여준다(장식·양식 머리글·emf 등 표시 불가 형식·검수 "연결 안 함" 제외). N = 남은 개수.
4. 사진은 A-4로 받는다. 클릭 → 이 사진들로 ⑨를 연다.

목록 항목 필드:

| 필드 | 용도 |
|---|---|
| `resource_id` | 사진 파일 조회 키(A-4) |
| `title` | 썸네일 캡션·⑨ 제목 — **답변 사진(A-3 Image.title)과 같은 형식** |
| `role` | 역할(A-3과 같은 값 + `decoration`·`form_header`) |
| `displayable` | 표시 여부(위 3번) |
| `sheet_name`, `from_cell`, `to_cell` | `시트!셀` 표기(A-3 규칙) |
| `surrounding_text` | ⑨ 주변 설명 |
| `step_no`, `step_title`, `version_no`, `in_print_area`, `review_status`, `mime_type`, `file_size`, `status`, `download_url` | 보조 |

⑨를 이 목록으로 열 때 `original_filename`은 인용의 `original_filename`을, [문서 위치]는 지금 보고 있는 인용을 쓴다.

## ⑨ 이미지 뷰어 ✅ (ANS-04)

- 열기: ⑤ 배지·썸네일, ⑥ 카드, ⑧ 연결 이미지 클릭. 대상 = 그 답변의 `images`(⑧에서 열면 그 인용의 연결 사진).

| 화면 요소 | 데이터 |
|---|---|
| 번호 · 제목 | 순서+1 · `title` |
| `n / N` | 현재 번호 / `images.length` |
| ← / → (키보드 ←·→ 포함) | 같은 목록 안에서 순환 |
| 큰 이미지 | A-4 (캐시된 URL 재사용) |
| 출처 | `original_filename · 시트!셀` |
| 주변 설명 | `surrounding_text` |
| [원본 열기] | A-4 blob URL을 새 탭으로 |
| [문서 위치] | 같은 답변 `citations`에서 `citation_id == context_no` 이고 `document_id`가 같은 인용 → 뷰어 닫고 ⑧을 그 인용으로 연다. 없으면 같은 `document_id`·`sheet_name` 인용, 그것도 없으면 버튼 비활성 |
| 닫기 | ✕, Esc, 바깥 클릭 |
