# VLM 테스트 모델 A.X-4.0-VL-Light 추가 배포 (GPU 서버 yest-gpu, 2026-11-05)

> 흐름도·도면 이미지 인식 비교 테스트용. 운영 서비스(LLM·임베딩·리랭커·ASR·docling)는 건드리지 않는다.
> 기본 절차·계정·권한은 `운영배포_가이드_서버별_v1.1.md` §1을 따른다. 이 문서는 추가분만 적는다.
> 2026-11-05: 처음 Gemma4-12B-it 기준으로 썼다가, 서버에 반입된 A.X-4.0-VL-Light 기준으로 바꿨다(사용자).

## 0. 배치

| GPU | 서비스 | systemd | 포트 | `--gpu-memory-utilization` | 모델(`--served-model-name`) | 모델 경로 |
|---|---|---|---|---|---|---|
| 1 | VLM 테스트 | `vllm@vlm` | 8110 | 0.35 (약 28GB) | `A.X-4.0-VL-Light` (max-model-len 16384) | `/mnt/a/chatbot/models/vlm/A.X-4.0-VL-Light` |

- GPU 1 비율 합계: 임베딩 0.18 + 리랭커 0.05 + ASR 0.15 + VLM 0.35 = **0.73** (기준 0.9 이하). 11-05 측정 사용량 24.4GB + 28GB ≈ 52GB / 80GB.
- GPU 0은 LLM 0.70 + docling으로 여유가 약 8GB라 올리지 않는다.
- 8109는 TTS 자리(V-6)라 8110을 쓴다. **TTS(0.24)를 GPU 1에 올리면 합계 0.97로 넘는다** → 그 전에 GPU 2로 옮기거나(승인 후) 멈춘다.
- 테스트용이라 `enable`(부팅 시 자동 시작)하지 않는다.

|---|---|

## 3. 서버(yest-gpu, sychoi)에서 설치

### 3.1 모델 폴더 확인 (읽기만 — 권한은 바꾸지 않는다)

> **모델 폴더와 상위 경로의 소유자·권한은 절대 바꾸지 않는다**(`chown`·`chmod`·`setfacl` 금지, 사용자 결정 2026-11-05). 아래는 모두 보기만 하는 명령이다.

```bash
M=/mnt/a/chatbot/models/vlm/A.X-4.0-VL-Light     # 경로를 M 이라는 이름에 담아 두는 것 — 아무것도 바꾸지 않는다
sudo ls -la $M                                   # config.json, tokenizer*, *.safetensors, preprocessor_config.json 등
sudo du -sh $M                                   # 약 16GB 안팎
sudo grep -A2 '"architectures"' $M/config.json   # 구조 이름 — 3.5 표 참고
sudo ls $M/*.py 2>/dev/null                      # 자체 코드(modeling_*.py)가 있으면 --trust-remote-code 로 읽는다

# vLLM 실행 계정(vllm-admin)이 읽을 수 있는지만 확인
sudo namei -l $M/config.json                     # 경로 각 단계의 소유자·권한 (비교용: 아래 기존 모델)
sudo namei -l /mnt/a/chatbot/models/gen/Qwen3.5-9B/config.json
sudo -u vllm-admin test -r $M/config.json && echo "config 읽기 OK" || echo "읽기 불가"
sudo -u vllm-admin find $M -type f ! -readable   # 아무것도 안 나오면 모든 파일 읽기 가능
```

**읽기 불가가 나오면 여기서 멈추고** `namei -l` 결과를 담당자와 보고 정한다. 서비스는 띄우지 않는다(띄워도 `Permission denied`로 실패할 뿐 다른 서비스에는 영향 없음).

### 3.2 실행 파일

서버 실제 상태(2026-11-05 확인): 기존 `run-*.sh`는 `sychoi:vllm-admin`, `-rwxr-x---+`(ACL 있음). 새 파일도 **옆 파일과 같게** 맞춘다 — 소유자는 바꾸지 않고, `run-vlm.sh`에 실행 권한만 준다.

```bash
# 파일을 /opt/yest/chatbot/vllm/app/ 에 복사한 뒤
sudo sed -i 's/\r$//' /opt/yest/chatbot/vllm/app/run-vlm.sh /opt/yest/chatbot/vllm/app/check-vlm.sh
sudo chmod 750 /opt/yest/chatbot/vllm/app/run-vlm.sh     # 이 파일 하나만. 없으면 systemd 203/EXEC
sudo ls -l /opt/yest/chatbot/vllm/app/                   # run-vlm.sh 가 run-llm.sh 와 같은 -rwxr-x---+ 인지
```

`check-vlm.sh`는 `bash check-vlm.sh`로 실행하므로 실행 권한이 없어도 된다(그룹 읽기만 필요).

### 3.3 키 추가

```bash
sudo -iu vllm-admin
vi /opt/yest/chatbot/vllm/app/env.sh
#   맨 아래에 로컬 deploy/gpu/.../env.sh 의 "export VLM_API_KEY=..." 줄을 그대로 붙여 넣는다
grep -c '^export VLM_API_KEY=' /opt/yest/chatbot/vllm/app/env.sh   # 1
exit
```

### 3.4 실행

```bash
nvidia-smi --query-gpu=index,memory.used,memory.total --format=csv   # 실행 전 GPU 1 사용량 기록 (약 24GB)
sudo systemctl start vllm@vlm                                         # enable 하지 않는다(테스트용)
sudo tail -f /mnt/a/chatbot/vllm/logs/vlm.log                         # "Uvicorn running on http://0.0.0.0:8110" 까지 (수 분) → Ctrl+C
systemctl status vllm@vlm --no-pager
nvidia-smi                                                            # GPU 1 약 28GB 증가, GPU 0 변화 없음, 2~7 0MiB
```

### 3.5 기동 실패 시

`sudo tail -n 100 /mnt/a/chatbot/vllm/logs/vlm-error.log`

| 증상 | 조치 |
|---|---|
| `Model architectures [...] are not supported` | vLLM 0.30.0 이 이 구조를 모름 — 3.1 의 `architectures` 값과 함께 보고 |
| `No available memory for the cache blocks` / KV 캐시 부족 | `run-vlm.sh` `--max-model-len` 8192로 낮추기 |
| `max_model_len ... is greater than` 모델 최대 길이 | `config.json`의 `max_position_embeddings` 이하로 `--max-model-len` 낮추기 |
| `Free memory on device ... is less than desired` | GPU 1 다른 서비스가 예상보다 많이 쓰는 중 — `nvidia-smi` 확인 후 보고 |
| `Permission denied` (모델 파일) | 권한은 바꾸지 않는다 — `sudo systemctl stop vllm@vlm` 후 3.1 `namei -l` 결과로 담당자와 협의 |
| `limit_mm_per_prompt` 관련 오류 | `run-vlm.sh`에서 그 줄을 지우고 restart |

`run-vlm.sh`는 저장소에서 고쳐 다시 올린다(3.2) → `sudo systemctl restart vllm@vlm`.

### 3.6 확인

```bash
sudo -u vllm-admin bash /opt/yest/chatbot/vllm/app/check-vlm.sh
# 1. 모델 목록에 A.X-4.0-VL-Light   2. 401   3. 한국어 한 문장   4. START → END 설명 + 응답 시간
for p in 8101 8102 8103 8107; do curl -s -o /dev/null -w "$p %{http_code}\n" http://127.0.0.1:$p/v1/models; done   # 기존 서비스 401(살아 있음)
```

도면 테스트(`adrag_backend/tests/test_qwen_vl_image.py`)는 `--base-url http://<GPU_IP>:8110/v1 --model A.X-4.0-VL-Light --api-key <VLM_API_KEY>`로 실행한다. **GPU 서버 밖(개발 PC·WAS)에서 부르려면** ACG F-4 인바운드에 TCP 8110을 추가해야 한다.

## 4. 운영·되돌리기

| 할 일 | 명령 |
|---|---|
| 멈춤 | `sudo systemctl stop vllm@vlm` (GPU 1 메모리 즉시 반환) |
| 재시작(인자 변경 후) | 저장소 `run-vlm.sh` 수정 → 다시 올려 3.2 → `sudo systemctl restart vllm@vlm` |
| GPU 2로 옮기기(승인 후) | `run-vlm.sh`의 `CUDA_VISIBLE_DEVICES=2` → restart |
| 완전히 제거 | `sudo systemctl stop vllm@vlm` → `sudo rm /opt/yest/chatbot/vllm/app/run-vlm.sh /opt/yest/chatbot/vllm/app/check-vlm.sh` → env.sh의 `VLM_API_KEY` 줄 삭제 |

다른 서비스 설정·`vllm@.service`는 바꾸지 않았으므로 위 단계만으로 원래 상태가 된다. 모델 폴더는 남겨 둔다.
