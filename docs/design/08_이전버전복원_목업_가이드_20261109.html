상세 응답 예시·필드 규칙: 문서_이전버전_복원_화면영역별_API_명세_v1.1.md · OpenAPI /docs

공통

  • URL은 /api 기준, 인증은 기존 Authorization: Bearer. 401은 기존 로그인 만료 처리.
  • 권한(2026-11-06, D-22): 문서를 볼 수 있는 사용자는 이력 열람과 복원을 모두 할 수 있다(관리자 전용 아님, 업로더가 아니어도 됨). 볼 수 없는 문서는 404. 역할명이 아니라 서버의 can_restore로 버튼을 결정한다.
  • 화면 진입은 일반 사용자 문서 관리(/admin). 관리자 계정의 진입 규칙(/admin/users)은 그대로.
  • 시간은 KST 문자열 YYYY-MM-DD HH:mm:ss 또는 null — 다시 변환하지 않는다. 버전은 정수, 파일 크기는 byte.
  • 서버 설정 DOCUMENT_VERSION_VECTOR_RETENTION_ENABLED·DOCUMENT_VERSION_RESTORE_ENABLED는 기본 꺼짐. 꺼져 있으면 restore_supported=false·FEATURE_DISABLED로 내려오므로 화면은 응답 값만 본다.
  • 기존 API 필드는 유지되고 필드만 추가된다. 모르는 필드는 무시한다. 오른쪽 위 연동판 패널은 확인용이며 제품에 구현하지 않는다.

오류 응답

복원 API 업무 오류는 {"detail":{"code","message"}}. 기존 API의 문자열 detail, 검증 오류의 배열 detail도 함께 처리한다.

연동 체크리스트

  • 일반 사용자 계정으로 문서 관리 → 버전 이력 → 복원, 볼 수 없는 문서는 404 처리.
  • 행 선택만으로 요청이 나가지 않고, 확인 클릭 한 번에 POST 한 번(재전송 시 같은 키).
  • 진행 중 창 닫기·새로고침 후 pending_operation으로 폴링 재개, 그동안 [최신본 변경]·[삭제] 비활성.
  • 성공 시 목록·이력·열린 적용 이력 재조회. 실패의 “유지 버전”은 재조회한 version_no. HTTP 타임아웃·폴링 장애는 작업 실패가 아님.
  • 목업의 버전 개수·이름·시각·자동 완료 시간을 하드코딩하지 않는다. 기존 최신본 변경 흐름(pending_job_id·pending_version_no)은 그대로.
