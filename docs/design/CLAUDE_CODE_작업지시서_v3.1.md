## 2. Phase 0 ~ 3 — v2.3 대비 바뀐 점만

### Phase 0
- v2.3 7개 항목 그대로. 추가로 **기존 사용자·권한 구조**(사용자 테이블, 역할, 문서 권한이 있는지)와 **기존 음성·TTS 관련 코드 유무**를 조사한다.

### Phase 1 · 1.5
- 변경 없음(v2.3 + DB 환경 보완 지시서 DB-ENV-1·2).

### Phase 2
- 변경 없음. 단 Qdrant payload에 **`acl`(D-04), `model_id`** 필드를 처음부터 넣고 payload index를 만든다(나중에 넣으면 전체 재색인 필요).
- 임베딩 차원은 설정값(`EMBED_DIM`, 기본 1024)으로 두고 컬렉션 이름에 버전을 붙인다(`chunks_v1`), API는 별칭으로만 접근(설계서 v0.2 4.5).

### Phase 3 — 작업 큐·동시 등록·개정본 교체
- v2.3 Phase 3 그대로(PostgreSQL 작업 큐, 재시도, 워커 장애 회수, 버전 전환) + **D-01 적용**:
  - 새 문서는 상단 업로드(대화 주제 = 문서 그룹, D-15), 개정본은 문서 행 [최신본 변경] → `POST /api/admin/documents/{doc_id}/versions`. 자동 개정 판단·`revision_candidate`·`confirm_upload` 단계는 만들지 않는다(이미 있으면 제거 계획 보고 후 제거). 기존 AdminView의 최신본 변경 API가 있으면 그것을 작업 큐·버전 전환 규칙에 맞게 확장한다.
  - `doc_key`는 저장만 하고 개정 판단에 쓰지 않는다.
- 추가 완료 기준
  - [최신본 변경] 업로드 → 같은 문서의 다음 버전, 처리 중 질의는 기존본 근거만 반환, 완료 후 새 버전만 반환.
  - 상단 업로드로 같은 내용의 다른 파일명 업로드 → 별개 문서(자동 병합 0건).
  - 실패 단계부터 재시도 최대 3회, 3회 초과 시 `FAILED` + 실패 사유가 상태 API에 나온다(SC-07).

## 3. Phase 4 — 검색·답변·이미지·출처 + 사용자별 권한

**범위**: 설계서 v0.2 4.4(이미지)·4.5(검색 안전장치)·4.6(질의응답) + 변경로그 D-03(정규화 즉시 반영), D-04(권한), D-09, D-11, D-12. 프런트 UI-01~05.

**할 일**
1. **권한(D-04·D-15)**: 마이그레이션 `tb_user_doc_access`(scope `TOPIC|DOC`), 문서 그룹은 기존 대화 주제. 작업자의 대화 주제 목록은 권한 있는 주제만. `core/auth.py`의 `allowed_acl(user)` 하나로 검색 필터·이미지 API·원본 다운로드·출처 조회를 판단. 권한 없는 리소스는 404.
2. **질의 정규화**: 용어 사전 테이블(`tb_glossary_term`, `tb_glossary_synonym`)과 초기 데이터 seed(`data/seed/`, DB-ENV-5)를 이 Phase에서 만든다. 용어 사전(`use_search_yn=Y`)으로 동의어 → 표준 용어, 품번 패턴 보존. 사전이 바뀌면 캐시가 즉시 무효화되도록(버전 키) 만든다.
3. **Hybrid 검색**: dense + sparse → RRF → 리랭크 → 최신본 재확인(`active_guard`), 필터 `is_active=true AND acl ∈ allowed_acl(user)`. 파라미터는 설정값(`RAG_*`).
4. **답변**: 근거 안에서만, 작업 방법 질문은 단계형, 안전(S) 항목 먼저, 근거 점수 `RAG_MIN_SCORE` 미만이면 LLM 호출 없이 "문서에서 찾지 못했습니다" + 비슷한 문서. 이미지 `[IMG:id]` 인용 → 후보 외 제거 → 최대 `RAG_MAX_IMAGES`(4).
5. **SSE 응답**: `status`(searching → generating) · `delta` · `final{message_id, answer, citations[], images[]}` · `error`. `graphs`는 넣지 않는다(D-08).
6. **대화·평가 기록(R6-4)**: 대화 이력 저장·표시(D-11: 이전 질문으로 검색어를 보완하지 않음), 👍/👎 저장(D-12), 활용률 집계에 쓸 수 있게 질문·답변·평가·입력 방식(text/voice) 기록.
7. **화면** (기준: 챗봇 목업 `docs/design/mockups/chat_UI-02-08_20261008.html`의 ANS-01~04, D-14): UI-02 챗봇 메인(대화 이력, Enter 전송, 마이크 버튼 자리, 평가), UI-03 답변 표시(단계형, S/Q 배지, 단계 정보, 인용 번호), UI-04 이미지 뷰어(미리보기 → 원본, ←/→, 시트·셀·연결 단계), UI-05 참고 문서 패널(문서·이미지 탭, 출처 카드: 파일·시트·셀·개정 차수·Step, 권한 시 원본 다운로드). UI-01은 사용자 정보에 역할·접근 가능 범위 표시.

**완료 기준**
- "FAN 모듈 REACT FAN 조립 체크포인트" 질의 → Step 6 사진 포함, 출처에 시트·셀·개정 차수, 후보에 없는 IMG ID 제거(v2.3 Phase 4 기준 유지).
- 품번 질의("MEC21103", "SEMS M4X10")가 키워드 검색으로 Top-5 안에 든다.
- 권한 테스트(D-04 테스트 항목) 통과, 근거 없음 질의에서 LLM 호출 0회.
- 동의어 추가 직후 재시작 없이 동의어 질의가 표준 용어 문서를 찾는다(D-03).
- SC-01, SC-03, SC-04(👍/👎) 시나리오 테스트 통과.

## 4. Phase 4.5 — 음성 질문(STT)·음성 답변(TTS) 기본

**범위**: 설계서 v0.2 4.7(STT) 그대로 + D-05(TTS). **작업 가이드(4.8)는 하지 않는다(D-07).**

**할 일**
1. STT: `POST /api/voice/transcriptions` → Qwen3-ASR(`ASR_API_URL`) → 용어 사전(`use_stt_yn=Y`) 보정 → `{transcription_id, text, raw_text, corrections[], …}`, `tb_voice_transcriptions` 저장, **음성 원본 즉시 삭제**. 1초 미만 400, 10MB 초과 413, 30초 초과 504.
2. UI-07 `VoiceInputPanel` (목업 VOC-01~03): idle → recording(“말씀해 주세요”, 경과 시간·음량, 최대 60초) → transcribing → preview(편집 가능, 용어 보정 표시, [다시 녹음]·[질문에 적용]·[바로 질문]·[×]) → [바로 질문]은 즉시 전송, [질문에 적용]은 입력창으로 옮겨 사용자가 전송. **자동 전송 없음.** HTTPS 아님·마이크 거부·무음·인식 실패 안내.
3. 질문에 `input_mode=voice`, `voice_transcription_id`, `voice_edited` 기록, 화면에 "음성"/"인식 결과 수정됨" 표시.
4. TTS(D-05·D-17): `POST /api/voice/speech {message_id}` → Qwen3-TTS(`TTS_API_URL`), UI-08 [음성 답변] 버튼 + 목업 ANS-05 형태 플레이어(클릭 시만, 진행 막대·시간, 정지·다시 듣기, 음성 요약은 2차), `FEATURE_TTS` 기본 true, 실패 시 텍스트 유지 + 재시도 안내.

**완료 기준**
- SC-02 시나리오 통과(정상 2경로 [바로 질문]/[질문에 적용] + 예외 4종), "리액트 팬" 발화 → `REACT FAN` correction 표시, 서버에 오디오 파일 잔존 0.
- [음성 답변] 클릭 시에만 TTS 호출(페이지 로드·답변 수신 시 호출 0회), 정지·다시 듣기 동작, 권한 없는 `message_id`는 404.

- 11/13(M6) 시점에 UI-12·19·20 시연 가능 상태를 별도 보고.

## 6. Phase 6 — DXF 도면 기본 모듈 (시범)

**범위**: D-06. 기준 문서는 DXF 기술검토 v0.1.

**할 일**
1. `dxf_ingest` PoC를 `ingest/drawing/`에 넣고 읽기 계층을 **ezdxf**로 교체(`dxfreader.load()` 한 곳). 의존성 추가 승인 필요하면 먼저 보고.
2. File Router에 `.dxf` 분기(`DRAWING_PARSE_MODE=backend`일 때). `.dwg`는 "1차 미지원" 안내와 함께 `415 UNSUPPORTED_FORMAT`.
3. 1차 추출 범위(G-1~5, G-9, G-13) → 청크(`drawing_overview`, `drawing_notes`, `drawing_bom`, `drawing_bom_item`, `drawing_revision`) + 크롭 이미지 → 기존 적재 파이프라인(작업 큐·버전·권한 payload 동일, payload에 `doc_type=drawing`, `drawing_no`, `rev`, `part_no`).
4. 확인용 md `{MD_SAVE_DIR}/drawing/{doc_key}/{job_id}/`, 키워드 사전 `drawing_keywords.yaml`.

**완료 기준**: 합성 샘플 2종 결과가 기술검토 7장과 같고 단위 테스트 17개 통과(ezdxf 교체 후), 기술검토 10장 검증 질의 중 표제란·BOM·주기·개정 질의 5개가 Top-5 안. 실제 도면(협의 #3)이 오면 표제란 필수 3필드 100%·BOM 행 누락 0을 추가 보고(키워드 사전만 보정, 코드 규칙 변경은 보고 후).

## 7. Phase 7 — 모델 비교·선정, 평가 도구, 통합 테스트

**할 일**
1. **평가 도구(TST-01, WRK-07)**: 질의셋(TST-02: 질의·정답·근거 문서·기대 이미지) 실행 → 정답 여부·근거 적중·이미지 포함·응답 시간(첫 글자·전체)·GPU 사용량 저장(`tb_eval_*`). 판정 기준은 협의 #2 확정 전까지 설정 파일로 두고 사람 판정 입력 칸을 둔다. 결과 리포트(md + 표).
2. **모델 비교(F-6-06)**: 프로그램·기능 목록 「모델 비교 테스트」 시트 형식대로 LLM·임베딩+리랭커·VLM·STT 표를 채운다. LLM 후보는 D-10. 임베딩은 BGE-M3 / KURE-v1 / Qwen3-Embedding 조합을 같은 질의셋 Recall@5·10, 품번 질의 정답률로 비교.
3. **최종 선정(F-6-07, 11/16 M7)**: 비교 결과 보고 → 사용자 승인 → `tb_model_config` 전환. NC 라이선스 모델은 사용 조건 확인 전 운영 기본값으로 정하지 않는다.
4. **통합 테스트(F-7-02)**: SC-01~SC-10 자동/반자동 테스트, 설계서 v0.2 9장 통합 항목(적재 수치, 재업로드, 전환 중 검색, 실패 재시도, 동시 업로드 10건, 작업 큐 중복 0, 워커 장애 회수).
5. **1차 측정(F-7-01, 11/30 M8)**: 확보한 질의셋 N건으로 정답률 측정(목표 50% 이상, D-09), 활용률 집계 방식 검증.

**완료 기준**: 모델 비교 리포트 + 선정 근거, SC-01~10 테스트 결과표, 1차 측정 결과표를 `docs/design/reports/phase-7.md`에 첨부.
