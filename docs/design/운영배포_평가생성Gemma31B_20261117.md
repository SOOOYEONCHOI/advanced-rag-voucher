# 평가 데이터셋 생성용 gemma-4-31B-it-FP8 추가 배포 (GPU 서버 yest-gpu, 2026-11-17)

> RAG 평가 데이터셋(질문·정답)을 만들 때만 켜는 모델. 운영 서비스(LLM·임베딩·리랭커·ASR·docling·VLM)는 건드리지 않는다.
> 기본 절차·계정·권한은 `운영배포_가이드_서버별_v1.1.md` §1, 형식은 `운영배포_리랭커Qwen3_20261110.md`를 따른다. 이 문서는 추가분만 적는다.
> 대장: `운영_GPU_사용현황_대장_20261117.xlsx` (모델별 현황 10번 행, 포트 8112)

## 0. 배치

| GPU | 서비스 | systemd | 포트 | `--gpu-memory-utilization` | 모델(`--served-model-name`) | 모델 경로 |
|---|---|---|---|---|---|---|
| 2 | 평가 데이터셋 생성 | `vllm@gen-gemma31b` | 8112 | 0.75 (약 60GB) | `gemma-4-31B-it-FP8` (max-model-len 16384) | `/mnt/a/chatbot/models/gen/gemma-4-31B-it-FP8` |

- GPU 2 합계 = Qwen3 리랭커 0.10 + 0.75 = 0.85 (상한 0.9 이하). 2026-11-17 `nvidia-smi` 기준 GPU 2 사용 8.6GB.
- 미리 양자화된 FP8 모델이라 `--quantization` 옵션을 주지 않는다(`config.json`의 `quantization_config`를 vLLM이 읽는다).
- 포트: 8101~8119가 챗봇 범위(2026-11-17 MAIP 공유). 8111 다음 빈 번호 8112.
- 키: 기존 `VLLM_API_KEY`를 같이 쓴다. `env.sh`·WAS `.env`는 바꾸지 않는다.
- 평가 기간에만 쓰므로 `enable`(부팅 시 자동 시작)하지 않는다. 끝나면 `stop`.

## 1. 추가 파일

| 로컬 파일 | 서버 경로 | 소유자·권한 |
|---|---|---|
| `deploy/gpu/opt/yest/chatbot/vllm/app/run-gen-gemma31b.sh` (새 파일) | `/opt/yest/chatbot/vllm/app/run-gen-gemma31b.sh` | 옆 `run-*.sh`와 같게, 실행 권한 750 |
| 모델 폴더 (**서버에 이미 있음**, 2026-11-18 확인) | `/mnt/a/chatbot/models/gen/gemma-4-31B-it-FP8/` | 반입·복사하지 않는다. **권한은 바꾸지 않고 읽기 확인만 한다**(3.2) |

`vllm@.service`(템플릿)와 `logrotate.d/vllm`(`*.log`)은 그대로 쓴다.

모델은 서버에 이미 있으므로 실행 파일 하나만 올린다. WinSCP(남부권 SSL VPN, **바이너리 모드**):

| 왼쪽(로컬) | 오른쪽(서버) |
|---|---|
| `deploy\gpu\opt\yest\chatbot\vllm\app\run-gen-gemma31b.sh` | `/mnt/a/chatbot/offline/gpu-config/` |

## 3. 서버(yest-gpu, sychoi)에서 설치

### 3.1 GPU 2·포트 확인

```bash
nvidia-smi --query-gpu=index,memory.used,memory.total --format=csv    # GPU 2 가 약 8.6GB(리랭커)여야 한다
nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name,used_memory --format=csv   # GPU 2 에 다른 팀 프로세스가 없는지
sudo ss -ltnp | grep -E ':8112\b'                                       # 아무것도 안 나와야 한다
```

GPU 2 사용량이 약 20GB를 넘거나 다른 프로세스가 있으면 **여기서 멈추고** 보고한다.

### 3.2 모델 폴더 확인 (읽기만)

```bash
M=/mnt/a/chatbot/models/gen/gemma-4-31B-it-FP8
sudo du -sh $M                                                  # 약 31~35GB
sudo grep -A3 '"quantization_config"' $M/config.json            # FP8 정보가 있어야 한다. 없으면 멈추고 보고
sudo namei -l /mnt/a/chatbot/models/gen/Gemma-4-12B-it/config.json   # 비교용(보기만)
sudo namei -l $M/config.json
sudo -u vllm-admin find $M ! -readable                          # 아무것도 안 나오면 OK
```

**읽기 불가가 나오면 여기서 멈추고** `namei -l` 결과를 담당자와 보고 정한다. 모델 폴더와 `/mnt/a` 등 상위 경로는 `chown`·`chmod`·`setfacl`을 하지 않는다(2026-11-05 결정).

### 3.3 실행 파일

```bash
sudo cp /mnt/a/chatbot/offline/gpu-config/run-gen-gemma31b.sh /opt/yest/chatbot/vllm/app/
sudo sed -i 's/\r$//' /opt/yest/chatbot/vllm/app/run-gen-gemma31b.sh
sudo chown --reference=/opt/yest/chatbot/vllm/app/run-vlm-gemma.sh /opt/yest/chatbot/vllm/app/run-gen-gemma31b.sh   # 새 파일 하나만
sudo chmod 750 /opt/yest/chatbot/vllm/app/run-gen-gemma31b.sh     # 이 파일 하나만. 없으면 systemd 203/EXEC
sudo ls -l /opt/yest/chatbot/vllm/app/                            # run-vlm-gemma.sh 와 소유자·권한이 같은지
```

### 3.4 실행

```bash
sudo systemctl start vllm@gen-gemma31b                                 # enable 하지 않는다(평가 기간만)
sudo tail -f /mnt/a/chatbot/vllm/logs/gen-gemma31b.log                 # "Uvicorn running on http://0.0.0.0:8112" → Ctrl+C (수 분 걸림)
systemctl status vllm@gen-gemma31b --no-pager
nvidia-smi                                                             # GPU 2 약 68GB(리랭커 8.6 + 60), GPU 0·1·3 변화 없음
```

### 3.5 기동 실패 시

`sudo tail -n 100 /mnt/a/chatbot/vllm/logs/gen-gemma31b-error.log`

| 증상 | 조치 |
|---|---|
| `Free memory on device ... is less than desired` | GPU 2를 다른 프로세스가 쓰는 중 — 3.1 다시 확인 후 보고 |
| KV 캐시 부족(`max_model_len ... larger than ... KV cache`) | `run-gen-gemma31b.sh`의 `--max-model-len`을 8192로 낮추고 3.3 → restart |
| `limit-mm-per-prompt` / 멀티모달 관련 오류 | 그 줄을 지우고 restart |
| 양자화 방식 관련 오류(`quantization`) | `config.json`의 `quantization_config` 내용과 함께 보고 |
| 모델 구조 미지원(`architectures ... not supported`) | vLLM 0.30.0 지원 여부 문제 — 오류 문구와 함께 보고 |
| `Permission denied` (모델 파일) | 3.2 `namei -l` 결과로 새 폴더만 확인 |
| `Permission denied: '/mnt/a/chatbot/vllm/cache'` (2026-11-18 발생) | `/mnt/a/chatbot/vllm`(ACL sychoi 만)을 vllm-admin 이 못 지나감. 기존 폴더 권한은 두고 새 폴더 `sudo install -d -o vllm-admin -g vllm-admin -m 750 /mnt/a/chatbot/vllm-cache` → `env.sh` 캐시 3줄 경로를 `/mnt/a/chatbot/vllm-cache`로(`cp -p`로 백업 후 `sed -i`) → restart |

### 3.6 확인

```bash
read -s K                                                        # VLLM_API_KEY 를 기록 없이 입력
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8112/v1/models          # 401 (키 없음)
curl -s -H "Authorization: Bearer $K" http://127.0.0.1:8112/v1/models | head -c 200; echo
curl -s http://127.0.0.1:8112/v1/chat/completions -H "Content-Type: application/json" -H "Authorization: Bearer $K" \
  -d '{"model":"gemma-4-31B-it-FP8","max_tokens":200,"messages":[{"role":"user","content":"다음 문장으로 작업자가 물을 만한 질문 1개와 정답을 JSON으로 만들어줘: 볼트는 규정 토크 25Nm로 체결한다."}]}'
# 한국어 질문·정답 JSON 이 나오면 정상
for p in 8101 8102 8103 8104 8107 8111; do curl -s -o /dev/null -w "$p %{http_code}\n" http://127.0.0.1:$p/v1/models; done   # 기존 서비스 401
```

**GPU 서버 밖(WAS·개발 PC)에서 부르려면** ACG F-4 인바운드에 TCP 8112를 추가해야 한다.

## 4. 운영·되돌리기

| 할 일 | 명령 |
|---|---|
| 멈춤(평가 끝) | `sudo systemctl stop vllm@gen-gemma31b` (GPU 2 메모리 즉시 반환) |
| 다시 켬 | `sudo systemctl start vllm@gen-gemma31b` |
| 완전히 제거 | `sudo systemctl stop vllm@gen-gemma31b` → `sudo rm /opt/yest/chatbot/vllm/app/run-gen-gemma31b.sh` |

다른 서비스 설정·`vllm@.service`·`env.sh`는 바꾸지 않았으므로 위 단계만으로 원래 상태가 된다. 모델 폴더는 남겨 둔다.
