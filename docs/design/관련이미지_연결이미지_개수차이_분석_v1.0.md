## 1. 결론

두 영역은 **같은 사진 목록을 다르게 보여 주는 것이 아니라, 서로 다른 목록을 보여 준다.** 그래서 개수가 다른 것이 현재 설계상 정상 동작이다.

| 영역 | 보여 주는 것 | 한마디로 |
|---|---|---|
| 답변 하단 **관련 이미지** | LLM이 답변에 `[IMG:ref]`로 **인용한 사진**(최대 4장). 인용이 없으면 자동 첨부 1장 | **"답변이 고른 사진"** |
| 참고 문서 카드 **연결된 이미지** | 그 출처 청크의 payload `resource_ids`에 들어 있는 **모든 사진**(표시 가능한 것) | **"이 청크에 붙어 있는 사진 전부"** |

실측 예(같은 답변 1건): 관련 이미지 **1장**, 참고 문서 [1]의 연결된 이미지 **4장**. 4장 중 LLM이 인용한 1장만 관련 이미지에 나왔다(3절).

## 2. 두 목록이 만들어지는 경로

### 2.1 관련 이미지 — 백엔드가 고른 목록을 그대로 표시

```
assemble_context.context_chunks (LLM에 넘긴 청크 전부, 문서당 최대 2개, 전체 최대 6개)
  → collect_image_candidates          app/graphs/images.py
       payload.resource_ids로 tb_spreadsheet_resources 조회
       표시 가능 형식·장식 제외·현재 버전만
       같은 content_hash는 1건으로 합침
       상위 RAG_IMAGE_CANDIDATES(8)개 → [IMG:ref] 후보 목록을 프롬프트에 넣음
  → generate_answer: LLM이 일부 사진에 [IMG:ref]를 붙임
  → validate_answer_images            app/graphs/images.py
       답변에 인용된 ref만 남김 (최대 RAG_MAX_IMAGES=4)
       인용 0건이면 자동 첨부 1장(ANSWER_IMAGE_AUTO_ATTACH)
  → SSE "images" / 대화 이력 images
  → 프런트 msg.images → ChatImageGallery.vue  "관련 이미지 {{ images.length }}"
```

- 프런트는 개수를 바꾸지 않는다. `useChatView.js normalizeImages`는 `resource_id`가 없는 항목만 뺀다.

### 2.2 연결된 이미지 — 프런트가 출처별로 다시 계산

```
format_citations: 답변에 [n]으로 인용된 청크만 출처 카드로 만듦
       citation.resource_ids = payload.resource_ids (전부, 개수 제한 없음)
  → CitationPanel.vue loadLinkedResources
       출처 문서마다 GET /api/documents/{document_id}/spreadsheet-resources
       (그 문서의 삭제 안 된 사진 전부 + displayable 플래그)
  → linkedImages(citation)
       문서 사진 중 resource_id ∈ citation.resource_ids
       AND displayable === true AND 이미지 형식
  → "연결된 이미지 {{ linkedImages(c).length }}장"  (출처 카드마다 따로)
```

## 3. 실측 확인 (개발 DB 대화 기록, 사진이 있는 답변 3건)

| 답변 | 관련 이미지 | 출처 카드별 연결된 이미지 | 차이 이유 |
|---|---|---|---|
| A | 1장 (LLM 인용 `cited=true`) | [1] **4장** | 4장 중 LLM이 1장만 인용 |
| B | 1장 (자동 첨부 `cited=false`) | [1] 1장, [2] **2장** (합계 3장) | 인용 0건 → 자동 첨부 1장. [2]의 사진은 후보였지만 선택 안 됨 |
| C | 1장 (자동 첨부) | [1] 1장 | 같음 |

답변 A의 출처 [1](Step 5 청크) 사진 4장 상세:

| 순서 | 사진(끝자리) | 역할 | 내용 해시(앞 8자) | 표시 가능 | 관련 이미지에 나옴 |
|---|---|---|---|---|---|
| 1 | `i0043` | step_photo | `d2477f6e` | 예 | 아니요 |
| 2 | `i0053` | detail_view | `d2477f6e` (**1번과 같은 사진**) | 예 | 아니요 |
| 3 | `i0054` | detail_view | `968ec072` | 예 | **예 (LLM 인용)** |
| 4 | `i0055` | detail_view | `f9984508` | 예 | 아니요 |

- 연결된 이미지 4장에는 **같은 그림이 2번**(1·2번, 해시 동일) 들어 있다. 관련 이미지 쪽은 해시가 같으면 1건으로 합친다.
- 4장 모두 표시 가능한 사진이라, 차이는 "고른 것 vs 전부"에서만 생겼다.

확인 조회문:

```sql
-- 답변별 관련 이미지 수와 출처별 resource_ids 수
with m as (
  select s.session_id, e.ord, e.msg
  from tb_query_sessions s, jsonb_array_elements(s.conversation_history::jsonb) with ordinality e(msg, ord)
  where e.msg->>'role' = 'assistant' and jsonb_array_length(coalesce(e.msg->'images','[]'::jsonb)) > 0
)
select substr(session_id,1,8) sid, ord,
       jsonb_array_length(msg->'images') as gallery,
       (select jsonb_agg(jsonb_build_object('cid', c->>'citation_id',
               'n', jsonb_array_length(coalesce(c->'resource_ids','[]'::jsonb))))
        from jsonb_array_elements(msg->'citations') c) as citations
from m;
```

## 4. 개수가 달라지는 원인 전체 목록

| # | 원인 | 관련 이미지 | 연결된 이미지 | 코드 |
|---|---|---|---|---|
| C-1 | **LLM이 고른 사진만 vs 청크의 사진 전부** (주원인) | `[IMG:ref]`로 인용된 것만 | `resource_ids` 전부 | `images.validate_answer_images` / `CitationPanel.vue linkedImages` |
| C-2 | **개수 상한** | 최대 `RAG_MAX_IMAGES`(4), 후보는 `RAG_IMAGE_CANDIDATES`(8) | 상한 없음 (한 청크 최대 21장 실측) | `config.py:239-240` |
| C-3 | **같은 사진 합치기** | `content_hash`가 같으면 1건 | 합치지 않음 (같은 그림이 배치 수만큼 반복) | `images._image_key` / 프런트에 해당 처리 없음 |
| C-4 | **자동 첨부** | 인용 0건이면 Step 사진 또는 질의어가 분명히 겹치는 사진 1장 (`cited=false`) | 해당 없음 | `validate_answer_images` 뒷부분 |
| C-5 | **세는 단위** | 답변 1건 전체 | 출처 카드마다 따로. 같은 사진이 여러 카드에 붙어 있으면 카드마다 또 셈 | `CitationPanel.vue:74` |
| C-6 | **대상 청크 범위** | LLM에 넘긴 컨텍스트 청크 전부(답변에 `[n]` 인용 안 된 청크 포함) | 답변에 `[n]`으로 인용된 청크만 | `collect_answer_images` / `format_citations` |
| C-7 | **행 범위 대체 조회** | `resource_ids`가 빈 excel 청크는 같은 시트·같은 행 범위의 인쇄영역 사진을 후보로 씀 | `resource_ids`만 봄 → 0장 | `images._lookup_resources` 아래쪽 |
| C-8 | 질의어 일치 정렬 | 질의어와 겹치는 사진을 먼저 후보로 | 순서 기준 없음 | `collect_image_candidates` |

C-6, C-7 때문에 **관련 이미지가 더 많은 경우**도 생길 수 있다. 예를 들어 사진이 출처 카드에 없는 청크(컨텍스트에는 들어갔지만 `[n]` 인용은 안 된 청크)에서 오거나, 행 범위 대체 조회로 찾은 사진이면 그렇다.

### 4.1 같은 판정을 쓰는 부분 (차이 원인 아님)

- 표시 가능 여부: 두 쪽 모두 `app/services/resource_labels.py`의 같은 규칙(png·jpeg·gif·webp·bmp, 장식·양식 머리글 제외, `review_status≠unlinked`, 삭제 제외)을 쓴다.
- 버전: 연결된 이미지 쪽은 버전 조건이 없지만, `resource_ids` 자체가 `-v{버전}-`이 들어간 그 버전의 ID라 결과는 같다.

### 4.2 함께 발견한 작은 문제

| # | 내용 | 코드 |
|---|---|---|
| S-1 | 연결된 이미지의 **표시 순서가 정해져 있지 않다.** 문서 사진 목록 SQL에 `ORDER BY`가 없고, 프런트는 그 목록 순서로 거른다(`resource_ids` 순서 아님) | `spreadsheet_resource_repository.list_by_document`, `CitationPanel.vue linkedImages` |
| S-2 | 출처 패널은 문서 사진 **전체**를 받아 프런트에서 거른다. 큰 문서(실측 190장)는 출처 카드가 하나만 있어도 190건을 받는다 | `GET /api/documents/{id}/spreadsheet-resources` |

## 5. 사용자 입장에서 헷갈리는 지점

- 두 영역 이름이 비슷해서("관련" / "연결된") 같은 목록이라고 생각하기 쉽다.
- 연결된 이미지에 같은 그림이 2번 나오면 오류처럼 보인다(C-3).
- 관련 이미지에 있는 사진이 어느 출처 카드에도 없을 수 있다(C-6·C-7).

## 6. 고칠 방향 (결정 필요 — 구현하지 않음)

| 안 | 내용 | 장점 | 단점·영향 |
|---|---|---|---|
| A. 현재 유지 + 문구 정리 | "관련 이미지" → "답변 사진", "연결된 이미지" → "이 출처의 전체 사진" 등. 답변 사진에 들어간 사진은 출처 카드에서 표시(배지) | 동작 변경 없음, 의미가 분명해짐 | 개수 차이는 그대로 |
| B. 연결된 이미지 중복 제거 | 출처 카드 안에서 `content_hash`가 같은 사진 1장만 | 같은 그림 반복(C-3) 해소 | 프런트 수정. 문서 사진 목록 API는 이미 `content_hash`를 준다 |
| C. 연결된 이미지 순서 고정 | `citation.resource_ids` 순서로 정렬 | S-1 해소 | 프런트 수정만 |
| D. 출처 카드도 답변 사진 기준으로 | 출처 카드에는 그 카드에서 나온 답변 사진만 표시 | 두 숫자가 맞음 | 출처의 다른 사진을 볼 길이 없어짐(목업 UI-05와 비교 필요) |
| E. 사진 ID로 직접 조회 | 출처 패널이 `resource_ids`만 조회하는 API 사용 | S-2 해소 | 백엔드 API 추가 |

제안: **A + B + C**. 동작 의미는 그대로 두고 혼동 요인(이름·중복·순서)만 없앤다. 목업(`admin`·`chat` 목업 UI-05)의 문구 기준과 맞는지 확인한 뒤 진행한다. 프런트를 고치면 "2026.11.xx(sooyeon.choi) 수정 - 설명" 주석 규칙을 따른다.
